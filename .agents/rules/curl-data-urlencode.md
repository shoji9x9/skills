# curl の送信値はエンコードし、秘密値は argv に載せない

## 送信値は --data-urlencode でエンコードする

配布スキル（`skills/<name>/`）の curl による API の例とスクリプトでは、変数の値を URL のクエリやフォームにそのまま埋め込まない。
`curl -d "k=$v"` や `?k=$v` の形では、curl は値をエンコードしない。
そのため、`+`・`=`・`/` や、中身を解釈できないトークン（refresh token・ページングの marker など）を含む値が別の値として送られ、リクエストが失敗するか、結果の一部を取得できない。

- 変数の値は `--data-urlencode "k=$v"` で送る。GET のクエリに載せる場合は `-G` を一緒に付ける。
- 変数を含まない固定の値（`grant_type=refresh_token` など）は、そのまま書いてよい。

## 秘密値は argv（ps / proc）に載せない

`--data-urlencode "k=$v"` では、値が curl の argv に載る。そのため、秘密値（トークン・`client_secret`・認可コード）には使わない。
curl はスクリプトとほぼ同じ時間だけ動くので、その間ずっと `ps` や `/proc/<pid>/cmdline` から値を読める。

- 秘密値は `umask 077` で作った一時ファイルに書き、`--data-urlencode "k@file"` で渡す。
  curl はファイルを読んで URL エンコードするので、送る本文は `k=$v` と同じになり、argv にはファイル名だけが載る。一時ファイルは `trap '...' EXIT` で消す。
- 秘密でない識別子（`client_id` など）は、そのまま埋め込んでよい。
- 対策は、その値を argv で受け取るすべてのプロセスから値を外して完了とする。
  スクリプトが値を stdin で受け取るように変えても、同じ値を argv で受け取る子プロセス（curl など）が残っていれば、値は `ps` から読める。
  レビューで、値を argv から外す対策を見たら、値を次に渡す先まで追って、argv に載らなくなったかを確かめる。
