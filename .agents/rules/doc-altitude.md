# ドキュメント記載基準（altitude）

エージェント向けドキュメント（`AGENTS.md` / `CLAUDE.md` / `SKILL.md` / `skills/*/references/` / `.agents/rules/` / `docs/`）には、
**エージェントが正しく行動するために必須の情報だけ**を載せる。「網羅」ではなく「行動に必須な分だけ」。

- 網羅性のための説明・**読み手（consumer）のいない節**・他ドキュメントと**重複**する内容は置かない。
- 詳細は参照リンク（`docs/` や `references/`）へ逃がす。
- 重複は二重管理 ＝ drift 源（一方が古くなる）。**single source of truth を 1 箇所に置き、他からは参照**する。
- **「正本は〜」と書いた内容を、その直後に全文で書き直さない。** 正本宣言は参照の合図であって転記の免罪符ではない。
  転記したい衝動が出たら、正本側に「ここへ転記しない」と明記し、参照側には**要約＋正本の節名**だけを置く
  （特に安全弁・選択規則のように複数スキルが従う規約は、乖離するとガードレール自体が不整合になる）。
- 追記しようとしたら自問する: 「これはエージェントが把握していないと誤った行動を取るか？」 No なら載せない
  （コンテキスト圧迫を避ける）。

## 文書の階層（Tier）

文書を 4 つの階層に分け、置き場所と参照の向きを決める。どのファイルがどの階層かは次の表で決める。

<!-- doc-tiers:begin（scripts/gates/doc-tiers.json から scripts/gates/check-doc-tiers.js --fix で生成する。手で直さない） -->

| Tier | 文書 | 置くもの |
| --- | --- | --- |
| 1 | `AGENTS.md`、`CLAUDE.md`（`AGENTS.md` を読み込むだけ）、`.github/copilot-instructions.md`（`AGENTS.md` を参照するだけ） | リポジトリの目的と、作業内容に依らず常に守る原則・規約の要約 |
| 2 | `.agents/rules/**`、`docs/**`、`skills/**`、private skill（`.agents/skills/<name>/` のうち `.private-skill` を持つもの）、`.textlint/word-list.md`（`.textlint/words.json` から生成する）、`README.md` | 特定の作業で守る規約・手順と、スキル |
| 3 | `evals/*/README.md`、コードコメント（設定ファイルのコメントを含む） | テストの設計と、実装の説明 |
| 4 | `.kaizen/**`、`tests/` の結果、Issue・PR | 経過と判断の記録（追記していく） |

階層の外に置く文書: `evals/*/fixtures/**`（eval の入力）、`.github/ISSUE_TEMPLATE/**`（Issue のテンプレート）。

<!-- doc-tiers:end -->

コードと設定の値そのものは階層の外に置く。文書がスクリプトや設定ファイルの名前・パスを挙げるのは、案内として書いてよい。
インストール済みのスキルのコピー（`.agents/skills/<name>/`）とエージェント用のリンク（`.claude/`）は `skills/` と同じ中身なので、階層に数えない。

- 上位と下位の記述が食い違ったら、上位に従い、下位を直す。
- 上位の文書は下位の文書を参照しない。ただし「詳細は X」「参照ルールガイド」のように、どこに何があるかを示す案内だけは書いてよい。
  規則の中身を下位に任せる書き方（「原本は docs/... にある」）や、下位の内容を前提にした書き方はしない。
- `AGENTS.md` が `@path` で取り込む文書（Claude Code がセッション開始時に読み込む）も、階層は元のままにする。
  取り込みは案内と同じに扱い、`AGENTS.md` だけを読むエージェント（Codex など）にも要点が届くよう、要点は `AGENTS.md` に書く。
- 同じ内容を複数の文書に書かない。1 か所に書き、他からは参照する。
- 作成日、「現状は」「当面」のように時間がたつと正しくなくなる記述を Tier 1〜3 に書かない。経過は Tier 4 に追記する。
- 配布するスキル（`skills/`）は配布先で単独で動く。階層とは別の制約として、このリポジトリの他の文書を参照せず、必要なものは同梱する。

参照の向き・リンクと節名の実在は `scripts/gates/check-doc-refs.js`、時間がたつと正しくなくなる記述は `scripts/gates/check-time-sensitive-prose.js` がチェックする。

## 既にある重複を正本参照へ縮約するとき

**縮約は「重複した文字列の削除」ではない。** 転記は重複であると同時に、退避と接続点も兼ねている場合がある。
転記を消したら、次の 3 点を確認してから終える（消した文字列だけを見て終えない）。

1. **規則の再記述が別形式で残っていないか掃き出す。** 箇条書きだけでなく**表セル・脚注・短縮形**も対象にする。
   文書の形で「転記か」を判断せず、規則の内容が再記述されているかで判断する。
   同一ファイル内で「ここへ転記しない」と宣言したら、**そのファイル自身を最初に検査する**。
2. **正本に到達できないときの分岐を消費側に置く。** 安全弁（ガードレール・停止条件）の転記を消すなら、
   参照先を読めない場合は従わず停止する指示を残す。正本自身には書けない指示なので消費側が持つ。
3. **一般規則と固有条件の接続点を明示する。** 正本から固有事情（スキル名・例外条件）の列挙を削るなら、
   「固有条件を持つ側の規定に従う」旨を正本に残し、条件を宙に浮かせない。

## 他スキルの正本を指す参照は、指示語で受けずスキル名を書く

「同スキルの」「本スキルの」「同ファイルの」は、**読み手がそのファイルの所属スキルとして解決する**。
姉妹スキル群（`replace-strategy` / `parity-*` 等）は `references/` の構成が対称でファイル名も似通うため、
誤読すると存在しないパスを探すことになる。

- **正本参照は 1 行で自己完結させる。** 直前の文でスキル名を挙げていても繰り返す
  （例: 「正本は同スキルの `references/baseline.md`」ではなく「正本は `parity-suite` の `references/baseline.md`」）。
- 指示語で受けてよいのは、**同じファイル内の別の節**を指すときだけ。

## 複数ドキュメントへ同じ契約を横断追加するとき

語句を統一するだけでは足りない。**各挿入先の親見出しと隣接構造を先に確認してから**書く。

- **番号付きリストなら、採番と「その番号を参照している全箇所」を同じ変更で更新する。**
  箇条書きで割り込ませると番号が飛び、他所からの番号参照が別項目を指す。
- **順序付き手順なら、順序の理由と停止条件まで書く。** 「なぜこの位置か」が無い項目は、
  次の編集者に並べ替えられる。
- 横断整合を**語句の統一**として扱わない。挿入先ごとに、番号参照・表の列・手順の前後関係という
  **局所の契約**があり、それを壊すと語句が揃っていても手順が成立しなくなる。

関連: 配置の決定論（どこに置くか）は別軸。本ルールは「そもそも載せるか・どの粒度で載せるか」を扱う。
