# 配布スキルの成果物は同梱する

配布するスキル（`skills/<name>/`。`gh skill publish` の対象）が実行時に読む成果物（テンプレート・設定ファイル・スクリプトなど）は、原本をスキルの中（`assets/`・`scripts/`・`references/`）に同梱する。
配布されるのは `skills/<name>/` の中だけで、リポジトリの直下や `.github/` に置いたファイルはインストール先に届かず、参照先が無くなるからである。

- インストール先のリポジトリに同じ種類のファイルが既にあれば、それを優先する。無いときだけ同梱物を使うか、ユーザーに確認してからコピーする。既にあるファイルは上書きしない。
- スキル本体（`SKILL.md` など）から参照するパスは、リポジトリ固有の場所ではなく、スキルの中の同梱物を起点にする。
- 利用者のプロジェクトにコピーして使ってもらうファイル（テンプレート）は最小限にする。
  実行の処理（エンジン・共通スクリプト）はコピーせず、スキルの中に置いたまま実行する。そうすれば `gh skill update` で自動で更新され、上書きの衝突や更新の取得忘れが起きない。
- 実行時に同梱物を探す条件は、ソースの属性ではなく、インストール済みのコピーで実測して決める。
  `gh skill install` が配るファイルのモードは `100644` なので、`[ -x "$dir/<script>.sh" ]` のような実行ビットの判定は配布先で必ず偽になる。ソースは 755 なので、手元では真になる。
  読めれば足りるなら `-r` で判定し、`bash <path>` で起動する。この分岐で検出されることは、モードが 644 のインストール済みのコピーを置いて確かめる。
- コピーされるファイルは、それだけで読めるように書く。スキルの中の `references/` などへの相対リンクや相対パスを書かない。コピー先の階層や利用者のプロジェクトでは解決できないからである。
  出典はスキル名で示すか、内容をそのまま書く。

## 開発専用の成果物は `skills/<name>/` に置かない

逆の向きも守る。`gh skill install` は、スキルのディレクトリの git tree を再帰的に取得し、すべての blob を配る。
除外の仕組みは無く、`.skillignore` のようなファイルも読まない。
根拠は cli/cli の `internal/skills/discovery/discovery.go` の `DiscoverSkillFiles` で、gh v2.93.0 で確かめた（<https://github.com/cli/cli/blob/v2.93.0/internal/skills/discovery/discovery.go>）。
ローカルからインストールする場合も、`installer.go` が WalkDir ですべてのファイルをコピーする。
置いたものはすべて配布先に配られるので、このリポジトリでしか意味を持たないものはスキルの外に置く。

- 回帰 eval（`evals.json`・`README.md`・fixture）は `evals/<name>/` に置く。
  配布先では eval を実行せず、手順もこのリポジトリのハーネス（`scripts/eval/run-skill-eval.sh` など）を前提にしているので、配っても使えない。
  配布スキルの文書から `evals/` を参照しない。配布先には存在しないからである。
- `scripts/gates/check-eval-reachability.js` が、CI の `Lint` ジョブですべてのスキルを調べ、`skills/<name>/evals/` が残っていたら違反にする。
