# 配布スキルは、このリポジトリの技術スタックと設定を前提にしない

配布スキル（`skills/<name>/`）は、技術スタックも lint・整形・型の検査の設定も違うプロジェクトに入る。
このリポジトリのツールや設定を前提にした記述は、利用者のプロジェクトで何も機能しないか、失敗の原因になる。
依存を足すときや見つけたときは、次の基準で「直す」か「許す」かを決める。

## 直すもの

- 利用者のプロジェクトへコピーするもの（雛形・1 ファイルだけコピーするツール）と、スキルが生成するファイルに入れた、このリポジトリの設定を前提にした記述。
  - 使われない抑止を報告されうる指示のコメント（`oxlint-disable`・`eslint-disable`・`biome-ignore`・`@ts-expect-error`・`deno-lint-ignore`）。
    利用者の設定では何も抑えず、使われない抑止を error にする設定では、それだけで lint や型の検査が失敗する。
    このリポジトリで外す必要がある規則は、行のコメントではなく、このリポジトリの設定（`oxlint.config.ts` の `overrides` など）で外す。
    スキルの中に置いたまま実行するスクリプトも、利用者の lint の対象に入りうるので同じに扱う。
  - このリポジトリの設定値を、ツールのデフォルトや一般の規約として書くこと（行の長さの上限など）。値を使うなら、スキルが決めた値として書く。
- 各スキルの `SKILL.md` の前提の節に書いていない必須の依存。無いと失敗するものも、警告なしに機能を減らして動くものも含む。
- このリポジトリのツールの選択（pnpm・mise・oxlint・リポジトリ内のパス）を前提に、手順やスクリプトが動く書き方。

## 許すもの

- 「前提」に書いた依存（Node.js・bash・`gh`・`git`・Playwright など）。Node.js に同梱される `npx` も含む。
- 任意の依存で、無いときの振る舞いを決めて「前提」に書いたもの（`jq` か `python3` があれば使い、無ければ機能を減らして動く、など）。
- 例として挙げる書き方（「lefthook など」「mise・asdf など」）と、特定のツールを使うプロジェクトでだけ読む手順（pnpm の推移的な依存の更新など）。
- 未使用でも報告されず、その規則が無いプロジェクトでは何もしない指示のコメント（textlint・markdownlint・shellcheck）。
- 特定のツールと版で確かめたという実測の記録。

使われない抑止を報告されうる指示のコメントは、`scripts/gates/code/check-skill-lint-directives.ts` が lefthook の pre-commit と CI の `Lint` ジョブでチェックする。
基底ドキュメントの決め打ちは、`distributed-skill-base-doc-generalization.md` で扱う。
