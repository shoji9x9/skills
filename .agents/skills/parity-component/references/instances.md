# 採取対象の確定（部品インスタンス）

採取の単位は**部品インスタンス（部品 × ページ）**で、対象の一覧は `.replace/components.md`（`replace-strategy` の `setup` 手順 10 が作る部品インベントリ）から引く。
**本スキルはこのファイルを書かない。** 不足は `replace-strategy` 側で埋めるようユーザーに促す（勝手に採番・補完すると、以降の採取が誰も確認していない対象一覧の上に載る）。

## なぜページ単位の被覆表を使わないか

`parity-suite` の被覆表 `component-coverage.json` も「部品 × ページ」のインスタンスを持つが、**あれは機能（画面）の採取の成果物**なので、
部品を画面より先に作る時点では 1 つも存在しない。**採取対象の一覧は部品インベントリが正本**で、被覆表はページができてから別に作られる。

両者は数えているものも違う。被覆表が数えるのは**操作と状態の有無**（`present` / `absent` / `unmeasured`）で、色・寸法・余白は見ていない。
**被覆表が緑でも見た目の担保にはならない**ので、片方をもう片方の代わりにしない。

## 引く項目

対象行から次を引く。**どれか 1 つでも空なら採取へ進まない。**

| 項目 | 用途 | 空のときの扱い |
|---|---|---|
| slug | 成果物パス `.replace/components/<slug>/` の識別子 | 停止（自分で採番しない） |
| インスタンス（ページ ＋ その部品を指す論理名） | 採取対象そのもの | 停止。**2 件未満も停止**（下記） |
| データ依存の有無 | 実データを採るかの分岐（[`capture.md`](capture.md)） | 停止（推測で決めない） |
| 採否（自前実装／採用パッケージ） | `build` の出発点 | `build` のみ停止。`capture` は進めてよい |
| Issue 番号 | `build` のブランチ作成 | `build` のみ停止（`replace-strategy issues` を促す） |

- **論理名はロケータマッピングの契約名と同じ流儀で付ける**——role ＋アクセシブルネームで引ける名前にし、id・自動生成クラスをアンカーにしない（正本は `parity-suite` の `references/locator-mapping.md`）
- ページは現行 target で実際に到達できる URL であること。到達できないページは採取対象から外し、**外したことを `gaps.md` に残す**（黙って減らさない）

## インスタンスが 2 件未満の部品は共通部品として先に作らない

固定と可変は**2 つ以上のインスタンスを突き合わせないと区別できない**。1 件しか無い部品を先に作ると、そのインスタンス固有の値が部品の固定値として焼き込まれ、
2 つ目の利用箇所が出た時点で引数を後から足すことになる（`amend.md` の改修は既存の見本の再採取を伴うので、先に作った利点が消える）。

- 1 件しか無い部品は**その機能の実装時に `parity-replace` が作る**のが正しい割り当て。部品インベントリから外すようユーザーに促す
- 「いまは 1 件だが今後増える見込み」も同じ扱いにする——**見込みは採取物ではない**

## インスタンスの id

`axis-diff.mjs` の照合キーになるので、**インスタンスごとに一意で、後から見てどのページのものか分かる文字列**にする（例: `orders-list` / `users-detail`）。

- 一意でない id は `axis-diff.mjs` が重複として落とす。**落ちたものを採取側で黙って結合しない**（別インスタンスの値が 1 件に潰れる）
- id は `metadata.json` の `instances[].id` と成果物パス `baseline/<id>/` に使う。採取後に変えると過去の採取物と突き合わせられなくなるため、**採取前に確定させる**

## 状態集合はインスタンス間で揃える

**列挙する候補の状態集合（`default` / `hover` / `disabled` 等）は全インスタンスで共通**にする。片方でしか採っていない状態は「その状態では差が無い」ではなく「測っていない」であり、
`axis-diff.mjs` は揃っていない状態を問題として落とす。

**例外は到達できない状態だけ**——候補に挙げたうえで、そのインスタンスでは作れないことを宣言する（下記）。宣言された状態は
`axis-diff.mjs` が除外として扱い、問題にしない。**宣言の無い欠落は採り忘れと区別できないので従来どおり問題**になる。

- 現行のそのインスタンスで**到達できない状態**（そのページでは常に活性、等）がある場合は、**状態を減らすのではなくその旨を記録する**——
  `metadata.json` の `instances[].unreachable_states` に状態名と到達できない理由を書き、同じ内容を `gaps.md` にも残す。
  `axis-diff.mjs` へ渡すマニフェストからもその状態を外し、**「全インスタンスで採れた状態」だけで軸を割り出す**
- 到達できない状態が多くて割り出せる軸がほとんど残らないなら、その部品は先に作る対象として不適なのでユーザーに上げる
