# 操作の結果の採取と突き合わせ

見た目の照合（画素・特性・当たっている CSS 規則）が見るのは、その状態に置いたときの見た目だけで、操作した結果が現行と同じかは見ていない。
部品が状態ごとの見た目で基準と一致していても、次のような違いは残る。
隅のアイコンを押すと列ピッカーではなく全選択になる。全選択の後に 1 行外しても、見出しのチェックが残る。書き出しで失敗する。
機能単位の `parity-suite` はページができてから動くので、部品を先に作る進め方では、画面を実装するまで誰も突き合わせない。

そこで、`capture` が現行で操作した結果を採り、`build` がカタログの見本で同じ操作をして、操作 × インスタンスごとに結果の状態を比べる。
判定は、同梱の [`../scripts/behavior-compare.mjs`](../scripts/behavior-compare.mjs) が行う（コピーせず、スキルの中のものを実行する）。

## 操作の列挙（capture）

- 操作は、部品の機能表から挙げる。市販の部品なら、同梱の機能の一覧と公式のサンプルを使う。自作や OSS の部品なら、部品カタログを使う。資料が無ければ、現行の UI から洗い出す。
  資料の扱い（資料は挙げる材料であって正解ではない）は、`parity-suite` の `references/coverage.md`「状態網羅の導出源」と同じである。
  使った材料を、`metadata.json` の `capture.operation_source` に書く。値は `vendor-feature-list`・`component-catalog`・`current-source`・`app-ui` のどれかで、無いときや一覧に無い値のときは、検査が形式の誤りとして失敗にする。
- 状態の列挙と同じく、操作の集合は全インスタンスで共通にする。
  そのインスタンスで実施できない操作だけを、`instances[].unreachable_operations` に理由と一緒に宣言し、同じ内容を `gaps.md` に残す。宣言の無い欠けは、検査が採り忘れとして失敗にする。
- 版の違いが出やすい操作を先に挙げる。見た目は CSS で揃えられても、イベントの順番（`mousedown` と `click` のどちらで判定するか）や、デフォルトの振る舞いの違いは、操作しないと現れない。
  たとえば、次のものを含める。
  - 複合の操作（全選択してから 1 行外す、メニューの操作の後に元に戻す）
  - キーボードの操作（Tab での移動）
  - 行の挿入の位置と削除の扱い（削除するか、印を付けるだけか）
  - 書き出し
- 操作ごとに、`metadata.json` の `capture.operations[]` に `id`・`description`・`steps`・`observe` を書く（様式の原本は [`../assets/metadata-template.json`](../assets/metadata-template.json)）。
  4 つとも必須で、空のときや、テンプレートのプレースホルダ（`<...>`）のままのときは、検査が形式の誤りとして失敗にする。
  `steps` が無いと、両側が同じ id で別の操作をしても、観測が一致すれば通ってしまうからである。
  理由・承認者・見本の識別子など、人が書き込む欄も同じで、プレースホルダのままでは書き込み済みとして扱われない（観測値は部品の出力なので、対象外である）。
- 操作を持たない部品（静的な表示だけのものなど）は、`operations` を空の配列にし、`operations_none_reason` に理由を書く。理由の無い空の配列は、検査が形式の誤りとして失敗にする。

## 観測項目の決め方

比べるのは操作の結果の状態で、画素ではない。観測項目は、操作ごとに `observe` で固定する。

- 例は次のとおりである。
  - 選択範囲（行と列の範囲）、チェックの付いた行と見出しのチェック、行の並び
  - 開いた要素（ポップアップやメニューの有無と種類）、フォーカスの位置、元に戻した後の値
  - 書き出したファイルの有無と名前、ページの例外とコンソールのエラーの件数（書き出しで失敗するようなものを拾う）
- 両側とも、`observe` の集合をちょうど記録する。観測を空にした記録同士は `{}` と `{}` で一致してしまうので、項目の欠けや余分は、検査が記録の不備として失敗にする。
  無いものは `null` と書き、キーを省かない。
- 値は、現行と新側で同じ表現にそろえられるものを選ぶ（行は表示中のキー列の値、選択は行と列の番号）。
  実装に固有のクラス名や内部の id を、観測値にしない。新側では名前が違うので、振る舞いが同じでも一致しなくなる。
- 時間の値（表示する時間・動きの長さ）を、観測値にしない。値が揺れるので、一致を求めるといつまでも失敗する。
  時間はプローブで採って [`motion.md`](motion.md) の検査で比べ、動きが終わってから始まる処理は、その後の決まった時点の状態を観測する。

## 採り方

- 各操作は、同じ初期状態から始める（ページや見本を開き直す）。前の操作の結果を引き継ぐと、順番によって結果が変わる。
- 手順は部品の中の論理名で書き、見本でも同じように再生できる形にする（role とアクセシブルネーム。ページに固有の要素に頼らない）。
  現行と見本で違う手順を踏むと、差が実装によるものか、手順によるものかを分けられない。
- 操作は書き込みになることがある。選択した target の `forbidden_actions` を先に読み、禁止された操作で作る結果は実施せずに、`unreachable_operations` と `gaps.md` に残す。
  取り決めの原本は、`parity-suite` の `references/data-discipline.md` である。
  画面の上だけで終わる操作（選択・並べ替え・ポップアップ）と、保存や送信まで進む操作（行の削除を確定するなど）を分けて判断する。
- 結果は、インスタンスごとに `baseline/<instance>/behaviors.json` に書く（様式の原本は [`../assets/behaviors-template.json`](../assets/behaviors-template.json)）。

## 突き合わせ（build）

- カタログの見本で、同じ手順を同じ初期状態から実施する。同じ観測項目と、実施した見本の識別子（`story`。必須）を、`new/<target>/behavior-comparison.json` に書く。
  様式の原本は [`../assets/behavior-comparison-template.json`](../assets/behavior-comparison-template.json) である。
- 次のコマンドで検査する。

  ```bash
  node <skill>/scripts/behavior-compare.mjs \
    --baseline .replace/components/<slug>/ \
    --comparison .replace/components/<slug>/new/<target>/behavior-comparison.json \
    --target <target>
  ```

  終了コードの意味は次のとおりである。
  - 0: 母集合のすべての組み合わせで、観測が一致した（または承認済み）。
  - 1: 一致しないもの、突き合わせていないもの、記録の不備が残っている。
  - 2: 使い方の誤りか、形式の誤り。

  結果の件数を、`build-metadata.json` の `behavior` に転記する。
- 一致しないものは、要対応として実装へ戻す（見た目の要対応と同じ往復に入れる）。
  現行の振る舞いを引き継がないことを選ぶのは仕様の変更なので、自分で決めずに利用者に上げる。
  承認されたら、その行を `disposition: accepted` にし、`reason`・`approved_by`・`approved_at`（ISO 8601）を書く。
- 母集合に無い組み合わせの行は置かない。基準の無い突き合わせは照合されず、合格の証拠に見えるだけだからである（検査が失敗にする）。
- 実装を変えたら、突き合わせをやり直す。この検査は、記録が新しいかを見ない。build の照合は commit の前の作業ツリーに対して行うので、commit で版を特定できないからである。

## 完了報告に書くこと

操作の結果の突き合わせが保証するのは、挙げた操作についてだけである。完了報告には、次のものを収束と並べて示す。

- 比べなかった組み合わせ（`unreachable_operations`）と、承認を得て残した組み合わせ（`accepted`）の、操作の名前と理由
- 挙げた範囲の外にある操作と、画面に載せてから現れる振る舞い（ページのデータ・ほかの部品との連動）は保証しないこと。
  これらを引き受けるのは、機能単位の `parity-suite` の部品の網羅表（`component-coverage.json`）と、`parity-replace` の新側の突き合わせ（`component-comparison.json`）である。
