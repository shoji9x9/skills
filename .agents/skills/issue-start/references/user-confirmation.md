# 利用者への確認

スキルが利用者に承認を求める段と、選択肢から選んでもらう段で、どう確かめるかを定める。
スキルの手順に「利用者に確かめる」「承認を得る」と書かれた段は、この手順で確かめる。

## 確かめ方を選ぶ

エージェントがその場で使える確認のツールによって、次のように選ぶ。

| 使える確認のツール | 確かめ方 |
| --- | --- |
| 選択肢ごとの preview 欄を持つツール（Claude Code の AskUserQuestion など） | そのツールで聞く。判断の材料は、選択肢の preview 欄に入れる |
| preview 欄を持たないツール | そのツールで聞く。判断の材料は、問いの本文に入れる |
| 使えるツールが無い | 応答の本文で聞く（下の「本文で聞く」） |

preview 欄を持つツールでも、その問いの形で preview 欄を使えないとき（AskUserQuestion の複数選択の問いなど）は、判断の材料を問いの本文に入れる。

確認のツールを持つエージェントでも、モードや呼ばれ方（subagent として呼ばれたときなど）によっては使えないことがある。
使えるかどうかは、その場で使えるツールの一覧で確かめ、記憶で決めない。
名前だけが示され、定義を読み込めば呼べるツール（Claude Code の遅延読み込みのツールなど）も、使えるツールに含める。

## 確認のツールで聞く

- 判断の材料（下書きの全文・対象の一覧など、各スキルが挙げるもの）を、確認のツールの中に入れる。
  直前の通常のテキストが、確認のダイアログと同時に見えるとは限らないからである。
  確認のツールに入らない材料（画像など）は、ファイルのパスを入れ、開いて見てから答えるよう書く。
- 1 回に聞ける問いの数に上限があるツールでは、上限までの数ずつ続けて聞く。1 つの承認を、複数の問いに分けない。

## 本文で聞く

確認のツールを使えないときは、応答の本文で聞き、その応答をそこで終える。

- 判断の材料を、すべて本文に出す。下書きは省略せずに全文を出す。
  本文に出せない材料（画像など）は、ファイルのパスを並べ、開いて見てから答えるよう書く。
- 選択肢に番号を付けて並べ、番号でも文でも答えてよいと書く。
  1 つの応答で複数の問いを聞くときは、問いにも番号を付け、選択肢を問いの番号と組にする（問い 1 の選択肢は 1-a・1-b など）。
  承認を求める段では、少なくとも「承認する」「直してから見せる（直す内容を書いてもらう）」「承認しない」の 3 つを並べる。
  「承認する」以外の答えを受けたときの扱い（直してもう一度見せる・中止する・その対象だけを残して続けるなど）は、各スキルの手順に従う。
- 利用者の返事を受け取るまで、次の段へ進まない。

## 返事を得られないとき

返事を受け取る前に、その返事で決まる更新する操作（起票・dismiss・学びの適用・削除・ファイルの書き込み・push など）へ進まない。承認を求める段も、選択肢から選んでもらう段も同じである。
確認のツールを使えなかったことを理由に、承認を求める段を飛ばさない。

返事をする人がいない実行（非対話の実行や、subagent として呼ばれた実行）では、聞くはずだった内容（判断の材料と選択肢）を報告して止まる。

返事を待つ決まり（「本文で聞く」の最後の箇条と、この節の 2 つの段落）には、例外が 1 つある。判断待ちを記録して先へ進む取り決め（承認を省く限定のモードや自律実行の保留など）をそのスキルか呼び出し元のスキルが持つときは、その取り決めに従う。
返事をする人がいる実行でも同じで、取り決めに従って判断待ちを記録し、承認が要らない工程を先に進めてよい。
