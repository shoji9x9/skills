# 書き込み系データの扱い（全モード共通）

**本ファイルが正本。** feature / api-resource / batch のどのモードでも、状態を変える検証（書き込み系スペック・ファイルアップロード・バッチ実行）はこの規律に従う。

- **読み取り側の特性化を先に行う。** 状態を変えないため何度でも回せ、DB 復元環境が整う前でも進められる
- **書き込み側は復元可能な環境でのみ行う**（スナップショット → 実行 → リストア）
- 復元できない場合は、**一意プレフィックス付きの自己作成データ＋後始末**で代替する
- 後始末できないもの（削除機能が無い等）は、**事前にユーザーへ残置可否を確認**し、「hermetic でない」と明示的にマークして `gaps.md` に一覧化する（隠さない）
- **選択した target の `forbidden_actions` を常に尊重する**（対象は UI / API 操作。空リスト＝すべて実施可、未定義＝読み取り専用。意味論の正本は `replace-strategy` の `references/project-config.md`）。
  現行アプリのコード・構成には手を入れず、データの書き込みは上記の復元・後始末の規律と承認の範囲でのみ行う。書き込みが許可されない target では書き込み系スペックを実行せず `gaps.md` に「未検証」として記録する

## ファイル・ストレージへの書き込み

- **ファイルのアップロードもこの規律の対象**である。アプリのストレージ／ファイルシステムに残る書き込みであり、**UI から消せないことが多いため後始末できない側に倒れやすい**
  （`gaps.md`「hermetic でないテスト一覧」の常連になる前提で計画する）。操作・fixture の生成・検証対象の正本は `replace-strategy` の `references/file-io.md`
- **書き込んでよい範囲は設定が決める**: ストレージへ**直接**書く・消す（後始末等。アプリ経由のアップロードは `forbidden_actions` が律する）のは選択した target の `storage.write_scope` 配下だけ（`storage.seedable: true` が前提）、DB は `db.seedable`、静的データは `dataset_static_paths`。
  範囲外へ書こうとしたら実行せず停止する（契約の正本は `replace-strategy` の `references/project-config.md`）
- **ストレージ実体へのゴールデンデータ投入は v1 スコープ外**（正本: 同ファイル「ファイルストレージ」）。アップロード操作の特性化はスコープ内で、投入だけがスコープ外である
