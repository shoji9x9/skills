# 追記専用の一覧（`append-only-manifest.json`）の書き方

`assets/append-only-manifest.json` の項目を足す人と直す人向けの規約である。
チェックは `scripts/append-only-check.mjs` が行う（呼び方は `SKILL.md`「成果物」）。

## 項目の `id`

各項目の `id` は、一覧の中で一意にする。
重複すると、同じファイルに当たった、突き合わせ方の違う 2 つの項目のうち、先に書いた方が警告なしに使われる。厳しい方の規則が外れるので、重複した一覧は exit 2 で失敗にする。

## 突き合わせの単位（`unit`）

一覧の各項目は、`unit` で突き合わせの単位を持つ。

| `unit` | 単位 |
| --- | --- |
| `lines` | 空白を畳んだ行 |
| `markdown-structure` | 見出し・表の列名・表の行（先頭のセルが鍵）・行 × 列のセル・定義の箇条書きの鍵・それ以外の散文の行 |
| `json-arrays` | `arrays` に挙げた配列の要素（深い等価で比べる） |

鍵だけを同一性にしない。
表の行は、先頭のセルだけを残せば中身を丸ごと差し替えられる。`key` を持つ配列も、鍵以外を自由に書き換えられる。

## 更新を許す箇所を開けるオプション

原本が更新を定めている箇所だけを、次のオプションで開ける。

- `mutable_columns`: 列名で開ける。`"*"` を書くと、セルを取り決めの対象から外す。
- `mutable_bullets`: 定義の箇条書きの鍵で開ける。
- `mutable_blocks`（`lines` 専用）: 原本が削除を定めている YAML のキーパスの配下を、単位から外す。
  キーの行は鍵だけの単位に畳むので、キーごと消せば失敗にする。
- `growable_containers`（`lines` 専用）: 追記だけを許すキーパスの、フロー形式のコンテナを、要素ごとの単位に展開する。
  要素を足すのは単位の増加、要素を消すのは単位の消失になる。
- `registry_groups`（`lines` 専用）: 鍵をまたいで要素が移動する台帳を、グループに共通の要素の単位に展開する。
  - 例は `intentional_diffs` の `keep` / `may_change` / `pending` で、棚卸しのときに人が文言を移す。
  - 鍵ごとの存在は別の単位で守るので、キーごと消せば失敗にする。どの鍵からも無くなった要素だけを失敗にする。
  - 要素がオブジェクトのときは、`item_key` で照合する。移動先に無い付随のフィールド（`slug` / `added_by` など）は、単位から外す。
- `fill_only`: 空から非空への変更だけを許す。
- `transitions`: 明示した `<変更前>-><変更後>` の変更だけを許す。

## 空欄で追記して後で埋める列（`fill_only_columns`）

空欄で追記し、後で人が決定を埋める表の列は、`fill_only_columns`（`markdown-structure` 専用）に書く。

- 空のセルだけを未記入とみなす。`-`（該当なし）と `未確認` は、決めた値・記録として守る。
  `-` も未記入として扱うと、決定済みの行の「該当なし」をその場で書き換えられる。
- 未記入から値への変更は通す。入っている値の差し替えと消去は、縮小として失敗にする。
- この列を `mutable_columns` に置くと、決めた値の書き換え（`引き継ぐ` から `直す` など）まで通る。どちらにも置かないと、空欄を埋めるだけの正規の編集が失敗する。
- 同じ列を `mutable_columns`（`"*"` を含む）と `fill_only_columns` の両方に書いた一覧と、`"*"` を書いた一覧は、exit 2 で失敗にする。緩い方が警告なしに優先されるためである。

## キーパスの書き方

キーパスを取る 3 つのオプション（`mutable_blocks` / `growable_containers` / `registry_groups`）は、ルートからの完全なパスで書く。
設定ファイルなら `skills.<スキル名>.intentional_diffs.pending` と書き、末尾だけでは照合しない。一致しないパスは、警告なしに「外し忘れ」になる。

同じパスを 2 つのオプションに書くと、単位が二重に決まるので、その一覧は exit 2 で失敗にする。
完全一致だけでなく、祖先と子孫の入れ子も同じに扱う。`mutable_blocks` に祖先を書くと、配下の展開がそこに届かず、配下の削除がすべて警告なしに通る。

## 同じ鍵の行

同じ鍵の行は、出現順で区別する。
`assets.md` は、方針を覆した行と現在の行が同じ「種類」で並ぶ。区別しないと、2 行の間でセルを入れ替えても単位が変わらない。

## すべてを行として比べない理由

原本は、その場での更新を明示的に求めている（版の +1、状態の列の `未` から `済`、Issue の列の `未起票` から番号、最終更新の日時）。
すべてを行として比べると、これらが「失われた行」と判定され、決定を 1 つも捨てていない成果物で収束が止まる。
守るのは行・列・節・配列の要素で、セルと箇条書きの値ではない。

`lines` で、空のリストに最初の要素を足すことを縮小と判定させないのが `growable_containers` である。
棚卸しで `pending` から `keep` に文言を移すことを縮小と判定させないのが `registry_groups` である。

外して「別の工程が数える」ことに任せない。
`pending` の配下を単位から外すと、棚卸しを経ずに要素を丸ごと消した編集まで通る。その削除を数える工程は無い。
`pending-triage-check.mjs` は今の `pending` を母集合にするので、消えた要素は対象にならない。

## 緩めるキーは名指しする

行はインデントを畳むので、同じ鍵の行が複数あることがある（`targets[].forbidden_actions` など）。
名指しせずに「増えた」を判定すると、兄弟の間で要素を移動しただけの編集（片方を空にして、もう片方に足す）まで通る。

## 行末のコメント

行末のコメントは、切り取ってから読む。
原本の設定ファイルは `keep: [] # 変えない（…）` と書く。行末が `]` であることを求めると、実際のプロジェクトでは緩和が一度も有効にならない。

鍵の行末のコメントは独立した単位として守るので、消せば失敗にする。
要素の行末のコメントは単位にしない。要素は設計上、鍵をまたいで移動するので、移動先にコメントの置き場所が無いためである。
