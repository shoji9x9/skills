# 対応範囲（対象・対象外・条件付き）

**着手前に「自分のアプリのどこまでを本スキル群で検証できるか」を判断するための一覧。** `setup` の測定（副作用の棚卸し）・戦略提示・`issues` の起票範囲で読み、判断に迷ったときも本ファイルで引く。

**一覧の正本は本ファイル。** 各スキルの `SKILL.md` / `references` は実行時の**行動**（どう記録するか・どこへ差し戻すか）を持つ。
**行動は各所、一覧は本ファイル**という分担であり、双方向に転記しない（列挙を各所へ写すと改訂が伝播せず、行動を本ファイルへ写すと実行時に読む場所が二重になる）。

## 判定の軸

**現行アプリを変更せずに、現・新の結果を決定論的に比較できるか。**

比較のために現行アプリのコード・構成の変更（ログ挿入・SMTP 迂回・プロキシ挿入）が必要なもの、または比較自体が現実的でないものは**対象外**とする。
対象外は「無いこと」にせず、`gaps.md` に「手動検証が必要」「スコープ外」として記録する——**確認済みにしない**のが本スキル群の原則である。

|---|---|---|---|
| 画面の表示・操作・状態・権限差 | 対象 | — | `parity-suite` の `references/coverage.md` |

| API（応答・エラー・並び順・ページング・認可） | 対象 | — | `parity-suite` の `references/api-batch.md` |
| バッチの出力（DB 状態・生成ファイル） | 対象 | 現行テスト環境のファイルシステムに到達できること | `parity-suite` の `references/api-batch.md`、[`file-io.md`](file-io.md) |

| アニメーションのパリティ | 対象外 | 差分比較で `animations: 'disabled'` にするため原理的に扱えない | `parity-suite` の `references/coverage.md` |

| ローディング表示 | 条件付き | 明示的な loading UI がある画面だけ対象。indicator が無い画面は対象外として記録 | `parity-suite` の `references/coverage.md` |
| 採取環境依存の一致（フォント等） | 条件付き | 環境非依存のフォントスタックにする／利用者環境でも採取する／`gaps.md` に残す のいずれか | `parity-suite` の `references/baseline.md` |
| 書き込み系の検証 | 条件付き | 対象 target が書き込みを許可していること（`forbidden_actions` / `seedable`）。不許可なら実行せず未検証として記録 | [`project-config.md`](project-config.md)「実行対象環境」 |
| 後始末できない書き込み（削除機能が無い等） | 条件付き | 事前にユーザーへ残置可否を確認し、「hermetic でない」と明示して一覧化 | `parity-suite` の `references/data-discipline.md` |
| 本番環境 | 対象外 | 参照も投入もしない（テスト環境のみ） | `golden-dataset` の `SKILL.md`「厳守の制約」 |

## 対象外・条件付きの扱い

- **対象外は記録して初めて扱ったことになる。** `gaps.md`（`parity-suite` が形式を定義）へ理由付きで残し、`.replace/survey.md` の副作用棚卸しにも判定を残す
- **条件付きは「条件を満たせるか」を実測してから区分を確定する**（満たせるはずだ、では未測定）
- **一覧に無い領域を見つけたら、勝手に対象／対象外を決めない。** 上記「判定の軸」で判断できるなら判断してユーザーに確認し、確認結果を本ファイルへ追記する

## この一覧に到達できないとき

**本ファイルを読めない環境（未インストール・ファイル移動）では、対象／対象外を推測で断定しない。**
「確認済み」にはせず、当該領域を `gaps` に未検証として残し、一覧の所在をユーザーに確認する（安全側に倒す）。
