# 比較測定のベースラインは遮断を実測で確認してから測る

## 事象

A/B 比較測定のベースライン側が、隔離したはずの資産を別経路から読んでしまい、測定した差分が信号にならなかった。
2026-04-02 / 2026-04-27 / 2026-05-19 / 2026-06-02 / 2026-06-14 と 5 回、同じ形で再発している。
5 回とも、測定担当者がその場で同じ遮断ラッパー（4 群のマウント指定）を組み立て直し、逐次で測り直すことで解決した。
組み立てた内容は 5 回とも同一だった。

## 根本原因

- なぜベースラインが資産へ到達したか? → 隔離の対象を「作業ディレクトリ」1 点で決めていた
  - なぜ 1 点で足りると考えたか? → 最初に特定した到達経路を、経路の集合そのものと同一視した
    - なぜ同一視したか? → 到達経路は OS（bind mount のミラー）や測定ハーネス自身（並列 run が作る一時ディレクトリ）も作る、という視点がなかった

## 提案

ベースラインは、対象資産へ到達できる経路を列挙して塞ぎ、**遮断できたことを実測で確認してから**測る。
汚染が疑われる run の差分は無効として扱い、経緯を残す。並列実行は隔離が効いているときだけ成立する。
