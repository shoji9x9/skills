# PR の本文は、決まった節を決まった順に書く

## 事象

PR の本文に、関連 Issue・変更の概要・確認した内容のすべてを書いたが、PR ごとに並びが違った。確認した内容が冒頭の段落に含まれていた PR もあり、レビューする人が確認の結果を探すのに時間がかかった。

## 根本原因

`AGENTS.md` は PR に書く要素を挙げているが、本文をどの節に分け、どの順に並べるかを決めていない。

## 根拠

同じセッションで作った 3 件の PR の本文を読み比べ、並びが 3 通りあることを確かめた。KEDB 照合（PR・本文）で一致は無かった。

## 既存の規約

- 扱い: なし
- 場所: なし
- 照合した範囲: `AGENTS.md`・`docs/` を `PR には`・`確認した内容` で検索した。要素を挙げた行はあるが、構成と順序を決めた記述は無い

## 提案

PR の本文の構成と順序を決めて、規約に書く。
