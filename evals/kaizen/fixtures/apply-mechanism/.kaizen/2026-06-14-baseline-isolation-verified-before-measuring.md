# 比較測定のベースラインは遮断を実測で確認してから測る

## 事象

A/B 比較測定のベースライン側が、隔離したはずの資産を別の方法で読んでしまい、測定した差分が信号にならなかった。
2026-04-02 / 2026-04-27 / 2026-05-19 / 2026-06-02 / 2026-06-14 と 5 回、同じ形で再発している。
5 回とも、測定担当者がその場で同じ遮断ラッパー（4 群のマウント指定）を組み立て直し、逐次で測り直すことで解決した。
組み立てた内容は 5 回とも同一だった。

## 根本原因

- ベースラインが資産へ到達した理由: 隔離の対象を「作業ディレクトリ」1 点で決めていた
  - 1 点で足りると考えた理由: 最初に見つけた到達の手段を、到達の手段のすべてと同じものとみなした
    - 同じものとみなした理由: 到達の手段は OS（bind mount のミラー）や測定ハーネス自身（並列 run が作る一時ディレクトリ）も作る、という視点がなかった

## 提案

ベースラインは、対象資産へ到達できる手段を列挙して塞ぎ、**遮断できたことを実測で確認してから**測る。

汚染が疑われる run の差分は無効として扱い、経緯を残す。並列実行は隔離が有効なときだけ成立する。
