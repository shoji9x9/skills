# ジョブの失敗を、ログで失敗したステップを確かめずに特定の検査の結果として書く

## 事象

PR #920 で、CodeQL の検出を確かめた結果を PR にコメントした。probe の commit で `GitHub Actions lint` のジョブが失敗したことを、zizmor が指摘した証拠として書いた。後でジョブのログを読むと、失敗したのは前のステップの actionlint で、zizmor のステップは実行されていなかった。コメントを編集して直した。

## 根本原因

- なぜ誤ったか: check-run の結論（failure）だけを見て、ジョブの中のどのステップが失敗したかを確かめなかった。
- なぜ確かめなかったか: 手元で zizmor が同じ種類の入力に exit 14 を返すことを確かめていたので、CI でも zizmor が失敗させたと思い込んだ。
- なぜ問題になるか: 1 つのジョブに複数の検査のステップがあると、ジョブの結論は最初に失敗したステップのものになり、後のステップは実行されない。ジョブの結論は、特定のステップが何かを検出した証拠にならない。

## 根拠

原因を 1 つに絞れているが、観測は 1 回なので medium にした。
コメントを投稿した後に `gh api .../actions/jobs/<id>/logs` を読み、actionlint の `expression` の検査で exit 1 になり、zizmor のステップが無いことを確かめた。
KEDB 照合（失敗・ジョブ・ステップ、ログ・check-run・結論）で一致は無かった。
コメント・gh pr comment で一致した `2026-10-14-worktree-bash-literal-guard-recurs.md` は別の事象である。

## 提案

CI のジョブが失敗したことを、特定の検査が検出した証拠として書く前に、ジョブのログで失敗したステップと、そのステップの出力に狙った指摘があることを確かめる。

- 1 つのジョブに検査のステップが複数あるときは、前のステップが失敗すると後のステップは実行されないことを前提にする。
- 機構は作らない（観測は 1 回で、文章の主張を機械で判定できない）。
- 置き場所の候補は、`docs/agent-workflow.md` の「確かめ方」にある、該当なしを根拠にするチェックの節。
