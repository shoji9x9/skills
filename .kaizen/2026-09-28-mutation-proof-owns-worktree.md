# 作業ツリーを書き換えて戻す長時間処理の実行中に、同じツリーの対象を編集しない

## 提案

作業ツリーのファイルを書き換えて戻す長時間処理（変異実証など）の実行中は、同じツリーの対象を編集するだけでなく読んで写す処理（reinstall-skill.sh・コピー・成果物生成）も走らせず、背景で走らせるなら別 worktree に置き、実行器側は復元の直前に対象が「自分が書いた変異後の内容」のままかを確かめて外部の編集を黙って上書きしない。

- 実行器（`scripts/mutation/check-mutation-proof.js` の `proveMutation`）: 復元前に現在の内容が `mutated` と一致するかを確かめ、一致しなければ上書きせず exit 2 で止める（`recoverFromInterrupted` は既に同じ照合をしている。通常経路にだけ無い）
- 手順（`AGENTS.md`「変異実証」）: 「並行して走らせない」に、**実行中に同じツリーの対象ファイルを編集しない**ことと、変更前の計測は基点 commit の別 worktree（`git worktree add --detach`）で取ることを足す
- 手順: 完了は通知ではなくプロセスの実在（`/proc/<pid>`）と実ログの最終行（`N proven / M failed`）で判定してから、正本を読む処理へ進む
- 横断: 同じく作業ツリーを書き換えて戻す処理（`check-mutation-proof.test.js` の差分選択テストの実走）も同じ前提

## 事象

Issue #507 で、変更前の `reaction-check` 宣言の所要時間を共有の作業ツリーで背景実行したまま、同じ `reaction-check.mjs` を編集した。
実行器は変異 1 件ごとに「元の内容」を読み、変異を書き、テスト後に元の内容を書き戻すため、編集は次の復元で黙って消えた（出力にも出ない）。
さらに計測を SIGTERM で止めたため exit ハンドラが走らず、変異（`if (false)`）が作業ツリーに残った（復元情報からの手動回収で戻した）。

## 根本原因

- なぜ編集が消えた? → 実行器が復元時に、読み込み時点の内容を無条件に書き戻す（外部の編集を検出しない）
- なぜ同じツリーで編集した? → 長い計測を背景へ回して並行で実装する段取りにし、計測がそのツリーの対象ファイルを所有している前提を落とした
- なぜ前提を落とした? → 規約は「無関係な `pnpm test` と重ねない」（読む側の衝突）だけを書き、**書く側の衝突**（実行中の編集が上書きされる）と、変更前計測を別 worktree で取る段取りが書かれていない。実行器にも検出の仕組みが無い

### 再発（2026-10-02、Issue #432）

変異実証を背景実行中に「完了した」と誤認し（背景タスクの完了通知が先に来たうえ、実ログに無い PASS 行を事実として扱った）、
`scripts/tools/reinstall-skill.sh` を実行した。インストール済みコピーに実行中の変異（AO-EXCL-ALL の `if (false)`）が写った。
実証の終了後に再インストールして回収した（skills-sync でも検出できた）。

- なぜ変異が写った? → reinstall が作業ツリーの正本を読んで写すため、実行中の変異も写る
- なぜ実行中に走らせた? → 完了をプロセスの実在（`/proc/<pid>`）ではなく通知で判断した
- なぜ? → 規約は「編集しない」（書く側）だけで、正本を読んで写す処理（再インストール・生成）も同じツリーの所有を侵すことが書かれていない
