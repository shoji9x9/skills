# ポーリング対象の完全 SHA は各呼び出し内で正本から取得する

## 事象

PR #355 の Codex レビュー到着監視で、commit 出力の短縮 SHA `0649306` を手で完全 SHA に補完して API の絞り込みへ使った。存在しない SHA のため review は常に 0 件になり、check suites API は 422 を返し、Automatic review の観測不能と誤診しかけた。

## 根本原因

完全 SHA を使う規約は把握していたが、監視ループのコマンドを組み立てる際に表示済み短縮値を識別子の正本として扱った。これは「初回に完全 SHA を確認する」ことと「各ポーリング呼び出しが正本から機械取得する」ことを同一視したためであり、さらに API の 0 件を対象不一致と検査成功に分ける陽性コントロールが無かったことが根本原因である。

## 提案

commit・review・check-runを SHA で相関するポーリングは、各ツール呼び出し内で完全 SHA を構造化レスポンスから取得し、形式と対象PRの現在HEADとの一致を検証してから同じ呼び出し内のAPIへ渡す。

短縮 SHA を変数初期値・フィルタ文字列・URLへ手入力しない。レビュー0件を根拠にする前に、そのSHAでcommitまたはcheck suitesを取得できることを陽性コントロールとし、422や対象不一致を「レビューなし」へ倒さない。
