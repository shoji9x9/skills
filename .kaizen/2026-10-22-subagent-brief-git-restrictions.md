# サブエージェントへの指示に、作業ツリーで使わない git の操作を書き、セッションだけで決めた制約も渡す

## 事象

Issue #758 の PR #771 で、レビューの指摘の修正を general-purpose のサブエージェントに任せた。
サブエージェントは、旧版との比較のために `git stash` で作業ツリーを一時的に戻し、その後に元へ戻した。
このセッションでは `git stash` を使わない制約で作業していたが、サブエージェントへの指示（共通の指示のファイルと各プロンプト）には書いていなかった。
stash は残らず、変更も失われなかったが、同じ作業ツリーで別のエージェントが並行して編集していれば、その変更も stash に入って消えるおそれがあった。

## 根本原因

- なぜ stash を使ったか: 指示に、使わない git の操作が書かれていなかった。サブエージェントは新しい文脈で動き、親のセッションだけにある制約を知らない。
- なぜ書かなかったか: 指示を書くとき、作業の内容（直す対象・確かめ方・守る振る舞い）だけを挙げ、作業ツリーの操作の制約を挙げる手順が無かった。
- なぜその手順が無いか: `AGENTS.md` のブランチ運用は `--amend` と force push を禁じるが、`git stash` には触れていない。並行するエージェントが同じ作業ツリーを共有するときに危ない操作（stash・checkout -- ・reset・restore）の一覧も、どこにも無い。

## 根拠

確信度の理由: 1 回の観測で、指示に制約が無かったことと stash が使われたことの対応は、サブエージェントの報告で確かめた。
同じ PR の 3 回目の修正の指示には使わない操作を書き、そのサブエージェントは一時的な変更をファイルのコピーで退避して戻した。
KEDB 照合: 「サブエージェント」「指示」で `.kaizen/2026-10-16-delegated-judgment-unchecked-distribution.md` が一致した。判断の基準を渡す学びで、作業ツリーの操作の制約は扱っていないので、別の学びにした。

## 提案

サブエージェントに作業ツリーでの作業を任せるときは、使わない git の操作（stash・checkout -- ・reset・restore・amend・force push）と、セッションの中だけで決めた制約を指示に書く。

- 一時的な変更の退避はファイルのコピーで行い、cmp で戻ったことを確かめる形を、同じ指示に書く。

- 置き場所は `AGENTS.md` の「外向きの操作と破壊的な操作」に 1 行足し、理由（並行するエージェントの変更を巻き込む）を `docs/agent-workflow.md` に書く。
- 横断スコープ: 作業を分担して任せるスキル（`issue-batch` など）の、サブエージェントへの指示の雛形に同じ一覧があるかを確かめる。
