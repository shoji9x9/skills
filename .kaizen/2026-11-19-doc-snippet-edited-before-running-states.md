# 文書に書くシェルの手順は、対話のシェルに貼る形と、対象が 0 件の状態で実行してから書く

## 事象

PR #1064 のレビューの指摘（テンプレートが 0 件なら失敗にする）を直すとき、`docs/security-scanning.md` の bash の例を 3 回編集した。
`exit 1` を置いた後で、対話のシェルに貼ると閉じることに気付いて `if`/`else` に直し、実行すると 0 件でも終了コードが 0 だったので `false` を足した。

## 根本原因

- なぜ 3 回編集したか: 書いてから実行した。
- なぜ書いてから実行したか: 文書の例をスクリプトと見なさず、読み手が実行する形（対話のシェルに貼る）と状態（対象が 0 件）を先に挙げなかった。
- なぜ挙げなかったか: 既存の規約（新しい分岐は状態を作って確かめる・手順のコマンドは 1 回実行する）は読んでいたが、小さな文書の修正だと見て先に書いた。

## 根拠

確信度 medium: 観測は 1 回だが、原因は「実行する前に編集した」に絞れる。
このセッションで、編集の後に、抜き出したコードブロックを実物の対象と空のディレクトリで実行して、2 回の手戻りに気付いた。
KEDB 照合（「コードブロック」と「exit」、「貼」と「シェル」と「exit」）で、同じ原因の学びは無かった。

## 既存の規約

- 扱い: 明確
- 場所: `AGENTS.md`「確かめ方」（新しく作った分岐は、その状態を実際に作って確かめる・0 件の結果を合格として扱わない）、`.agents/rules/external-tool-format-verification.md`（手順として書いたコマンドの並びは 1 回実行する）
- 照合した範囲: `AGENTS.md`・`docs/agent-workflow.md`・`.agents/rules/` を「0 件」「手順として書いたコマンド」で検索した

## 食い違い

- 相手: なし
- 判断: なし

## 提案

文書に書くシェルのコードブロックは、書く前に、読み手が実行する形（対話のシェルに貼る）と対象が 0 件の状態で実行し、終了コードとシェルが閉じないことを確かめてから書く。

- 既存の規約に従う。再発したら、文書のコードブロックを実行して確かめる機構を検討する。
