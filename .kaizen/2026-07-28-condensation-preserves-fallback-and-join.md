# 転記を正本参照へ縮約するときは、転記が担っていた退避と接続点を引き継ぐ

## 事象

Issue #133（正本と転記の drift 防止）で、on_diff ガードレール一覧・target 選択規則の
全文転記を「要約＋正本参照」へ縮約した。/code-review が 3 件を検出した。

- `parity-diff/SKILL.md` の表セルに選択規則の短縮転記（「省略時は new 側の `default`」）が残存。
  同ファイル 25 行目で「ここへ転記しない」と宣言した直後で自己矛盾し、停止条件も欠落していた
- ガードレール転記を消した結果、正本（`replace-strategy` の references）へ到達できない環境
  （未インストール・ファイル移動）で安全弁ごと失われる経路が開いた。転記は退避を兼ねていた
- 正本からスキル名の列挙を削った結果、一般規則（`default` を使う）とスキル固有の追加候補条件
  （`golden-dataset` の `db.seedable`）の接続点が誰の担当でもなくなった

## 根本原因

- なぜ穴が開いたか? → 縮約を「重複した文字列の削除」としてのみ捉えた
  - なぜそう捉えたか? → 重複＝冗長という前提で、転記が果たしていた副次機能を洗い出さなかった
    - なぜ洗い出さなかったか? → `doc-altitude` は「重複を置くな」を規定する一方、
      **既にある重複を消すときの手順**を規定していない ← 根本原因

KEDB 照合: 表セルの残存は [[2026-06-09-intra-doc-consistency-pass]]（applied・同一ドキュメント内の
自己整合）の再発。退避・接続点の喪失は既存の学びに無く、[[2026-06-08-agent-doc-altitude]] の裏面にあたる。
横断スコープ: 同種の縮約は姉妹スキル群の references 全体で多用されており同じ確認が要る。

## 提案

重複を正本参照へ縮約するときは、転記の削除で終えず「別形式での残存」「正本に到達できないときの
退避」「一般規則と固有条件の接続点」の 3 点を確認する。`.agents/rules/doc-altitude.md` に追記する。

1. **規則の再記述が別形式で残っていないか掃き出す**。箇条書きだけでなく表セル・脚注・短縮形も
   対象にする（文書の形で「転記か」を判断せず、規則の内容が再記述されているかで判断する）。
   同一ファイル内で「ここへ転記しない」と宣言したら、そのファイル自身を最初に検査する
2. **正本に到達できないときの分岐を消費側に置く**。安全弁の転記を消すなら、参照先を読めない
   場合は従わず停止する指示を残す（正本自身には書けない指示なので消費側が持つ）
3. **一般規則と固有条件の接続点を明示する**。正本から固有事情の列挙を削るなら「固有条件を持つ
   側の規定に従う」旨を正本に残し、宙に浮かせない
