# バッククォートを含む本文はシェルの二重引用符に埋めず quoted heredoc で渡す

## 事象

設定スキーマの YAML ブロックが実際にパースできるかを確かめようとして、
`python3 -c "..."`（二重引用符）の中に Markdown のコードフェンスを含む正規表現を直接埋めた。
bash がフェンスのバッククォートを command substitution として解釈し
``syntax error near unexpected token `.*?'`` で落ちた。

同じ 1 コマンドに、書きかけの実験断片（`... if False else None` と未使用の
`import yaml`）も残っていたため `ModuleNotFoundError: No module named 'yaml'`
も同時に出た。**結果としてこの実行では YAML ブロックのパース検証は 1 度も
走っていない**。別ツール（node + js-yaml）で取り直して初めて検証できた。

## 根本原因

1. なぜ落ちたか → 二重引用符の中のバッククォートはシェルが command
   substitution として解釈するため。
2. なぜ二重引用符に埋めたか → 同じセッションで多用していた quoted heredoc
   (`python3 - <<'PY'`) を、短い 1 行だからと使わなかった。ペイロードに
   バッククォート・`$` が含まれるかを引用形式の選択基準にしていなかった。
3. なぜ基準が無いか → 「シェル経由でインタプリタへ本文を渡すときの引用形式」
   の規律が基底ドキュメントに無い ← 根本原因（対策可能）

加えて、検証コマンドに使い捨ての実験断片を残したことで、**失敗の原因が
2 つ重なって読み取りにくくなり**、かつ「検証したつもりで何も検証していない」
状態が生まれた。

## 提案

バッククォートや `$` を含む本文（Markdown のコードフェンス・正規表現・
テンプレート文字列）をシェル経由でインタプリタへ渡すときは、二重引用符の
`-c` ではなく quoted heredoc（`<<'PY'` / `<<'JS'`）を使う。検証コマンドには
書きかけの実験断片を残さず、落ちたらその検証は「実行していない」として
別手段で取り直す。

- 反映先: 基底ドキュメント（`AGENTS.md`「ワークフロー」節）。パスで絞れない
  一般規律なので `.agents/rules/` にはしない
- 既存の隣接項目「パイプ越しの成否判定に末尾 `$?` を使わない」と同じ粒度で
  並べる（どちらもアドホックな検証コマンドの信頼性の話）
- 横断スコープ確認: `skills/` `scripts/` `docs/` `AGENTS.md` に
  バッククォートを含む `python3 -c "` / `node -e "` は 0 件。今回はアドホック
  実行のみで、成果物への波及は無い
