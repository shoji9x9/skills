# 実行中のセッションを検査する検出器を広げると、自分の編集コマンドがブロックされる

## 事象

PR #399 でコミット前ゲートの区切り文字クラスへ backtick / `)` / `{` を追加した直後から、
**自分の編集コマンドが 2 度ブロックされた**。heredoc で渡したコメント文やテスト
ケースに含まれる `git commit` のリテラルが、新しく広げた区切りの直後に来ていたため。
ブロックは呼び出し全体にかかるので、同じ呼び出しに入れたファイル書き込みも走らない。

## 根本原因

- なぜ自分の編集が止まったか → ゲートは PreToolUse で、**実行中のセッションのツール呼び出しを
  検査する**。検出器を広げる変更は、その瞬間から自分の呼び出しにも適用される
  - なぜ予測しなかったか → 検出器の対象を「ユーザーの commit」だけと見ており、
    自分が書くテスト・コメント・コミットメッセージも同じ入力集合だと考えていなかった
    - なぜそう見たか → **自分を含む系を変更しているという自己参照性を、変更前に列挙していない** ← 根本原因

## 提案

実行中のセッション自身を検査する仕組み（PreToolUse hook 等）の検出範囲を広げるときは、自分のツール呼び出しが新たに何に当たるかを先に列挙する。

- 変更前に「この拡張で、自分がこれから書くテスト・コメント・メッセージのどの形が引っかかるか」を 1 行宣言する
- 引っかかるなら、検出される語を**部分文字列に分けて構築**する（python なら `"com" + "mit"`）。
  ゲートは呼び出し全体を止めるので、同じ呼び出しに入れた準備も走らない
- AGENTS.md の既存項（「`git commit` を含む呼び出しに準備を混ぜない」）の隣に置く。
  既存項は「本物の commit を含む呼び出し」の話だが、こちらは**commit を含まない呼び出しが
  リテラルだけで止まる**ケースで、別の現象
