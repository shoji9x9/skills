# 共有契約の変更は消費側を逆引きしてからコミットする

## 事象

レビューツールの設定解決へ CLI と環境変数を追加したが、初回コミット前に issue-batch の handoff と基底ドキュメントの旧 YAML 前提を更新できなかった。また、ソースリポジトリ固有の mise 設定が配布先にも効くように読める README 記述を残し、Codex レビューで 3 件の手戻りになった。

## 根本原因

定義元の pr-finalize-loop と pr-review-handle の整合だけを確認し、設定値を読む箇所ではなく名前が既知の姉妹スキルだけを対象にした。これは共有契約の「定義」を直せば完了と考えたためであり、さらに配布境界をまたいだときにルート設定が同梱されるかというライフサイクルを通していなかったことが根本原因である。

## 提案

共有設定の解決規則を変えたら、commit 前に設定名・handoff 先・要約文を横断検索し、定義元だけでなく全消費側と配布境界を通した代表フローを突き合わせる。

grep は新しい設定名だけでなく変更前の設定名と委譲先スキル名でも行う。ルート設定に依存する説明は、配布物へ同梱されるかを確認し、同梱されないならソースリポジトリ固有と利用側手順を分けて書く。
