# 条件リストに項目を足したら、同じ条件を別語彙で言い切っている分岐版を逆引きで列挙する

## 事象

Issue #230 で `pr-finalize-loop` / `pr-review-handle` の「指摘の収集対象」に 3 系統目
（トップレベル PR コメント）を追加した。編集した節の中は整合していたが、`/code-review` で 4 件の欠陥が出た。

- `review_tool: none` の完了条件が「CI 全成功かつ未解決スレッド無し」のままで、追加した
  「スレッド外の指摘対応済み」が抜けていた（同じファイルの停止条件とは矛盾）。3 箇所（要約・収束判定・
  `references/review-tool.md`）で同時に漏れた
- 新設コマンドが導入した `<headRefOid>` を、`pr-review-handle` のフローがどこでも取得していなかった
- 切り詰め禁止の警告が、`pr-review-handle` には存在しない `body[:200]` を指していた（実在は `body[:60]`）
- 絞り込み指示が「bot に絞ってよい」と「bot 以外を捨てない」を並記し、実行可能な指示として自己矛盾していた

## 根本原因

- なぜ漏れたか? → 波及箇所の列挙を、変更した概念のキーワード（「レビュー本文」等）の grep に頼った
  - なぜ grep で足りなかったか? → `none` 分岐は条件を**列挙し尽くす形**で書かれ、追加語を 1 つも含まない。
    分岐版は「変更前の語彙で完結している」ため、変更後の語では原理的にヒットしない。
    同様に、新設したプレースホルダ（`<headRefOid>`）と、姉妹スキルごとに値が違う実例（`[:200]` / `[:60]`）も
    grep の軸に乗らない
    - なぜその空振りを想定しなかったか? → `docs/skill-development.md`「push 前の整合パス」は項目 1 で
      キーワード grep を、項目 5 で「新設は grep が空振る」を扱うが、後者の逆引きは**契約の新設**に限った
      記述で、**既存の条件リストへの項目追加**が同じ空振りを起こすことは書かれていない ← 根本原因

## 横断スコープ

同じ形は「条件を外す・減らす」分岐すべてにある——`review_tool: none`、`--wait-ci-before-review`、
`--max-iterations` 到達時の報告項目など。姉妹スキルへ複製された節（`references/` の同名ファイル）は、
実例の値だけが違うため grep では等価に見えて中身が食い違う。

## 提案

`docs/skill-development.md`「push 前の整合パス」項目 5 の空振り注記を、契約の新設だけでなく
**既存の条件リストへの項目追加**にも広げる。逆引きの軸を「追加した語」ではなく
**「その条件リストを再掲・要約・例外化している箇所」**に取り、次を 1 件ずつ確認する:

- 条件を**減らす分岐**（`none` / skip / 既定オフのモード）の完了条件
- 同じ条件を短く言い直した**要約行**（節の冒頭・停止条件・使い方）
- 追加したコマンドが導入した**プレースホルダ**の取得元がフローに存在すること
- 姉妹スキルへ複製した節は、**実例の値**（切り詰め桁・API 名）がその複製先に実在すること
