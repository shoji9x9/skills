# ジョブの間で値を渡すとき、失敗したジョブだけを再実行する場合と、渡す側のジョブが失敗した場合を当てていなかった

## 事象

PR #785 で、エージェントのレポートを `review` ジョブから `tracking-issue` ジョブへ artifact で渡した。
再実行で前の試行のレポートを拾わないよう、両方のジョブが自分の `run_attempt` から名前を作る形にした。
失敗したジョブだけを再実行すると `review` は再実行されず、名前が合わなくなる。これを Copilot の 2 回目のレビューで指摘され、名前を `review` の outputs から渡す形に直した。

同じ PR で、GHES ではレポートの upload が失敗して `review` ジョブが失敗する形にしていた。
失敗したジョブの outputs を下流が読めるかは公式のドキュメントに書かれておらず、読めなければ `tracking-issue` が skip される。
Copilot の 3 回目のレビューで指摘され、upload を `continue-on-error` にして `review` を成功で終える形に直した。

## 根本原因

- なぜ名前が合わなくなったか: upload する側と download する側が、同じ式でそれぞれに名前を作っていた
- なぜその形にしたか: 再実行を「run 全体の再実行」の 1 つだけで考え、両側の試行の番号が常に同じだと置いた
- なぜ 1 つだけで考えたか: ジョブの間で値を渡すときに当てる実行の形（全体の再実行・失敗したジョブだけの再実行・後のジョブだけの再実行）を、`github-actions-authoring` の観点が挙げていない。これが根本原因である

当てる形には、渡す側のジョブの結果（成功・失敗・skip）も入る。2 件目では成功だけを当てた。

## 根拠

確信度 medium: 同じセッションの観測で、原因を「受け渡しで、実行の形と結果を 1 つだけ当てた」に絞れているが、再現はしていない。
手元の `/code-review` が再実行で古いレポートを拾うおそれを指摘し、試行の番号を名前に入れて直した。
その後、Copilot が、失敗したジョブだけの再実行で名前が合わないことを指摘した。
さらに Copilot が、upload の失敗で `review` が失敗すると `tracking-issue` が skip されうることを指摘した。同じ原因で、同じ PR の中で 2 回目の手戻りである。
KEDB 照合（再実行・run_attempt）は一致なし。

## 提案

ワークフローのジョブの間で値や artifact を渡すときは、全体の再実行・失敗したジョブだけの再実行・渡す側のジョブの失敗のそれぞれで、受け取る側が動き、同じ値を指すかを確かめる。

- 受け取る側で名前を作り直さず、渡す側の job の outputs から受け取る
- 公式のドキュメントに振る舞いが書かれていない状態（失敗したジョブの outputs など）には頼らず、その状態にならない形（`continue-on-error` など）にする
- 適用先の候補: `.agents/rules/github-actions-authoring.md` に観点を 1 節足す
