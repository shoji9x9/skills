# 複数ファイルを tail するときは -n N で書く

## 事象

リントの結果を 4 ファイルに分けて保存し、`tail -5 f1 f2 f3 f4` でまとめて表示しようとした。GNU tail が `option used in invalid context -- 5` で落ち、ツール呼び出しが exit 1 で終わった。そのため、どのリントが落ちたのかを別の呼び出しで取り直した。

## 根本原因

- なぜ落ちたか: 旧式の `-N`（`-5`）は、GNU tail ではファイルが 1 つのときしか受け付けられない。
- なぜ使ったか: 1 ファイル用の癖をそのまま複数ファイルに当てた。
- なぜ気付かなかったか: 表示用のコマンドを判定の後ろ・呼び出しの末尾に置いたので、その失敗が呼び出し全体の終了コードになった。

表示の段だけが壊れ、判定結果（md=1）は読めたため、影響は小さい。

## 提案

ログを表示する head / tail は、ファイルの数に関わらず `-n N` で書き、複数ファイルの出力の確認は `for f in ...; do echo "== $f"; tail -n N "$f"; done` の形にする。

- 置き場の候補: AGENTS.md の「パイプ越しの成否判定」の項（出力の絞り方）に 1 行足す。
- 横断スコープ: skills/**/*.md のコマンド例に `tail -[0-9]` や `head -[0-9]` を複数ファイルへ当てる形がないか grep する。
