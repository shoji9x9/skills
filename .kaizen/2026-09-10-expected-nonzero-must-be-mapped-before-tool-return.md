# 期待される非ゼロ終了をツールエラーとして外へ返さない

## 事象

`kaizen-kedb-match.sh` が「既存の学びなし」を仕様どおり exit 1 で返したが、複数コマンドをまとめた shell 呼び出しの最終終了コードになり、UI ではツールエラーとして記録された。
Issue #322 で修正した未知の Codex transcript レコードによる exit 2 とは別経路で、走査器や KEDB 検査自体は正常だった。

## 根本原因

1. なぜツールエラーになったか → 状態を表す exit 1 を shell 呼び出しがそのまま返した。
2. なぜそのまま返したか → コマンドの仕様上の判定結果と、呼び出し全体の成功／失敗を同じ終了コードとして扱った。
3. なぜ区別されなかったか → 複数コマンドをまとめるとき、期待される非 0 を直後に解釈して正常分岐へ写像する規律が無かった。

KEDB を `expected non-zero exit` / `shell command` / `tool error` で照合し、直接一致は無かった。横断すると、`grep` の該当なし、差分検査、検索、KEDB 照合など、非 0 が状態を表す全コマンドに同じ原因がある。

## 提案

判定結果として期待される非 0 は直後に保存して `case` / `if` で意味づけし、正常な分岐を 0、仕様外・検査失敗だけを非 0 としてツール呼び出しへ返す。

基底ドキュメントの終了コード規律へ適用した。
