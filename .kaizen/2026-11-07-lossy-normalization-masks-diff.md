# 比較のテストで両辺に同じ正規化を当てるときは、その正規化が落とす文字を含む入力を足す

## 事象

PR #932 で、golden-dataset の表の読み方を GitHub の描画と比べるテストを書いた。
読んだ側と描画の側の両方に `normalizeCell`（バッククォートとアスタリスクを落とす処理）を当ててから比べた。
そのため、`count(*)` のアスタリスクが読み取りで消える食い違いを、テストが検出できなかった。ローカルレビューの指摘で初めて分かった。

## 根本原因

- なぜ検出できなかったか: 両辺に同じ正規化を当てたので、正規化が落とした文字の差は両辺から同じように消えた。
- なぜその比べ方にしたか: 読んだ側の値が `normalizeCell` を通った形なので、描画の側も同じ形にそろえれば比べられると考えた。正規化が情報を落とすかは確かめなかった。
- なぜ確かめなかったか: `AGENTS.md`「確かめ方」の正規化の箇条は「両辺に同じ正規化を当てる」ことを求めているが、正規化が情報を落とすときに差が見えなくなることは書いていない。

## 根拠

確信度は medium である。1 回の観測だが、両辺に当てた正規化が差を消したという原因に絞れている。
`count(*)` の入力を足して `normalizeCell` を直した後も、両辺に `normalizeCell` を当てる比べ方のままでは、記号を落とす形に戻してもテストが通った。
描画の側にテストの中で書いた畳み方を当てると、記号を落とす形で 4 件が落ち、今の形で 51 件が通った。
KEDB 照合では「正規化・テスト・両辺」と「normalize・比較」で照合し、一致は無かった。

## 提案

比較のテストで両辺に同じ正規化を当てるときは、その正規化が落とす文字を含む入力を足し、落としたせいで差が消えていないかを確かめる。

- 適用先の候補: `AGENTS.md`「確かめ方」の「等しいかを比べる処理を正規化で直すときは」の箇条に、正規化が情報を落とすと差も消えることを足す。
