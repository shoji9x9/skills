# 「この変更で壊れた」という指摘は、旧版も同じ条件で測るまで確認できない

## 事象

PR #403 のレビューが medium の所見を出した——「`days_from_civil` を共通ライブラリへ移した結果、
ライブラリを読めない縮退環境で `epoch_from_stamp` が常に失敗し、放置センチネルの時間回収が
no-op になる。**変更前はゲート内にローカル定義があり動いていた**ため回帰」。

指摘は具体的で、修正も安かった（縮退版のスタブへ暦の実装を 8 行足すだけ）。
**私は再現を取らずに修正を当て、「変更前は動いていた」という指摘の記述をそのままコメントへ書いた。**

その後に実測すると、縮退環境では**新旧どちらも 1 件も回収しなかった**。
縮退版の `kaizen_sentinel_key_of` は空文字を返し、`sweep_expired_foreign_sentinels` は
`[ -n "${key}" ] || continue` で持ち主を特定できないセンチネルを一律に対象外へ倒す。
暦が通っても手前で落ちるので、回収はこの PR より前から成立していなかった。
修正は到達しないコードで、コメントは事実に反していた。戻した。

| 構成 | main | 本ブランチ |
|---|---|---|
| 通常（ライブラリあり） | 回収された | 回収された |
| 縮退（ライブラリなし） | 回収されない | 回収されない |

## 根本原因

1. なぜ到達しないコードを書いたか → 指摘の因果（「移動したから壊れた」）を検証せずに受け入れた。
2. なぜ受け入れたか → 指摘が具体的で、修正が安かった。**安い修正は「当ててから考える」を誘う**
   ——測定より先に手が動く。
3. なぜ測定を省いたか → 「現行版で再現するか」だけを検証だと思っていた。
   **仮にそれをやっても誤判定していた**——縮退環境の現行版は実際に 0 件回収で、
   指摘どおりに見える。**回帰と『元からそう』は現行版の観測では区別できない** ← 根本原因（対策可能）

回帰の主張は 2 つの版についての主張なので、確認には 2 点測定が要る。
片側だけ測ると、「壊れている」と「もともと動いていない」が同じ出力になる。
これは [[2026-09-18-detector-needs-labeled-real-data]] と同じ形（検出器が出した側だけを読み、
出していない側を読まなかったので再現率が測れなかった）の、版を軸にした変種。

`AGENTS.md` には「『常に壊れる／失敗する』系のレビュー指摘は、適用前に使い捨て環境で再現テストして
裏取りする」が既にある。**規約はあり、破った。** しかも規約の文面は「再現テスト」としか言っておらず、
現行版だけの再現で足りると読める。[[2026-09-18-behavior-change-judged-by-symmetry-not-regression]] が
却下側の裏取りを足そうとしているのと対になる、採用側の穴。

横断スコープ: 「この変更で壊れた」「以前は動いていた」を含む全ての指摘（レビュー・Issue・ユーザー報告）。
とくに縮退・失敗経路は、元から no-op でも壊れたように見える。

## 提案

回帰を主張する指摘は、修正を当てる前に**旧版と現行版を同じ条件で測り**、差が出ることを確認してから直す。

- **現行版だけの再現で足りると考えない。** 主張が 2 版についてのものなら、観測も 2 版必要。
  旧版は `git show <base>:<path>` で取り出し、同じ入力・同じ環境変数で走らせる
- **差が出ない ＝ 回帰ではない。** その場合は修正を当てず、**なぜ元から成立していないか**を
  1 箇所に注記する（次のレビューが同じ指摘を再提出するため）。本件は
  `epoch_from_stamp` の縮退ガードへ「縮退版は持ち主を特定できないので回収自体が成立しない」と書いた
- **陽性コントロールを添える。** 「両方 0 件」は測定が動いていない可能性と区別できない。
  本件は通常構成（新旧とも回収される）を同じ手順で測り、観測側が回収を見られることを示した
- **修正の安さを着手順の根拠にしない。** 8 行の修正でも、事実でない前提のコメントが一緒に入る

反映先: `AGENTS.md` の「『常に壊れる／失敗する』系のレビュー指摘は、適用前に使い捨て環境で
再現テストして裏取りする」の項に、**回帰の主張は旧版も測る**・**両方 0 件は陽性コントロールで
弁別する**の 2 点を足す。
