# PR が新しく作る状態への指摘を、受け入れ条件の外として確かめずに見送った

## 事象

PR #984 で、`/code-review` の 2 件（取り消しを断られたとき・引き渡しの後に下流の作業が済んでいたとき）と Codex の 1 件目（`--autonomous` で取り消しが判断待ちの間）を、受け入れ条件の外として見送った。
pr-finalize-loop を収束させた後で、3 件を別の Issue にまとめることを提案した。
利用者は同じ PR で直すよう求め、設計の確認・実装・サブエージェントのレビュー・eval をもう 1 周回すことになった。

## 根本原因

- なぜ見送ったか: 3 件とも Issue の受け入れ条件に無い状態だと判断した。
- なぜそう判断したか: `docs/agent-workflow.md` の「受け入れ条件に無い状態を自分から扱いに足さない。足すなら利用者に確かめるか、別の Issue にする」を当てた。
  3 件は、この PR が新しく作った分岐（`handed-off` の記録を `blocked` に戻す流れ）の先で起きる状態である。pr-finalize-loop の「この PR の変更が影響する箇所に生んだ問題」（範囲の中）にも当たるが、狭い方を選んだ。
- なぜ確かめなかったか: 規約が「利用者に確かめる」と「別の Issue にする」を並べ、どちらを誰が選ぶかを書いていない。そのため別の Issue を自分で選び、確かめるのを収束の後に回した。

## 根拠

確信度 medium: 1 回の観測で、見送った判断の根拠が規約の 1 文に絞れている。再発は観測していない。
見送った時点の PR の本文に「受け入れ条件に無い状態は扱いに足さない」と書き、3 件を Issue 化の候補として報告した後に、利用者が同じ PR での修正を求めた。
KEDB 照合（「受け入れ条件」「見送」、「範囲の外」「PR」）で、規約の元になった `2026-10-29-fallback-branches-reviewed-each-round.md`（applied）が当たった。同じ原因の pending の学びは無かった。

## 既存の規約

- 扱い: 埋もれている
- 場所: `docs/agent-workflow.md`「同じ箇所への指摘が 2 回続いたら、分岐を足す前に共通の原因を無くす作りを試す」の 3 段落目。選び方を決めていない弱い書き方である
- 照合した範囲: `docs/agent-workflow.md`・`skills/pr-finalize-loop/`・`skills/issue-start/references/` を「受け入れ条件に無い状態」で検索した

- 判断: なし

## 提案

PR の変更が新しく作る状態（足した分岐の先で起きる場面）への指摘を、受け入れ条件の外として直さないなら、別の Issue にすると自分で決めず、PR を作る前に利用者に確かめる。

- `docs/agent-workflow.md` の該当の文を、この形に書き換える候補にする。pr-finalize-loop の範囲の定義（変更が影響する箇所に生んだ問題は範囲の中）とも揃う
- 機構は作らない。指摘の中身を読まないと、新しく作った状態かを判断できない
