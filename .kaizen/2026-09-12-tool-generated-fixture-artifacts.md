# 決定論ツールが生成する成果物を fixture に手書きしない

## 事象

`parity-component` の eval fixture に、同梱スクリプト `axis-diff.mjs` の出力として `axes.json` を手書きで置いた。
中身はもっともらしく（`ok: true`・`problems: []`）、JSON として妥当で、どの検査にも掛からなかった。

実走した baseline run が別件で指摘したのをきっかけに、同じ入力を実際に `axis-diff.mjs` へ通したところ、
実出力は可変 10 軸 / 固定 62 軸で、手書きの宣言（可変 4 / 固定 6）と食い違っていた。
さらに手書きの `axes.json` は、両インスタンスの値が同一の軸を `variable` に置いていた——
ツールの定義では値が割れない軸は `fixed` なので、ツールなら決して出力しない形だった。

この fixture を使う eval は「採取が完了している」状態を作るためのものだったが、
ツールの契約に反する入力を与えていたため、その状態を作れていなかった。

## 根本原因

1. なぜ実出力と食い違ったか → ツールに通さず、必要な数値だけを想像して書いたから。
2. なぜ通さなかったか → fixture を「読み手に状況を伝える説明」として書いており、
   「ツールの出力である」という契約を持つデータだと捉えていなかった。
3. なぜ捉え損ねたか → 成果物の出自（スキルが書くのか、決定論ツールが書くのか）で
   fixture の作り方を変える規律が無かった。スキルが書く成果物（`metadata.json` 等）は手書きでよいので、
   同じディレクトリに混在する両者を同じ手つきで書いてしまう。

KEDB 照合（`ツール` / `出力` / `生成`、`fixture` / `evals` / `手書き`）では
`.kaizen/2026-08-30-new-state-branches-need-fixtures.md`（applied）が最も近いが、あちらは
**前提が足りず対象分岐へ到達しない**話。こちらは**前提は揃って見えるのに内容がツールの契約に反する**話で、
欠落ではないため前段ゲートの検査では見つからない。

横断スコープ: `skills/*/evals/fixtures/` には決定論ツールが書く形の成果物が他にもある。
`component-coverage.json` の `conformance`（`coverage-expand.mjs` が `--write` で書き戻す）と、
特性照合の結果がこれに当たる。スキル（LLM）が書く `metadata.json` / `diff.md` 等は対象外。

## 提案

eval fixture に置くデータのうち、同梱の決定論ツールが生成するものは手書きせず、そのツールを実行して得た出力をそのまま置く。

- 出自で分ける。**決定論ツールが書く成果物**（`axis-diff.mjs` の `axes.json`、`coverage-expand.mjs` が書き戻す
  `conformance`、特性照合の出力）は生成する。**スキル（LLM）が書く成果物**（`metadata.json`・`porting.md` 等）は手書きでよい
- 生成した出力を要約・省略して置き換えない。件数や一部だけを書くと、ツールの契約に反する組み合わせが混ざる
  （値が割れない軸を `variable` に置く等）。要約が要るなら別ファイルに書き、成果物そのものは実出力を置く
- fixture を作った時点で、そのツールに 1 回通して exit code と主要な件数が一致することを確かめる
- 同じ fixture 内の他ファイル（宣言値を持つ `metadata.json` 等）とも突き合わせ、件数・状態集合を揃える
