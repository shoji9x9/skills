# 実行中のセッションの Hook を変異の対象にすると、その間の Bash が変異した Hook で判定される

## 事象

PR #585 で `bash-command-guard.mutations.json` をバックグラウンドで全件実行している間に、レビューへの返信を quoted heredoc（python3 が読む）で書こうとした。
このスクリプトはこのセッション自身の PreToolUse の Hook でもあり、変異した版（ヒアドキュメントの読み飛ばしを無効にしたもの等）が本文をコードとして読み、呼び出しを誤って止めた。
逆向きの変異なら、止めるべき呼び出しを通していた。

## 根本原因

- なぜ誤って止まったか → Hook が作業ツリーのファイルをそのまま起動し、そのファイルに変異が入っていた
  - なぜその間に Bash を使ったか → 09-28 の規約は「対象を編集しない・コピーしない」で、対象を実行する処理を挙げていない
    - なぜ挙げていないか → 書き手と読み手だけを軸にし、「自分のセッションが自動で実行するもの（Hook）」を対称な反対側として当てなかった ← 根本原因

KEDB: 2026-09-28-mutation-proof-owns-worktree（applied）の新しい形。

## 提案

Hook として登録しているスクリプト（`.claude/settings.json` 等が起動するもの）を対象にする変異は、別の worktree で実行する。

- 仕組みにするなら: ランナーが、変異の対象がエージェントの Hook の設定に現れるパスなら、共有の作業ツリーでは警告する
- 文書: docs/tooling.md の「実行中は編集・コピーしない」に「Hook として実行されるものも同じ」を足す
