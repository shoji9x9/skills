# 存在を確かめていないパスの ls を、探索用の複合コマンドの末尾に置かない

## 事象

モデル指定の置き場を探す探索コマンドで、`git grep ...; echo ---; sed ...; ls ~/.claude/agents` のように、
実在を確かめていないディレクトリへの `ls` を最後に置いた。ディレクトリが無かったため呼び出し全体が exit 2 になり、
探索自体は成功していたのにツールエラーとして記録された（kaizen のコミット前ゲートが候補として拾い、commit が止まった）。

## 根本原因

- なぜ exit 2 になったか: 終了コードを決める末尾に、存在が環境で変わるパスへの `ls` を置いた
- なぜ置いたか: 「ついでに有無も見る」確認を探索の後ろに足し、確認の失敗が呼び出し全体の失敗になることを考えなかった
- なぜ規約があるのに再発したか: AGENTS.md「判定結果として期待される非 0 を…漏らさない」に同じ形（存在が実行構成で変わる成果物の確認）が書かれているが、
  散文の規約で、探索用の使い捨てコマンドを組む時点では想起されない

## 提案

有無を確かめる目的の `ls` / `cat` は `[ -d <path> ] && ls <path>` か `ls <path> 2>/dev/null || echo "<path>: 無し"` の形で書き、有無そのものを出力にする。

- 既存の AGENTS.md の規約で足りるかを、再発が続くか見てから判断する（2 回目の再発で `bash-command-guard.sh` 等の仕組み化を検討）
