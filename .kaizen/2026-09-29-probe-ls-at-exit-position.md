# 存在を確かめていないパスの ls を、探索用の複合コマンドの末尾に置かない

## 事象

モデル指定の置き場を探す探索コマンドで、`git grep ...; echo ---; sed ...; ls ~/.claude/agents` のように、
実在を確かめていないディレクトリへの `ls` を最後に置いた。ディレクトリが無かったため呼び出し全体が exit 2 になり、
探索自体は成功していたのにツールエラーとして記録された（kaizen のコミット前ゲートが候補として拾い、commit が止まった）。

### 追記（2026-09-30・再発）

eval の assertion 差し替えで `...; node check-eval-reachability.js >/dev/null && echo reach-ok; [ -e tests/.../iteration-12 ] && echo EXISTS` と、
未作成であるはずのディレクトリの存在確認を末尾に置いた。無いのが正常なので `[ -e ]` が偽で exit 1 になり、
処理は全部成功していたのにツールエラーとして記録され、コミット前ゲートが候補として拾った。
下の提案に書いた形 `[ -d <path> ] && ls <path>` 自体が、同じ故障（無ければ非 0）を持っていた。

## 根本原因

- なぜ exit 2 になったか: 終了コードを決める末尾に、存在が環境で変わるパスへの `ls` を置いた
- なぜ置いたか: 「ついでに有無も見る」確認を探索の後ろに足し、確認の失敗が呼び出し全体の失敗になることを考えなかった
- なぜ規約があるのに再発したか: AGENTS.md「判定結果として期待される非 0 を…漏らさない」に同じ形（存在が実行構成で変わる成果物の確認）が書かれているが、
  散文の規約で、探索用の使い捨てコマンドを組む時点では想起されない

- 再発（2026-09-30）でなぜ書いたか: 前回の提案が `[ -d <path> ] && ls <path>` を推奨しており、記録した対策が故障を再生産した。
  提案の形を記録時に実行して終了コードを確かめていなかった

## 提案

有無の確認は `if [ -e <path> ]; then echo "<path>: 在る"; else echo "<path>: 無し"; fi` の形で書き、有無を出力にして終了コードを 0 に保つ（`[ ] && cmd` を呼び出しの末尾に置かない）。

- 2 回目の再発なので、`bash-command-guard.sh` 等で呼び出し末尾の `[ ... ] && ...` を検出する仕組み化を apply で検討する
- 旧提案の `[ -d <path> ] && ls <path>` は同じ故障を持つので使わない

## 追記（2026-10-05）

AGENTS.md の「判定結果として期待される非 0 を…漏らさない」は Issue #372 で `docs/agent-workflow.md`「原則」へ移した。
文章の書き換えで、この原則は `docs/agent-workflow.md`「結果として期待される 0 以外の終了コードを、呼び出し全体の終了コードにしない」の節になった。
AGENTS.md「シェルの書き方」には要約（「結果として期待される 0 以外の終了コード」）だけがある。
