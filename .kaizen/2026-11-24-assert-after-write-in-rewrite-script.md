# 書き換えのスクリプトが、確かめの assert より先にファイルへ書き込んだ

## 事象

Issue #1134 の作業で、テストのファイルの 2 つのテストを関数にまとめる python のスクリプトを書いた。
スクリプトは、行の範囲を切り出して組み直した内容をファイルへ書き込んでから、元の CLI のスタブの本文が残っているかを assert で確かめた。
assert は、切り出す範囲を 1 行多く取っていたので失敗したが、ファイルはもう書き換わっていた。
書き換わった内容を git diff と grep で読み直し、スタブの本文が変わっていないことを確かめてから進んだ。

## 根本原因

1. なぜ失敗した assert の後にファイルが変わっていたか → 書き込みの後に assert を置いた。
2. なぜ後に置いたか → 確かめたいのは書き込む内容（組み直した文字列）だったが、書き込みと確かめを同じ変数で続けて書き、順序を意識しなかった。
3. なぜ順序を決める手がかりが無かったか → `AGENTS.md`「編集」の規約は、置換ごとに書き戻して assert にどの置換かを書くことを求めるが、assert を書き込みより前に置くことは書いていない。行の範囲を組み直す書き換え（置換でない形）も対象に挙げていない ← 根本原因

## 根拠

確信度の理由: 1 回の観測で、原因は assert の位置の 1 つに絞れている。
スクリプトは exit 1 で止まったが、その前の open().write() でファイルを書き換えていた。直後の git diff で書き換えを確かめた。
KEDB 照合（「assert」「python」「書き戻」、「置換」「assert」）は、整形の後の置換元の不一致の学び（2026-10-14-patch-script-after-format-recurred.md など）に当たった。
そちらは置換元の出所の問題で、今回の原因（確かめと書き込みの順序）とは違う。

## 既存の規約

- 扱い: 埋もれている
- 場所: `AGENTS.md`「編集」の「複数の置換をまとめたスクリプトは、置換ごとにファイルへ書き戻し、`assert` にどの置換かを書く」
- 照合した範囲: `AGENTS.md`・`docs/`・`.agents/rules/` を「assert」で検索し、置換と書き込みに触れる行を読んだ

## 食い違い

- 相手: なし
- 判断: なし

## 提案

ファイルを書き換えるスクリプトの確かめ（assert）は、書き込む内容に対して書き込みより前に置き、失敗したら何も書かずに止まる形にする。

- 適用先の候補: `AGENTS.md`「編集」の置換の箇条に「assert は書き込みより前に置く。行の範囲を組み直す書き換えも同じ」を足す。
