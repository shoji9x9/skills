# 同じファイルへのすべてのパスを対象にし、「できない」は代わりの形を試してから述べる

## 事象

Issue #564 で tsconfig の対象を `skills/*/assets` だけにした。
利用者が `.agents/skills/` のコピーを開くとエラーが出て、報告を受けて直した。
次に `.claude/skills/` のリンクを同じプロジェクトの include に足して効果が無かった 1 回で「制限」と報告した。
別のプロジェクトにすれば解決でき、利用者が 2 度目の報告をすることになった。
その前にも「相対パスの import は消せない」と試さずに述べ、試して訂正している。

## 根本原因

- なぜ利用者が先に見つけたか: 検証を git の原本のパスだけで行い、利用者が実際に開くパスを挙げなかった
- なぜ挙げなかったか: このリポジトリでは同じファイルが原本・インストール済みのコピー・シンボリックリンクの 3 つのパスで届くが、対象を決めるときにそれを入力の状態として列挙する手順が無い
- なぜ「制限」と報告したか: 1 つの形で失敗したことを「仕組みとしてできない」と一般化し、失敗の条件（同じプロジェクトの中の重複）を外した形を試さなかった

## 提案

ファイルを対象にする設定・検査を書くときは、同じファイルに届くすべてのパス（原本・インストール済みのコピー・シンボリックリンク）を列挙して実測し、「できない」と述べる前に失敗の条件を外した代わりの形を 1 つ以上試す。

- 適用先の候補: docs/agent-workflow.md「新しく作った分岐と、新しく受け付ける入力」の節に、このリポジトリの 3 つのパスを入力の軸として足す
- 「できない」の報告には、試した形と失敗の条件を添える
