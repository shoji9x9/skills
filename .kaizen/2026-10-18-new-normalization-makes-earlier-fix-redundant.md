# 比べる前に値を書き換える処理を足すときは、同じ値を守るために先に入れた修正（エイリアスのための浅いコピーなど）への影響を、ミューテーションテストの前に確かめる

## 事象

PR #692（#651）で、エイリアスの metadata を守るために metadata を浅くコピーする修正を入れた。
その後のレビューの対応で、負のゼロを 0 にそろえる処理を前に足した。最初の形は、マッピングをコピーして返した。
負のゼロの処理がマッピングをコピーしたので、metadata の浅いコピーが要らなくなり、浅いコピーを無効にする変異がどのテストも落とさなくなった。ミューテーションテストが FAIL になってから、それに気づいた。
次のレビューで、コピーする形が自分自身を参照するエイリアスで止まらないと分かり、その場で書き換える形に変えた。その形では metadata の浅いコピーが再び要るので、浅いコピーを戻した。
テストと変異の定義を 3 回書き直した。

## 根本原因

1. なぜ変異が FAIL になったか → 浅いコピーの前に、新しい処理がマッピングをコピーしていた。
2. なぜ気づかなかったか → 新しい処理を足すときに、同じ値（metadata のマッピング）を守るために先に入れた浅いコピーとの関係を見なかった。
3. なぜ見なかったか → 値を書き換える処理を足す修正を、比べる値の 1 つの軸（数値）だけの変更として扱い、値の同一性（コピーか参照か）の軸を挙げなかった ← 根本原因

## 提案

比べる前に値を書き換える処理（コピーして返す・その場で書き換える）を足すときは、同じ値を守るために先に入れた修正とその変異を挙げ、新しい処理でその修正が不要になるか、再び要るかをミューテーションテストの前に確かめる。

- 反映先の候補: `.agents/rules/state-space-and-mutation-proof.md` の §6 に、修正で新しく生じる状態として「先に入れた修正が不要になる・再び要る」を足す。
- KEDB 照合: 該当なし。
