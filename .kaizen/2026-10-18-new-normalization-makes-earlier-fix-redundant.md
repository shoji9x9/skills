# 正規化の段を足したら、同じ値を扱う別の修正のうち、先に入れたものが、その段で不要にならないかを、ミューテーションテストの前に確かめる

## 事象

PR #692（#651）で、エイリアスの metadata を守るために metadata を浅くコピーする修正を入れた。
その後のレビューの対応で、負のゼロを 0 にそろえる段（マッピングをコピーして返す）を前に足した。
浅いコピーを無効にする変異がどのテストも落とさなくなり、ミューテーションテストが FAIL になってから、浅いコピーが不要になったことに気づいた。
テストと変異の定義を 2 回書き直した。

## 根本原因

1. なぜ変異が FAIL になったか → 浅いコピーの前に、新しい段がマッピングをコピーしていた。
2. なぜ気づかなかったか → 新しい段を足すときに、同じ値（metadata のマッピング）を扱う別の修正のうち、先に入れたものとの関係を見なかった。
3. なぜ見なかったか → 正規化の段を足す修正を、比べる値の 1 つの軸（数値）だけの変更として扱い、値の同一性（コピーか参照か）の軸を挙げなかった ← 根本原因

## 提案

正規化の段（値をコピーする・書き換える処理）を足したら、同じ値を扱う別の修正のうち先に入れたものと、その変異を挙げ、新しい段でその修正が不要にならないかをミューテーションテストの前に確かめる。

- 反映先の候補: `.agents/rules/state-space-and-mutation-proof.md` の §6 に、修正で新しく生じる状態として「前の修正が不要になる」を足す。
- KEDB 照合: 該当なし。
