# 期待値の集合は宣言から作る（実測の一覧から作らない）

## 事象

`capture-scope-check.mjs` は「撮るはずの組」の期待値を `noise_baseline`（＝**実際に採った組の一覧**）から作っていた。
そのため、ページ × 状態 × ビューポートの組を**丸ごと採らなかった**場合、その組は期待値からも消え、
穴が 1 件も出ないまま exit 0 になった。検査の目的（範囲の狭さを差分 0 件と区別する）がその入力クラスで無効になる。

同じ巡で見つかった他の 3 件も同型の fail-open だった——任意引数（`--replace-metadata`）を省くと鮮度の照合が
一度も評価されない、空文字の入力を未指定へ丸めると節ごと検査が飛ぶ、様式に書かせた項目（`dirty`）を読んでいない。

## 根本原因

- なぜ穴が出なかった? → 期待値と実測が**同じ入力**から作られていた
  - なぜ同じ入力にした? → 突き合わせの相手として一覧が手近にあり、「採った組ごとに実測が要る」だけを見ていた
    - なぜそれで足りると思った? → **検査の対象（記録の不足）と、検査が答える問い（範囲に穴が無いか）を区別していない** ← 根本原因

KEDB 照合: [[2026-09-16-eval-expectation-must-be-derived-from-input]] は eval の期待値を入力から導出する話で、
「期待値の出所」という軸は同じだが、こちらは**検査器の期待集合が観測側に依存すると欠落が自己隠蔽する**という機序。
[[2026-09-08-overdetection-fix-is-itself-a-relaxation]] は緩和経路の話で、任意引数・空文字の丸めはそちらに属する。

## 提案

集合を突き合わせる検査は、期待集合を**観測の記録ではなく宣言（仕様・設定・条件）から**構成する。

- 期待集合の出所を 1 行で書けるか確かめる。「観測した一覧」と書けてしまうなら、その検査は欠落を検出できない
- 宣言から期待集合を作れない入力（軸が空・区切り文字入り・重複）は合格に倒さず落とす
- 期待集合に対する不足は、他の欠陥と同じ出口（理由付きの免除宣言）へ流す——専用の抜け道を足さない
- 同じ変更で「任意にした引数」「未指定へ丸めた入力」「様式に書かせたが読んでいない項目」も点検する。
  いずれも判定の一部を評価しないまま収束させる同型の穴になる
