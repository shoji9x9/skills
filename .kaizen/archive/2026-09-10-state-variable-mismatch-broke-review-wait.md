# 状態変数を検証せず待機ループの比較へ渡さない

## 事象

PR レビュー待機で件数を `current_count` に代入した後、数値比較では未定義の `current_reviews` を参照した。空値の数値比較が 3 回繰り返され、レビュー待機ではなく shell ラッパー自身がエラーになった。

## 根本原因

1. なぜ数値比較が失敗したか → 代入名と異なる未定義変数を参照した。
2. なぜ 3 回繰り返したか → ループへ入る前に値の非空・数値検証を行わず、同じ誤った比較を反復した。
3. なぜループが必要になったか → 単発取得後に呼び出し側で状態を判断できるのに、shell 内へ取得・判定・待機をまとめて複雑化した。

KEDB では、終了コードを誤ってツールエラーへ返す同日事例はあったが、状態変数の代入・参照不一致による待機ループ失敗は別の再発経路だった。横断すると、CI・レビュー・プロセス監視など、件数や状態を shell 変数へ格納して反復する全コマンドに同じ原因がある。

## 提案

状態変数は比較前に非空・期待型を検証し、代入名と参照名を同じ短いブロックで一致確認する。単発取得で足りる確認を shell ループへ広げず、呼び出し側で待機継続を判断する。

基底ドキュメントの終了コード規律へ適用した。
