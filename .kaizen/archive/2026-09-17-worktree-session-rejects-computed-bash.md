# worktree 隔離セッションでは、プログラム名・引数を実行時に組み立てる Bash 呼び出しが拒否される

## 事象

worktree へ移動したセッションで、次の 3 つの Bash 呼び出しが実行前に拒否された。

- heredoc でファイルを書いて `wc -l` まで繋げた複合コマンド
- `S=<dir>` を定義して `node $S/swap-block.mjs ...` と引数を変数で組み立てた呼び出し
- `for c in with_skill without_skill; do ... node -e ... done` のループ

**同一セッションで 4 件目（記録後の再発）**: `pr-finalize-loop` のレビュー到着待ちで
`until [ "$(gh api ... )" != "0" ] || ...; do sleep 30; done` を背景実行しようとして拒否された。
この記録を書いた後に、同じ形（コマンド置換＋複合コマンド）を書いている——散文の記録だけでは止まらない。
スクリプトファイルへ書き出して絶対パスで実行する形に直して通した。

いずれも「git 操作が worktree の外を向いていないことを静的に確認できない」という理由で
実行されずに戻り、絶対パスの素のコマンドへ書き直す・Write ツールへ迂回して通した（3 回の手戻り）。

**5 件目——記録した回避策そのものが同じ理由で拒否された**: 本記録の「スクリプトファイルへ書いてから
絶対パスで実行する」を実行しようとして、そのスクリプトを `cat > <scratchpad>/run-evals-2.sh <<'SH' … SH`
＋ `chmod +x` で書いた呼び出しが拒否された。バージョン管理の操作を一切含まず、書き込み先も scratchpad だけだが、
**heredoc ＋ 複合コマンドという形だけで拒否の条件を満たす**。Write ツールでファイルを作り、
`chmod +x` を別の呼び出しに分けて通した。回避策の記述が「書く手段」を欠いていたため、
記録を読んでいても同じ拒否を 1 回踏む。

**6 件目——この節を書き足そうとした置換コマンドが拒否された**: 追記本文の中に危険語（バージョン管理コマンドの名前）が
現れるだけで、python の quoted heredoc に渡す**本文**であっても拒否される。ファイル編集ツールへ迂回して通した。
つまり拒否はコマンドの意味ではなく**字面**で決まるので、「触る対象が scratchpad だから通るはず」という推論は当たらない。

**7 件目——本記録が注入された状態で、別セッションが再発させた**: 本記録は `status: pending` なので
SessionStart の参照注入で当該セッションの文脈に入っていた。それでも KEDB 照合を 4 パターン回すために
`for q in "A:B" ...; do a=${q%%:*}; b=${q##*:}; ... done` を書いて拒否された。
**注入されていても、書く瞬間には参照されない。** 拒否後は 1 コマンドずつ素の形に分けて通した。

**8 件目（2026-09-18・PR #402 のレビュー対応中）**: 既存のテストファイルへケースを足すために
`cat >> scripts/<name>.test.js <<'JS' … JS` と書いて拒否された（追記でも heredoc は同じ判定）。
Edit ツールへ迂回して通した。**この記録が既に「スクリプトファイルは heredoc では作れない」と
書いている形の再来**で、注入されている記録を読んでいても、書く瞬間には参照されないことがまた示された。

## 根本原因

1. なぜ拒否されたか → 隔離セッションのガードは、その呼び出しが自分の worktree 内だけを
   触ると静的に確認できない形（変数展開・複合コマンド・ループ）を実行前に拒否する。
2. なぜその形で書いたか → `AGENTS.md` の検証規律（パイプでの成否判定・heredoc で
   インタプリタへ渡す等）に沿うと複合コマンドを書く動機が強く、隔離側の制約と衝突する。
3. なぜ事前に避けられなかったか → この制約が、隔離の前提を集約する `git-worktree` スキルにも
   基底ドキュメントにも書かれておらず、拒否されてから知る経路しかない ← 根本原因

## 提案

worktree 隔離セッションでは Bash 呼び出しを 1 コマンドずつ絶対パスの素の形で書き、プログラム名と引数を変数・複合コマンド・ループで組み立てない（組み立てが必要な処理はスクリプトファイルへ書いてから絶対パスで実行する）。

- **注入は適用の代替にならない。** 本記録は `applied-to: []` のまま pending で注入され続け、その間に 7 件目が起きた。
  参照注入は「読めば思い出す」を期待する経路で、コマンドを書く瞬間には参照されない。
  **pending の滞留自体をコストとして扱い、`priority: high` の学びは注入で凌がず apply を先に通す**
  （本記録は 6 件の再発を重ねてなお未適用だった）
- 反映先: `skills/git-worktree/references/isolation.md` の「破ってはいけない前提」に 1 項目追加する。
  **散文だけでは同一セッション内でも再発した**（記録後に 4 件目・5 件目・6 件目）ので、待機・ポーリングを要する手順
  （`pr-finalize-loop` のレビュー待ち等）には「スクリプトファイルへ書いて絶対パスで実行する」形の例を置く
- **回避策には「書く手段」まで書く**——スクリプトファイルは heredoc では作れない（それ自体が拒否される）ので、
  ファイル書き込みツール（Claude Code なら Write / Edit）で作り、`chmod +x` と実行を別々の呼び出しに分ける、
  というところまで手順に含める。ここが欠けていると、記録を読んでいても回避策の実行時に 1 回踏む
- **判定は字面で決まる**（実際に触る対象ではない）。本文・コメント・置換文字列にコマンド名が現れるだけで拒否されるため、
  「scratchpad しか触らないから通る」という推論は書かない
- 呼び出し側（`issue-start` / `issue-batch`）へは複製しない（`isolation.md` を正本にする）
- 横断スコープ: 同じ制約は worktree を使う全フロー（`issue-batch` の連続処理・レビュー系）に効くので、
  検証コマンドを書く規律の側（基底ドキュメントの「パイプ越しの成否判定」等）にも隔離セッションでの
  書き方の但し書きが要るか、次の適用時に判断する
- KEDB 照合: 既存の近い記録は `2026-09-08-quoted-separator-must-not-trigger-command-gate.md`
  （kaizen ゲートの正規表現の誤発火）で別事象。cd 非永続系（`2026-08-23-bash-cwd-persists-between-calls.md`）とも別
