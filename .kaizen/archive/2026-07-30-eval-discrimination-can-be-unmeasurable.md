# 事象の事実が結論を含む eval は、cue を消しても弁別しない——測れないと結論して検査項目を替える

## 事象

Issue #143 で `kaizen` の適用先表に「機構」行を足し、その効果を測る eval 9 を追加した。
3 iteration 回して、狙った項目（「散文ではなく機構を第一候補にする」「判定法を根拠に述べる」）の
弁別は**一度もゼロを脱しなかった**（with 3/3・without 3/3 が 3 iteration 連続）。

- iteration-4: fixture の根本原因欄に「対策が手順の記述で終わっていた」と書いており、ベースラインが
  それを引用して正答した（既知の失敗形＝入力が答えを持っている）
- iteration-5: その cue を除去してドメイン層の why 連鎖に差し替えたが、弁別は回復しなかった。
  ベースライン 3 run は事象欄の「5 回とも同一のラッパーを組み立て直した」から独自の言葉で到達した
  （「実体の欠落」「決定論的で反復される手順は実行可能な成果物にすべき」「判断の余地がないのに人間が毎回介在」）
- iteration-6: 両 configuration を同一サンドボックスに入れても同じ（弁別ゼロのまま）

一方、skill 固有の手順を検査する項目（`grep -l "^status: pending"` の取りこぼし確認、Step 5 の
「ブランチ継続 or Issue 作成」の二択）は with 3/3・without 0/3 で明確に弁別した。

## 根本原因

- なぜ弁別しなかったか? → 結論（機構に落とす）が、fixture の cue ではなく**事象の事実そのもの**から導ける
  - なぜ事実から導けるか? → 「5 回とも同一の成果物を人が手で再現した」は、十分に強いモデルには
    「コード化すべき」と読める。この事実は学びの成立に不可欠で、fixture から削れない
    - なぜそこで測り続けたか? → 「弁別しない ＝ fixture に cue がある」と 1 つの原因に決め打ちし、
      **「その主張はこの eval では原理的に測れない」という結論を選択肢に持っていなかった** ← 根本原因

KEDB 照合: [[2026-07-23-eval-assertion-discrimination]]（applied）が挙げる 4 つの「測れない形」に、
**5 つ目＝入力から結論が演繹できる**が加わる。既存 4 点は入力の書き方で直せるが、これは直せない。

横断スコープ: 「一般に賢いモデルなら到達できる判断」をスキルで規定した場合すべて。
規定の価値は Delta ではなく判断の一貫性と後退検知にある、と benchmark に明記して次の iteration に持ち越す。

## 提案（適用済み）

弁別ゼロが cue の除去後も続いたら、fixture をさらに削るのではなく**その項目はこの eval では測れない**と
結論し、検査項目を skill 固有の手順・語彙・成果物へ替える。測れない項目を残すなら、Delta ではなく
「後退検知」の目的であることを benchmark に明記する。

`.agents/rules/eval-assertion-discrimination.md` に追記済み（`paths: skills/*/evals/**`）。
実測の経緯は `tests/kaizen/iteration-{4,5,6}/benchmark.md` の notes に残した。
