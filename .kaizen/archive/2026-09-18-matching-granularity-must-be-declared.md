# 照合・鍵は「粒度」を先に決める（部分文字列・連結は黙って潰れる）

## 事象

PR #402 の 1 巡目の指摘を直した同じ変更の中で、**同じクラスの穴を 2 件残していた**。

- 1 巡目: 「絞り込みが複数並ぶと述語 1 本で全部を満たす」を修正したが、照合を `includes(column)`
  （部分文字列）で書いたため、2 巡目で `owner_id` の述語が列 `id` を満たすと指摘された
- 同じ PR で新設した撮影組の鍵も、`<page>|<state>|<viewport>` の連結なのに材料側で
  区切り文字を禁じておらず、別の組が同じ鍵へ潰れると指摘された

どちらも「一致した」の単位（識別子か文字列か、組か連結された文字列か）を決めずに書いており、
失敗するときは例外ではなく**黙って合格側へ潰れる**。

## 根本原因

- なぜ残った? → 指摘を「報告されたインスタンス」で直し、故障クラス（照合の粒度）へ一般化して
  自分の新規コードを掛け直さなかった（[[state-space-and-mutation-proof]] の
  「レビュー指摘は故障クラスとして掃き出す」の未実施）
  - なぜ一般化しなかった? → 照合・鍵の実装で「粒度を先に決める」という手順が無く、
    書いてからテストで拾う前提になっていた ← 根本原因（対策可能）

KEDB 照合: [[2026-09-01-matching-key-material-state-space]]（`status: applied`）は**鍵の材料の欠落・重複**を扱い、
本件は**材料が揃っていても粒度が粗いと潰れる**形なので別の軸。applied ノートには追記しない。
[[2026-09-08-overdetection-fix-is-itself-a-relaxation]]（`status: pending`）は受理条件の列挙不足で、
これも同じ PR で再発している（そちらへ別途追記済み）。

横断スコープ: 同じ PR で新設した 3 スクリプト（`predicate-coverage-check.mjs` /
`capture-scope-check.mjs` / `component-comparison-check.mjs`）のうち、`component-comparison-check.mjs` の
セル鍵（`component|item|instance`）も同じ連結で作っている。こちらは材料の非空しか見ておらず、
同じ潰れ方をしうる（本 PR の範囲では指摘されていないが、次に触るときに同じ規律を当てる）。

## 提案

照合器・鍵を書く前に「一致の単位」を 1 行宣言し、連結で作る鍵は材料側で区切り文字を禁じる。

- 単位の語彙は識別子 / トークン / 完全一致 / 前方一致。部分文字列を使うなら、**一方が他方の一部になる入力**を境界テストに必ず入れる
- **連結で作る鍵は、材料側で区切り文字を禁じるか構造化する。** 鍵が利用者に見える id になるなら
  符号化ではなく材料側で弾く（符号化すると id が読めなくなる）
- レビュー指摘を直すときは、同じ変更で**自分がその PR で新設したコード**を同じクラスで grep する
  （指摘は 1 インスタンスしか報告しないが、同じ PR の他のファイルに同型が残っていることが多い）
