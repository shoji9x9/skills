# 外部コマンドの分岐は「その分岐が成立する状態」で実測する

## 事象

`gh pr checks --required` を使う手順を dependabot-merge / pr-finalize-loop へ書いた際、
「必須チェックが 0 件のときは行が 0 件になる」と記述した。実際には `gh` は空配列を返さず
`no required checks reported on the '<branch>' branch` を stderr に出して非 0 で終了する
（実測: jqlang/jq#3596・junegunn/fzf#4876 で rc=1、必須チェックのある sharkdp/bat#3860 は rc=0）。
0 件はまさにこの節が扱う force-push 直後の状態であり、エージェントは非 0 終了をコマンド不備と
誤読してループを誤停止しうる。コードレビューの指摘で発覚した。

## 根本原因

- なぜ誤記したか? → `--required` の検証を、必須チェックが**存在する** PR（自リポ #155）でしか
  行わず、0 件の状態を一度も作らなかった。
  - なぜ作らなかったか? → 手元で到達しやすい状態で「フラグが効くこと」を確認した時点で
    検証完了とみなした。`--help` にも 0 件時の振る舞いは書かれていない。
    - なぜそれで完了とみなしたか? → 既存ルール（`external-tool-format-verification`）が求めるのは
      「構造とフィールド意味論を一次情報で検証」であり、**書いた分岐ごとにその状態を再現して
      実測する**ことまでは求めていなかった。正常系を測れば異常系も推測できるという暗黙の
      前提が残っていた。← 根本原因（対策可能）

横断スコープ: skills 内で外部コマンドの「0 件 / 空 / 未登録」分岐を書いているのは
`issue-start`（`--comments` の 0 件、実測済み）と今回の 2 件のみ（grep 確認）。
同じ穴は「エラー時・空結果時にだけ通る分岐」を書くたびに再発しうる。

KEDB 照合: [[2026-06-09-external-tool-config-verify-official-docs]]（構造を一次情報で検証）と
[[2026-07-22-gh-issue-view-comments-only]]（gh の挙動を実測せず記述）はいずれも `applied` で、
今回は**両方の規律を守った上で**なお外した。軸が「一次情報を見たか」ではなく
「**どの状態で測ったか**」のため、既存ルールへの追補として記録する。

## 提案

外部コマンドの**分岐を書いたら、その分岐が成立する状態を実際に作って実測する**。
正常系でフラグやフィールドの存在を確認しただけで、異常系・空結果・未登録の振る舞いを
推測で書かない。状態を自前で作れないときは、その状態を持つ公開リポジトリで実測する。

既存ルール `.agents/rules/external-tool-format-verification.md`（paths: `skills/**`）に
次の箇条書きを追加する（新規ルールは作らない）:

- **分岐を書いたらその分岐が成立する状態で実測する。** 「0 件」「該当なし」「失敗時」の振る舞いは
  `--help` / 公式ドキュメントに書かれないことが多く、正常系の実測から推測すると外れる
  （例: `gh pr checks --required` は必須チェック 0 件のとき空配列ではなく stderr メッセージ＋非 0 終了）。
  自リポジトリで状態を作れないときは、その状態を持つ公開リポジトリで実測する。
