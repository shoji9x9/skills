# レビューの指摘ごとに場合分けの案内を足すと、確かめていない案内が増える

## 事象

PR #666（agent-usage の Hook の stage が、コミットが実行されなくても残る件）で、`SKILL.md` の「コミットの前の確認」の段落が、2 回のレビューで合わせて 15 件の指摘を受けた。
1 回目の指摘に合わせて、ブランチを移る場合（`git restore --staged` で戻す）と、パスを指定してコミットする場合の案内を足した。
2 回目のレビューは、使い捨てのリポジトリで git を実行して、案内どおりでは解決しない形を 2 つ示した。

- 明細がこのブランチで既にコミットされていると、`git switch` は拒否され、stage を戻しても移れない
- まだコミットしていない明細を戻すと、ファイルは untracked のまま残り、移った先が「記録する」ブランチならその Hook が stage し直す

場合ごとの案内をやめ、コミットの後に `git status` で確かめる 1 つの手順にまとめた。
まとめた手順のコマンドも確かめずに書いたので、3 回目のレビューで 2 件の誤りが見つかった。
相対パスはサブディレクトリから実行すると何も表示せず、`status.showUntrackedFiles=no` の設定では untracked の明細が隠れる。
直した後のコマンドは `git status --short --untracked-files=all -- ':/.agent-usage/records'` で、使い捨てのリポジトリで両方の場合を確かめた。

## 根本原因

- なぜ案内が誤っていたか → 足した案内を、git で実行して確かめていなかった
  - なぜ確かめなかったか → 指摘の文面に合わせて、その場合だけの案内を書き足した
    - なぜその形にしたか → 場合を挙げるほど、git の振る舞い（追跡の有無・Hook の再 stage・switch の拒否）の組み合わせが増える。それを数えずに、指摘を 1 件ずつ閉じることを優先した ← 根本原因
- 関連: `2026-10-08-doc-describes-check-from-one-branch`（文書に挙動を書く前に、分岐と副作用を挙げる）

## 提案

文書で利用者に操作を案内するときは、場合ごとの案内を足す前に、結果を確かめる 1 つの手順（コマンドの出力で判定する形）で全部の場合を扱えないかを先に考え、足す案内は使い捨ての環境で実行して確かめてから書く。

- 適用先の候補: `docs/skill-development.md`「push 前の整合パス」に 1 項目足す
