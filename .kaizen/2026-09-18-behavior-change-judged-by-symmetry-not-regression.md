# 自分の変更が持ち込んだ退行を、他コンポーネントとの「対称性」を根拠に据え置いた

## 事象

PR #400（Issue #377）で claude-code の raw trace を `--output-format json` から
`stream-json --verbose` へ変えた。レビュー（`/code-review`）が
「汚染スキャンがマーカーを `raw/` 全文に grep するので、走査面が中間メッセージまで広がる」と指摘し、
仕様判断が要るとして修正を保留した。

**私は「変更しない」と判断した。** 根拠は次の 2 点で、どちらもユーザーへの報告に書いた。

- codex の `raw/` は元から `agent_message` を全件含んでおり、走査対象だった。今回の変更は非対称の解消にすぎない
- マーカー設計（ディレクトリ固定・プロンプト／fixture／姉妹スキルの減算）はその表面を前提に調整済み

**4 巡後の codex レビューが、この形を実際に再現した** —— 唯一のツール呼び出しが
`echo references/oauth-setup.md` の baseline が `CONTAMINATED`（exit 4）になり、正当な測定が捨てられる。
**私の変更以前は起きなかった**（変更前の `raw/claude-code.json` は最終結果オブジェクトだけで、`result.json` と同じ本文だった）。
claude-code の `raw/` を走査対象から外して修正した。

## 根本原因

1. なぜ据え置いたか → 新しい挙動が**それ自体として弁護できるか**（他コンポーネントと揃っているか）で判断した。
2. なぜその問いを立てたか → レビューの指摘が「走査面が広がる」という**構造の記述**だったので、
   構造の妥当性を論じて答えた。**「以前通っていた入力が落ちるか」へ翻訳しなかった。**
3. なぜ翻訳しなかったか → 変更の可否を測る問いが「新しい挙動は妥当か」に寄っており、
   **退行（以前の合格が不合格になる）を独立の判定軸として持っていなかった** ← 根本原因（対策可能）

**対称性は退行を許す理由にならない。** 「B は前からそうだった」は、A を新たに壊してよい根拠ではない。

## KEDB 照合

`退行` / `判断` で照合し [[2026-08-30-new-state-branches-need-fixtures]]（`applied`）のみ一致。
あちらは新設分岐に fixture を用意する話で、本件は**判断の軸**なので別。
`AGENTS.md` には「『常に壊れる／失敗する』系のレビュー指摘は、適用前に使い捨て環境で再現テストして裏取りする」があるが、
**これは指摘を採用する前の裏取り**を定めるもので、**指摘を却下する前の裏取り**を求めていない。本件は却下側で踏んだ。

横断スコープ: 同じ形は「レビュー指摘を仕様判断として保留・却下する」全ての場面。
とくに fail-closed なゲート・安全弁の表面を変える変更は、通っていた入力が落ちる向きに倒れやすい。

## 提案

レビュー指摘を却下・保留するときは、却下の理由を書く前に「この変更で、以前通っていた入力が落ちるか」を実際に作って確かめる。

- 反映先: `AGENTS.md` の検証規律にある「『常に壊れる／失敗する』系のレビュー指摘は、適用前に使い捨て環境で
  再現テストして裏取りする」の項へ、**却下側にも同じ裏取りを要求する**一文を足す
- 文面の骨子: **指摘を採用するときだけでなく、却下・保留するときも再現を試みる。**
  「新しい挙動が妥当か」ではなく **「以前通っていた入力が落ちるか」** を問いにする
- **他コンポーネントとの対称性を、退行を許す理由にしない。** 「B は前からそうだった」は
  A を新たに壊してよい根拠ではない。対称性は設計の一貫性の話で、退行の有無とは別の軸
- 保留すると決めた場合も、**その形を再現するテストだけは同じ変更に入れる**（次に踏んだ人が原因へ即到達できる）
