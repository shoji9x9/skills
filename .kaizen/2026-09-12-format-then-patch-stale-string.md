# 整形を挟んだ後の置換は、記憶ではなく現在の中身から取る

## 事象

`oxfmt` を通したスクリプトに対し、整形前に自分が書いた文字列を置換元にして `python` で patch しようとし、
`AssertionError` で 2 回落ちた。整形で行が折り返され、引用符と空白が変わっていたため一致しない。

## 根本原因

1. なぜ一致しなかったか → 置換元を記憶（自分が書いた形）から組み立てたから。
2. なぜ記憶から組み立てたか → 直前に自分で書いたファイルなので、中身を知っているつもりだった。
3. なぜ気づけなかったか → 既存の規律が「Edit の `old_string`」に限定して書かれており、
   スクリプト経由の置換と、整形を挟んだ場合が射程に入っていなかった。

KEDB 照合（`old_string` / `Edit` / `一致`）で `.kaizen/2026-08-28-edit-tool-old-string-must-be-copied-verbatim.md`
（applied、反映先 AGENTS.md）がヒット。同じ根本原因の再発で、経路（スクリプト）と誘因（整形）が違うだけ。

## 提案

文字列一致で編集するときは、置換元を直前に読んだ現在の中身から一字一句コピーする（Edit でもスクリプト経由でも同じ）。

フォーマッタを通した後は特に効く。自分が書いた文字列は整形で折り返し・引用符・空白が変わっているため、
記憶から組み立てた置換元は一致しない。整形を挟んだら置換前に読み直す。

反映先: `AGENTS.md` の該当項目を「Edit の old_string」からスクリプト経由を含む形へ広げ、整形後の注意を追記済み。
