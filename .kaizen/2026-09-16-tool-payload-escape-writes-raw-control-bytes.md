# ツール引数に書いた制御文字のエスケープは生バイトとしてファイルに入り、テキストファイルが黙ってバイナリになる

## 事象

`skills/replace-strategy/scripts/asset-probe.mjs` を Write ツールで作成した際、Map のキー区切りとして
ソースに `"\u0000"` と書いたつもりが、ファイルには生の NUL バイト（3 箇所）が書き込まれた。

- oxfmt・oxlint・`node --check` はすべて通り、ブラウザでの動作確認も成功した
- `git diff --no-index --numstat` が `-` `-`（バイナリ扱い）を返し、`grep -c 'u0000'` が 0 件を返したことで初めて気付いた
- 気付かずに commit していれば、PR 上で差分が「Binary file」になりレビュー不能になっていた
- 横断確認で NUL を含む追跡対象テキストファイルは 0 件（陽性コントロール付きで確認）。
  ただし最初の走査は `grep -lP '\x00'` で `-a` が無く、陽性コントロールすら検出できていなかった
- **この学びファイル自体でも再発した**: 本文に `"\u0000"` を書いた箇所が生の NUL 2 個・生のタブ 1 個になり、確認 UI の preview でも `\u0000` が置換文字で表示された（手順を知っていても書き手の注意では防げない）

## 根本原因

- なぜ NUL が入った? → ツール引数は JSON 文字列として解釈されるため、本文に書いた `\u0000` がツール層で制御文字に復号され、そのままファイルに書かれた
- なぜ気付けなかった? → フォーマッタ・リンタ・構文検査はいずれも NUL を含むソースを正常に扱い、失敗として現れない
- なぜ仕組みで止まらなかった? → テキストとして扱うべき拡張子のファイルに制御文字（NUL 等）が混入していないかを検査するゲートが pre-commit にも CI にも無い ← 根本原因（対策可能）

## 提案

テキスト拡張子（md / js / mjs / cjs / ts / json / yml / yaml / sh 等）の追跡ファイルに NUL などの制御バイトが無いことを pre-commit と CI で検査し、混入を commit 前に落とす。

- `scripts/` に検査スクリプトを追加し、lefthook pre-commit（ステージ差分）と CI の `Lint` ジョブ（全体）に入れる。
  NUL（`\x00`）を必ず対象にし、タブ・改行・CR 以外の C0 制御文字を含めるかは誤検知の実測で決める
- 検査は `grep` の `-a` 相当でバイナリ扱いを無効化して走査する（`-a` 無しの `grep -lP '\x00'` は陽性コントロールすら拾わなかった）。
  陽性コントロール（NUL を含む一時ファイル）と陰性コントロール（通常のテキスト）の両方をテストに置く
- 書き手側の補助として、ソース中で制御文字が要るときはエスケープを文字列リテラルに書かず、`String.fromCharCode(0)` や `JSON.stringify([a, b])` のキーのように復号されない形で表す旨を、該当する規約（JS 作成時のルール）に 1 行添える
