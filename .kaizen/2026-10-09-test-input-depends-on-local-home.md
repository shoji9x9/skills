# テストの入力に、実行する人の環境にあるパスを使わない

## 事象

PR #585 で、`~` を展開してディレクトリかを見る処理のテストに `pnpm exec oxfmt ~/projects/skills/scripts` を使った。
手元では自分のホームにそのパスがあるので合格し、ミューテーションテストも PASS したが、CI のランナーには無いので Unit tests が失敗した。

## 根本原因

- なぜ失敗したか → テストの入力が、実行する人のホームの中身に依存していた
  - なぜその入力にしたか → レビューが実測に使ったコマンドをそのままテストに転記した
    - なぜ気付かなかったか → 手元の実行とミューテーションテストは同じ環境で動くので、環境に依存する入力を区別できない。
      テストの入力が環境変数やリポジトリの外のパスを読むときの規約が無い ← 根本原因

## 提案

テストが環境変数（`HOME`・`PATH` など）やリポジトリの外のパスを読む処理を測るときは、その値をテストの中で固定し、リポジトリの中か一時ディレクトリを指すようにする。

- 適用先の候補: `.agents/rules/state-space-and-mutation-proof.md` §4（fixture）
- 仕組みにするなら: `scripts/**/*.test.js` の文字列に `~/` や `/home/` で始まるパスがあれば警告する検査
