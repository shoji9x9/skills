# 配布物の探索条件をソースの属性から決めた

## 事象

kaizen の週次ワークフローが同梱スクリプトを探す条件を `[ -x "$dir/kaizen-schedule-report.sh" ]` と書いた。
`gh skill install` が配るコピーは 100644 なのでこの分岐は配布先で必ず外れ、ワークフローは毎週 exit 1 で落ちる。
自リポジトリだけはソース配置（755）も持つため通っており、レビューまで気付けなかった。

## 根本原因

- なぜ 1: 実行ビットの有無を、自分で `chmod +x` したソースファイルの見え方から推定し、検査対象であるインストール済みコピーで確かめなかった
- なぜ 2: 探索条件を「意味」（読めれば足りる）ではなく「手元の見え方」（実行可能に見える）で決めた。陽性コントロールをソース側で取っていた
- なぜ 3: 同梱物の属性・権限が配布でどう変わるかを確かめる規定が無かった。既存ルール `distributed-skill-bundle-artifacts.md` は「同梱せよ」までで、同梱物を**実行時にどう見つけるか**には触れていない ← 根本原因

## 提案

配布物を実行時に探す条件は、ソース側の属性ではなくインストール済みコピーで実測して決める。

- 反映先: `.agents/rules/distributed-skill-bundle-artifacts.md` に 1 項追加する
- `gh skill install` は 100644 で配るので `-x` は必ず外れる。読めれば足りるなら `-r` にし、起動は `bash <path>` にする
- 分岐の陽性コントロールは 644 の installed copy を置いて取る（755 のソースで取った確認は何も実証しない）

## 横断スコープ

`scripts/` 配下の `-x` 4 箇所は非配布ツールが自分で生成する実行ファイルを見ており、同じ欠陥は無い（確認済み）。
