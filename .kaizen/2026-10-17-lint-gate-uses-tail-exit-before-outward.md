# 外向きの操作の前提にする lint は、出力を tail に通した終了コードで判定せず、lint 自身の終了コードを保存してから分岐する

## 事象

Issue #677〜#681 を起票するとき、本文の lint と起票のスクリプトを `lint-prose.ts <files> 2>&1 | tail -2 && bash issues-create.sh` とつないだ。
lint は指摘 1 件で 0 以外を返したが、`&&` が見たのは `tail` の終了コード 0 だったので、指摘が残ったまま 5 件の Issue を起票した。そのうち #678 の本文を、起票した後で直すことになった。

## 根本原因

- なぜ指摘が残ったまま起票されたか → `&&` の左辺の終了コードは、パイプの最後のコマンド（`tail`）のものだった
- なぜ tail に通したか → 出力を短くしたかった。AGENTS.md の「パイプでつないだ検証の成否は `${PIPESTATUS[0]}` か `set -o pipefail` で取る」を、外向きの操作の前提の判定に当てていなかった
- なぜ気づけなかったか → 同じ呼び出しの出力に lint の指摘と起票した URL が並んでいて、起票の後で初めて読んだ

## 提案

外向きの操作（Issue・PR・コメントの作成）の前提にする lint は、出力を tail に通した終了コードで判定せず、lint 自身の終了コードを保存してから分岐する。

- 適用先候補: `AGENTS.md`「外向きの操作と破壊的な操作」の「順序のある外向きの操作は `&&` でつなぐ」に、前段がパイプなら `>out 2>&1; rc=$?` で分けてから判定することを足す
- 起票のスクリプトの中で本文の lint を実行し、0 以外なら起票しない形にする（`issue-create` スキルの起票の手順にも足せるか検討する）
