# チェックの挙動と判断の理由を文書に書く PR で、レビューの指摘に合わせて条件を足し引きし、前の回と逆の修正を求められ続けた

## 事象

issue-batch の #717（PR #790）と #677（PR #791）で、kaizen と agent-usage のコミット前のチェックが止める条件と、`if` を付けるかの理由を setup の文書に書いた。
レビューは毎回、実装と食い違う条件や抜けた場合を挙げた。条件を足すと次の回で「挙げ切る形が実装と合わない」と指摘され、消すと次の回で「消した情報がどこにも無い」と指摘された。
PR #791 では「いずれ要る抽出」を 4 回目で消し、5 回目で「消したので根拠が無くなった」と戻すよう求められた。`defaultDecision` の条件も同じように消してから戻した。
pr-finalize-loop の反復（`/code-review` の effort ごとの回数）は、PR #790 が high 5 回・medium 2 回・low 1 回だった。
PR #791 は high 5 回の後、medium の 1 回目で粒度を PR の本文に書き、それより細かい 5 件を見送った。粒度を書く前の high の回では、消した文を 2 つ戻していた。

再発（PR #822、#659）: `lint:fallow` を 2 つの検査に分けた理由と、ベースラインの扱いを `docs/tooling.md` と `AGENTS.md` に書いた。
high 5 回・medium 2 回のレビューで、理由を足す指摘（1・2 回目）と削る指摘（5 回目）、`AGENTS.md` との重複を消す指摘（4 回目）と要点を `AGENTS.md` に戻す指摘（5 回目）が交互に出た。
終了コードと案内の分岐も、回ごとに細かい組み合わせを指摘され、直す途中で exit 2 を 0 にする誤りを入れかけた（push 前に実測で気付いた）。
粒度を PR の本文に書かないまま局所的に直しており、この学びの提案を適用していなかった。

## 根本原因

文書の一文に、実装のすべての分岐（設定の誤り・締め切り・lifecycle・ラッパー・引用）を正しく反映しようとした。
分岐の数だけ書き方があり、どこで切っても「書いていない分岐」と「書いた分岐と実装の差」のどちらかが残る。
それをレビューの 1 回ごとに局所的に直したので、前の回の判断の根拠（なぜその文を消したか）が次のレビューに伝わらず、同じ箇所を往復した。

## 根拠

確信度の理由: 同じ原因（粒度を決めずに指摘ごとに局所的に直し、前の回の判断の根拠が次のレビューに伝わらなかった）で、PR #790・#791 に続いて PR #822 でも再発したため。

## 提案

チェックの挙動を文書に書くときは、最初に、文書に置く粒度を決めて PR の本文に書く。

例えば「主な例だけを挙げ、網羅しないと明記する」「判断の根拠は 1 つの比較に絞り、ほかの止まり方は既存の節を参照する」と決める。
レビューがその粒度より細かい分岐を挙げたら、直さずに PR の本文の決定を引いて返信する。前の回に消した文を戻す指摘も、戻すかをこの粒度で決め、決めた理由を返信に書く。
粒度をまだ書いていないときに戻す指摘を受けたら、戻す前に粒度を決めて PR の本文に書く。
