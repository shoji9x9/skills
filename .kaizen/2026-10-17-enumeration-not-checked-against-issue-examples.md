# 対象を洗い出すスクリプトの結果は、Issue が名前を挙げた既知の例がすべて含まれるかを突き合わせてから使う

## 事象

Issue #606 で、型ガードを TypeScript のパーサで洗い出すスクリプトを書いた。
読んだのは、TypeScript の戻り値の型と JSDoc の `@returns` の型述語だけだった。
変数の JSDoc の `@type {(x: unknown) => x is string}` の形（`isPropertyName`・`isMode`）を拾わず、44 個で直したことにした。
Issue の本文は `isPropertyName` を名前で挙げていたが、洗い出した一覧と突き合わせなかった。push 前のレビューで初めて抜けが分かった。

## 根本原因

- なぜ抜けたか → 型述語の書き方を、思いついた 2 つの形だけから列挙した。書き方の文法（関数の型を注釈する形）から挙げなかった
- なぜ気づかなかったか → スクリプトが出した件数を、答えの集合として扱った。既知の要素（Issue が名前を挙げた型ガード）が含まれるかを確かめなかった

## 提案

対象を洗い出すスクリプトの結果は、Issue が名前を挙げた既知の例がすべて含まれるかを突き合わせてから使う。

- 適用先候補: `docs/agent-workflow.md`「集合を答えにするチェックと、0 件で何もしない一括処理は、検出できることと件数を確かめる」に、Issue やレビューが挙げた名前を既知の要素に使うことを足す
- 洗い出しで落とした名前は、一覧に入らない理由（対象外の書き方か、抜けか）を 1 件ずつ書く
