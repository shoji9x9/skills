# 該当が 0 件になりうる grep を呼び出しの最後に置き、確認の呼び出しが exit 1 で終わった

## 事象

issue-batch の run の #889 で、eval の 2 つの run の答えを確かめる呼び出しの最後に、`grep -c 'provisional-decisions' <raw の記録>` を置いた。
without_skill の run には該当が無いので `grep -c` が 0 を出して exit 1 で終わり、呼び出し全体が失敗として記録された。
答えの確認そのものはできていた。

2026-11-20 の #1091 の整合パスで、語ごとの件数を出すループの最後に `grep -rl ... | grep -v '^skills/git-worktree/'` を置いた。
該当がすべて git-worktree の中だったので最後の `grep -v` が何も出さずに exit 1 で終わり、呼び出し全体が失敗として記録された。
件数の確認そのものはできていた。

## 根本原因

- なぜ exit 1 で終わったか: `grep` は、該当が 0 件のとき exit 1 で終わる。`grep -c` も、パイプの最後の `grep -v` も同じである。それを呼び出しの最後に置いた。
- なぜ最後に置いたか: 件数や一覧を見るだけの確認だったので、結果として期待される 0 以外の終了コードだと意識しなかった。2 回目は、「外の該当があれば出す」という絞り込みで、該当が無いことを想定していなかった。
- なぜ意識しなかったか: AGENTS.md の「結果として期待される 0 以外の終了コード（grep の該当なしなど）は、値を保存して分岐し、呼び出し全体の終了コードにしない」を、確認用の grep（件数・一覧の絞り込み）にも当てるものとして読んでいなかった。

## 根拠

2 回とも同じ原因（確認用の grep の 0 件を呼び出しの最後に置いた）で、呼び出しが exit 1 で終わったことで確かめた。
1 回目は出力の最後の行が `0` で、呼び出しが `Exit code 1` で終わった。KEDB 照合は「該当なし」「grep」「終了コード」で行い、一致は無かった。
2 回目は、`EnterWorktree` の語の行まで出力した後に、呼び出しが `Exit code 1` で終わった。KEDB 照合は「終了コード」「grep」「最後」で行い、このノートと `2026-09-29-probe-ls-at-exit-position.md`（`ls` の同じ形）が一致した。

## 既存の規約

- 扱い: 強制なし
- 場所: `AGENTS.md`「シェルの書き方」の「結果として期待される 0 以外の終了コード（grep の該当なしなど）は、値を保存して分岐し、呼び出し全体の終了コードにしない」と、`docs/agent-workflow.md` の同じ名前の節
- 照合した範囲: `AGENTS.md`・`docs/agent-workflow.md` を「grep の該当なし」「最後の位置」で検索した

## 食い違い

- 相手: なし
- 判断: なし

## 提案

確認用の grep（件数の `grep -c`・一覧を絞る `| grep -v`）も、該当が 0 件になりうるなら呼び出しの最後に置かず、`|| true` で終えるか、件数を変数に保存して表示する。

- AGENTS.md の該当の箇条の例に、`grep -c` の 0 件とパイプの最後の `grep -v` を足すかを apply のときに決める。
- 機構は作らない。効果は小さく、呼び出しが失敗として記録されるだけで、判定の誤りにはつながらない（2 回とも確認はできていた）。費用は、呼び出しの最後の位置を判定する Hook の分岐（パイプ・ループ・`;`）が書き方の数だけ増えることである。
