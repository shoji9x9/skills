# 該当が 0 件の grep -c を呼び出しの最後に置き、確認の呼び出しが exit 1 で終わった

## 事象

issue-batch の run の #889 で、eval の 2 つの run の答えを確かめる呼び出しの最後に、`grep -c 'provisional-decisions' <raw の記録>` を置いた。
without_skill の run には該当が無いので `grep -c` が 0 を出して exit 1 で終わり、呼び出し全体が失敗として記録された。
答えの確認そのものはできていた。

## 根本原因

- なぜ exit 1 で終わったか: `grep -c` は、数えた件数が 0 のとき exit 1 で終わる。それを呼び出しの最後に置いた。
- なぜ最後に置いたか: 件数を見るだけの確認だったので、結果として期待される 0 以外の終了コードだと意識しなかった。
- なぜ意識しなかったか: AGENTS.md の「結果として期待される 0 以外の終了コード（grep の該当なしなど）は、値を保存して分岐し、呼び出し全体の終了コードにしない」を、`grep -c` の 0 件にも当てるものとして読んでいなかった。

## 根拠

出力の最後の行が `0` で、呼び出しが `Exit code 1` で終わったことで確かめた。KEDB 照合は「該当なし」「grep」「終了コード」で行い、一致は無かった。

## 提案

件数を数えるだけの確認でも、`grep -c` を呼び出しの最後に置かず、`|| true` で終えるか、件数を変数に保存して表示する。

- AGENTS.md の該当の箇条の例に、`grep -c` の 0 件を足すかを apply のときに決める。
- 機構は作らない。呼び出しは失敗として記録されるだけで、判定の誤りにはつながらない。
