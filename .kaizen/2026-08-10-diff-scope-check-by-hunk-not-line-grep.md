# 差分のスコープ確認は hunk の帰属で判定する。行単位 grep を除外語で空にして根拠にしない

## 事象

Issue #185（pnpm 11.17.0 → 11.19.0）の bump で、`docs/package-manager.md` の
「生成後に `git diff` で範囲を確認し、bump 対象以外のブロックは元に戻す」に従い
巻き込み差分（python）を戻したあと、差分が pnpm のみであることを確認しようとした。

1 回目 `git diff mise.lock | grep -E '^[+-][^+-]' | grep -vc 'pnpm'` → 14。
pnpm セクション内の `checksum = "sha256:..."` 行はツール名を含まないため、
正しい状態なのに 14 件の偽陽性を出した（切り分けに 1 往復を要した）。

2 回目は `pnpm-lock.yaml` に対し `grep -viE 'pnpm|11\.(17|19)\.0|integrity: sha512'`
と除外語を足して出力を空にし「pnpm のみ」と判断した。しかし除外語の
`integrity: sha512` は無関係パッケージが変わったときに出る行そのものであり、
この検査は目的の異常を原理的に検出できなかった（結論自体は hunk ヘッダで別途
確認できていたため誤りではなかったが、根拠としては無効）。

## 根本原因

- なぜ検出不能な検査を根拠にしたか → 除外語を「ノイズ除去」として足し、
  出力が空になった時点で目的を達成したと読んだ
  - なぜそう読んだか → 1 回目が偽陽性を出した反動で「空になる形」をゴールにし、
    検査を期待へ合わせて調整した（filter tuning）。除外語が標的シグナルを含むかを
    検証していない
    - なぜ検証しなかったか → 差分のスコープは行の内容ではなく hunk が属する
      セクション（`[[tools.X]]` / パッケージ entry）で決まるのに、行単位の文字列
      マッチで代用した。checksum / integrity / URL など対象名を含まない行が必ず
      存在するため行単位マッチは破綻し、それを除外で埋めると標的まで塞ぐ
      ← 根本原因（対策可能）

KEDB 照合: [[2026-07-30-negative-result-checks-need-positive-control]] と
[[2026-08-03-detector-nonzero-hits-not-proof]]（ともに applied）と同型。前者は
「陰性＝合格」、後者は「非ゼロ出力で陰性性が隠れる」を扱う。本件は**期待に合うまで
除外語を足して陰性を作る**派生形で、どちらの発動条件にも自分が該当すると認識され
なかった。applied のため追記せず恒久側を強化する。手順の正本
[[2026-08-03-lockfile-regen-collateral-diff]]（applied）は「`git diff` で範囲を確認」
までで、確認の取り方を規定していなかった。

横断スコープ: 同じ穴はロックファイル一般（`pnpm-lock.yaml` / `mise.lock`）の巻き込み
確認に加え、「対象ブロック以外に触れていない」を使い捨て grep で主張する検査全般に
ある。`git diff --stat` はファイル単位までしか見ないため、ファイル内スコープの主張は
別の手段が要る。

## 提案

差分のスコープ確認は変更行の文字列マッチではなく **hunk の帰属**で判定する。
除外語を足して出力を空にする形の検査は、除外語が標的シグナルを含み得るため根拠にしない。

- 差分が小さければ全文を読み、hunk ヘッダと直近のセクション見出し（`[[tools.X]]` /
  パッケージ entry）で変更が対象ブロック内に収まることを確認する
- 行単位 grep を使うなら、**除外語を足す前に**無関係ブロックの変更行を 1 行混ぜて
  検出できることを確かめる（陽性コントロール）。空にするために除外語を足した時点で
  その検査は根拠として無効になる
- 反映先: `docs/package-manager.md`「mise lock の巻き込み差分を絞る」節
