# 便宜で表示した終了コードを検証結果として報告し、偽の合格を出した

## 事象

PR #418 の検証で `node scripts/lint-pagination.js 2>&1 | tail -5; echo "pagination exit=$?"` を
実行し、`exit=0` を見て「通過」と報告した。この 0 は `tail` の終了コードで、
スクリプト本体は exit 1 だった（後で `>/dev/null` にしたら `&&` 連鎖が切れて発覚）。

実害は無かった（指摘 2 件は未追跡の eval 成果物で、CI は見ていない）が、
「検査を通した」という報告自体が誤りだった。

**同じセッション内で正しく書いてもいる**——`gh pr checks ... | tail -15; echo "exit=${PIPESTATUS[0]}"`。
規約を知らなかったのではなく、片方だけ適用した。

## 根本原因（なぜを 3 階層）

1. なぜ偽の合格を出した? → パイプ末尾の `$?` を読んだから
2. なぜ `PIPESTATUS` を使わなかった? → その行の `echo "...exit=$?"` を
   「検証の判定」ではなく「出力の添え物」として書いた（`gh pr checks` の方は
   最初から判定のつもりだったので `PIPESTATUS` を使った）
3. なぜ添え物が報告になった? → 出力された数字は、書いたときの意図と無関係に
   後から根拠として読まれる。**便宜で出した数字と判定に使う数字を
   同じ見た目で出すと、後者として読まれる** ← 根本原因

## 横断スコープ確認

AGENTS.md には既に「パイプ越しの成否判定に末尾 `$?` を使わない」があり、
`.kaizen/2026-07-05-pipeline-exit-code-masking.md` は `status: applied`。
**常時ロードされる文章規約を破った再発**なので、同じ規約を書き足しても効かない
（[[2026-09-16-prose-rule-recurrence-needs-deterministic-gate]] と同じ形）。

ただし今回の発生場所は**対話的な検証コマンド**で、リポジトリの lint / hook は見えない。
機構側へ寄せられるのは「終了コードをツール呼び出し自体に持たせる」形まで。

## 提案

検査の合否を知りたいときは、終了コードを `echo` で印字せずツール呼び出し自体に持たせる。

- パイプを付けずにそのまま走らせるか、`&&` で連鎖する。出力を絞りたければ
  `cmd >out 2>&1 || rc=$?` のように**分離して**から `tail out` する
- `echo "exit=$?"` を書くのは「この数字を判定に使う」ときだけにし、その場合は
  必ず `${PIPESTATUS[0]}` か `set -o pipefail` を使う。添え物としては出さない
- AGENTS.md の既存行へ 1 句追加: **出力した終了コードは必ず主張として読まれる。
  判定に使わないなら出さない。**
