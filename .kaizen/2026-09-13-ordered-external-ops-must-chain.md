# 順序依存のある外向き操作は && で連鎖する

## 事象

PR #352 でレビュースレッドに「返信してから解決する」をループで回したところ、
返信が 404 で失敗したのに解決だけが成功し、**返信の無いスレッドを解決済みにした**。

直接の引き金は、返信先の comment id を URL の中で `$(gh api graphql ...)` と
コマンド置換しており、そのクエリが `gh: Expected NAME` で割れたこと。

同日の PR #355 では `reply && resolve` の返信側が HTTP 502 を返した際、resolve は実行されなかった。
返信の部分作成を API で確認してから resolve だけを再開でき、提案する連鎖が不整合を防ぐことを実測した。

**2026-09-17 に PR #391 で再発（同じ根本原因の別の形）。** レビュー返信を
`gh api repos/.../pulls/391/comments/4032873141/replies -F body=@<file>` で投稿し
`404 Parent comment not found` になった。**`4032873141` はどの出力にも現れない、こちらが組み立てた番号**で、
直前に取得していた実際の id は `4032861562` だった。しかも同じ呼び出しの `||` 側に
「未解決スレッドの `databaseId` を取得する」コマンドを書いていた——**id が不確かだと認識しながら、
確認を fallback に置いて本番の外向き操作を先に撃っていた**。
同じ形の返信を 5 ラウンド繰り返しており、**定型化した呼び出しほど可変部（id）の由来確認が抜ける**。

## 根本原因（なぜを 3 階層）

1. なぜ順序が崩れた? → `reply; resolve` を独立した 2 コマンドとして並べた
2. なぜ並べた? → 複数スレッドを for ループで処理した。
   ループの自然な書き方が依存関係を落とす
3. なぜ落としても気付かない? → 順序の要求がスキルの散文（「順序厳守」）にしか無く、
   コマンドの形が強制していない ← 根本原因

再発（#391）の側の「なぜ」:

1. なぜ存在しない id を渡した? → 前ラウンドと同じ形のコマンドを写し、可変部の id だけを
   「それらしい値」に替えた（取得した出力と突き合わせていない）
2. なぜ突き合わせなかった? → 確認を `||` の fallback に置き、**本番操作を先に実行する順序**にした
3. なぜその順序でよいと思った? → 既存規律（`AGENTS.md`「opaque ID は…機械取得し、
   非空・形式・比較対象との一致を検証してから渡す」）は**値の作り方**を定めるが、
   **確認と本番操作の実行順**までは形で縛っていない ← 根本原因（本ノートの提案と同じ層）

## 横断スコープ確認

同じ形は `pr-review-handle` / `pr-finalize-loop` の「返信 → 解決」、
`issue-start` の「ブランチ作成 → 紐付け確認」など、外向き操作を 2 段で行う箇所すべてにある。
スキル側は順序を散文で書いているが、実行するコマンドの形までは指定していない。

## 提案

`.agents/rules/` の既存ルール（シェル操作系）へ次を追加する。

- **順序依存のある外向き操作は `&&` で連鎖する**。
  前が失敗したら後が走らない形にする（`reply && resolve`）。
  ループで回すときはとくに効く——1 件失敗しても次の反復へ進むので、
  失敗を見逃すと不整合な状態だけが残る
- **不可逆な操作の引数を、その操作と同じコマンド内のコマンド置換で作らない**。
  先に別コマンドで取って非空を確かめてから渡す
- **確認を `||` / fallback に置かない。** 引数の由来が不確かなら、**確認を先に実行して値を確定させてから**
  本番の外向き操作を撃つ（`id=$(...); [ -n "$id" ] && gh api .../$id/...`）。
  fallback へ回すと「不確かだと認識したまま本番を先に実行する」形になり、外向きの副作用が先に飛ぶ
- **定型化した呼び出しの可変部は、毎回その場で取得した出力から埋める。** 同じ形を繰り返すほど
  可変部（id・番号・SHA）の由来確認が抜ける。前ラウンドのコマンドを写して可変部だけ書き換えない
  （AGENTS.md 「opaque ID ・完全 SHA は構造化された正本から機械取得する」の具体例）
