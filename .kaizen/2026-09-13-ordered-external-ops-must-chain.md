# 順序依存のある外向き操作は && で連鎖する

## 事象

PR #352 でレビュースレッドに「返信してから解決する」をループで回したところ、
返信が 404 で失敗したのに解決だけが成功し、**返信の無いスレッドを解決済みにした**。

直接の引き金は、返信先の comment id を URL の中で `$(gh api graphql ...)` と
コマンド置換しており、そのクエリが `gh: Expected NAME` で割れたこと。

## 根本原因（なぜを 3 階層）

1. なぜ順序が崩れた? → `reply; resolve` を独立した 2 コマンドとして並べた
2. なぜ並べた? → 複数スレッドを for ループで処理した。
   ループの自然な書き方が依存関係を落とす
3. なぜ落としても気付かない? → 順序の要求がスキルの散文（「順序厳守」）にしか無く、
   コマンドの形が強制していない ← 根本原因

## 横断スコープ確認

同じ形は `pr-review-handle` / `pr-finalize-loop` の「返信 → 解決」、
`issue-start` の「ブランチ作成 → 紐付け確認」など、外向き操作を 2 段で行う箇所すべてにある。
スキル側は順序を散文で書いているが、実行するコマンドの形までは指定していない。

## 提案

`.agents/rules/` の既存ルール（シェル操作系）へ次を追加する。

- **順序依存のある外向き操作は `&&` で連鎖する**。
  前が失敗したら後が走らない形にする（`reply && resolve`）。
  ループで回すときはとくに効く——1 件失敗しても次の反復へ進むので、
  失敗を見逃すと不整合な状態だけが残る
- **不可逆な操作の引数を、その操作と同じコマンド内のコマンド置換で作らない**。
  先に別コマンドで取って非空を確かめてから渡す
  （AGENTS.md 「opaque ID ・完全 SHA は構造化された正本から機械取得する」の具体例）
