# 「コマンドの出力と同じか」の判定を、変えたファイルの名前だけで書いた

## 事象

Issue #1110 で、`dependabot-merge` に例外を足した。手で足した commit が文書のコマンドで作り直せるものだけなら、`@dependabot recreate` してよいとする例外である。
例外に当たるかは、「commit が変えたファイルが、すべてそのコマンドの出力である（`git show --stat` で確かめる）」とだけ書いた。
`/code-review --fix` が 3 つの抜けを指摘した。1 つ目は、ファイル名が同じでも中身を手で書き換えた commit（ロックのバージョンを手で固定したなど）が例外に当たること。
2 つ目は、merge commit では `--stat` がファイルを表示しないこと。3 つ目は、PR の commit を fetch していない clone では `git show` が失敗することである。
3 つを直す手戻りになった。

## 根本原因

- なぜ抜けたか: 「作り直せる」を、変えたファイルの集合がコマンドの出力の集合に含まれるかという 1 つの軸だけで判定した。
- なぜ 1 軸だけだったか: 元の事例（Gradle のロックだけを足した PR）の表面から条件を書き、判定がずれうる軸（ファイル名・中身・commit の形・手元に在るか）を挙げなかった。
- なぜ挙げなかったか: `AGENTS.md`「確かめ方」の「判定軸を足すときは、元の事例の表面ではなく機序から作る」を、コードやチェックの話と受け取り、スキルの手順の文に書く判定の条件に当てなかった。

## 根拠

確信度を low にしたのは、規約を読んでいて当てなかったのか、当てはまると気付かなかったのかを、このセッションの観測から区別できないからである。
同じセッションで、code-review の指摘を受けて、中身が同じかの確認（PR の head でコマンドを実行し `git status --short` が空）と、merge commit の除外・fetch を足した。
KEDB 照合（`判定軸`・`git show`、`作り直`・`生成物`、`ファイル名`・`中身`）は、同じ原因の学びに一致しなかった。

## 既存の規約

- 扱い: 明確
- 場所: `AGENTS.md`「確かめ方」の「規約に語彙・記録項目・判定軸を足すときや、…元の事例の表面ではなく機序から作る」
- 照合した範囲: `AGENTS.md` で `判定軸`・`ずれうる軸` を検索した

## 食い違い

- 相手: なし
- 判断: なし

## 提案

既存の規約（`AGENTS.md`「確かめ方」の判定軸の箇条）に従い、スキルの手順に判定の条件を書くときも、判定がずれうる軸（名前・中身・形・手元に在るか）を挙げてから書く。再発したら、箇条に「スキルの手順の文に書く判定の条件も含む」と足すことを検討する。
