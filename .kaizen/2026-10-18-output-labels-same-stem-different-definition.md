# 利用者に見せる指標を足すときに、同じ出力の似た名前のラベルを洗い出さず、定義の違う「稼働」を並べた

## 事象

Issue #699 で agent-usage の report のチャートに「稼働中」（人ごとに run の区間を合わせた時間）を足した。
同じ画面には、外部待ちを除いた「稼働（時間）」、run の件数の「稼働の回数」、「連続稼働の中央値」があった。
定義の違いを注記で説明するだけにし、上部の「停止」のタイルもそのままにした。
利用者が 2 回指摘した。1 回目は上部の停止のタイルも稼働状況にすること、2 回目は似た名前で意味の違うものがあると混乱するので定義を統一することである。
そのたびに、集計・HTML・テスト・変異・文書を直した。

## 根本原因

1. なぜ並んだか → 新しい系列の名前を決めるとき、同じ出力の中で語幹（稼働）を共有する既存のラベルを洗い出さなかった
2. なぜ洗い出さなかったか → 変更の対象を指示されたチャート 2 つに限り、同じ画面の他の表示との整合を確かめる対象にしなかった。違いは注記で足りると判断した
3. なぜそう判断したか → 利用者に見せる指標（チャート・表・タイルのラベル）を足すときに、同じ出力の既存のラベルと定義を突き合わせる手順が無い。skill-consistency-pass は文書の取り決めが対象で、出力のラベルは対象外 ← 根本原因

## 提案

利用者に見せる指標（チャート・表・タイルのラベル）を足すか定義を変えるときは、同じ出力の中で語幹を共有する既存のラベルを洗い出し、定義が違えば名前か定義をそろえる（注記で違いを説明して済ませない）。

- 反映先の候補: docs/agent-workflow.md「確かめ方」と AGENTS.md の要約。または skill-consistency-pass の対象に、配布スキルの出力のラベルを足す
- 横断: 他の配布スキルの出力（parity-diff の分類・browser-test の報告など）にも同じ形が無いかを apply のときに確かめる
- KEDB: 「語彙」で 2026-09-16-vocabulary-derived-from-one-direction（applied、規約の語彙の対称性）に一致したが、別の事象。新しく作る
