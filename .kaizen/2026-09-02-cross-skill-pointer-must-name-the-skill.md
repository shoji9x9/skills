# 姉妹スキルの正本を指すときは指示語を使わずスキル名を書く

## 事象

PR #289 のレビューで 2 件指摘された。`parity-diff` の `references/capture-new.md` に
「正本は**同スキル**の `references/baseline.md`」、`parity-suite` の `references/baseline.md` に
「正本は**同スキル**の `references/capture-new.md`」と書いており、どちらも**直前に挙げた姉妹スキル**を
指すつもりだったが、置かれているファイルのスキルを指すとも読める。姉妹スキル間では
`references/` のファイル名が似通うため、誤読すると存在しないパスを探すことになる。

## 根本原因

- なぜ曖昧になった? → 「`parity-suite` が測る…」と直前に書いたので、後続の「同スキル」で
  受けられると考えた
  - なぜそれで通ると思った? → 執筆時は 1 ファイルの中で読んでおり、読み手が
    そのファイルの所属スキルを基準に読むことを考慮しなかった
    - なぜ? → 配布スキル横断の正本参照について、**指示語（同スキル・本スキル・同ファイル）で
      受けない**という執筆規約がどこにも無い ← 根本原因（対策可能）

横断スコープ: `skills/**` の相互参照全般。姉妹スキル群（replace-strategy / parity-*）は
`references/` の構成が対称なので特に踏みやすい。

KEDB 照合: `kaizen-kedb-match.sh "指示語" "skills"` は 0 件（既存の学びなし）。

## 提案

`.agents/rules/doc-altitude.md`（または配布スキルの執筆規約）に追記する:

- **他スキルの正本を指す参照は、指示語で受けずスキル名を書く。** 「同スキルの」「本スキルの」は
  読み手がそのファイルの所属スキルとして解決するため、姉妹スキルを指す用途に使わない。
  直前の文でスキル名を挙げていても繰り返す（正本参照は 1 行で自己完結させる）。
