# 設定ソースは異なるスコープを担うものだけ追加する

## 事象

一時的にレビューツールを切り替える要件に対し、共有 YAML に加えて GitHub Repository Variable、clone ローカルの `.git/config`、環境変数を順に提案した。ユーザーの指摘を受け、ローカル用途には CLI・環境変数・共有既定だけで十分と整理し直したため手戻りが生じた。

## 根本原因

設定を永続化したいという表面的な要求から、技術的に利用可能な保存先を追加した。これは利用者・有効期間・共有範囲を先に分類しなかったためであり、さらに既存の設定ソースと新しい設定ソースが異なる責務を持つかを検証せず、選択肢の多さを柔軟性とみなしたことが根本原因である。

## 提案

設定ソースを追加する前に利用者・有効期間・共有範囲・正本を列挙し、既存ソースと責務が重なるものは追加せず最小の優先順位にする。

設定の優先順位を設計するときは各層に固有の利用場面を 1 行で説明する。同じ利用場面を担う層が複数ある場合は、認証・通信・隠れた状態・更新方法の負担を比較して 1 つへ絞る。
