# 使い捨ての集計スクリプトの判定も、既知の入力で確かめてから読む

## 事象

ミューテーションテストの expect_failing を測る使い捨てのスクリプトで、vitest の JSON の `numFailedTestSuites` を
「テストファイルの読み込みに失敗した」とみなして印字した。
実際はテストが 1 件でも落ちたファイルを数える値なので、すべての変異に `SUITE FAILED` と出た。
本当に読み込みに失敗した変異（DR-SEC-NOTFOUND。末尾のカンマで構文エラー）が、その中に紛れた。

## 根本原因

- 誤った理由: フィールドの意味を確かめずに、名前から推測した。
- 確かめなかった理由: 使い捨てのスクリプトは検証の対象外だと扱った。
- その理由: `docs/agent-workflow.md` の「使い捨てのスクリプトも検出されることを確かめる」は、検出・除外の走査を例にしている。
  結果の分類（ラベル付け）には当てはめなかった。

## 提案

使い捨てのスクリプトが出す分類のラベルも、各ラベルに当たる既知の入力を 1 件ずつ通してから読む。

- 既知の入力の例は、読み込みに失敗する変異と、普通に落ちる変異。
- 既存の規約の再発なので、文書に追記するのではなく、`scripts/mutation/check-mutation-proof.js` の `--only` で
  本物のランナーを使う形に寄せる。
