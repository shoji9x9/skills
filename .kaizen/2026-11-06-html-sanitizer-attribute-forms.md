# SVG から `on*` を除く処理で、形を HTML だけの文法から挙げ、引用符の直後の `on*` と XML にだけある文脈の `on*` を取りこぼした

## 事象

2026-11-06、Issue #921 で aws-architecture-diagram の SVG から `<script>` と `on*` を除く部品（`strip-active-content.mjs`）を書いた。
`on*` の前の区切りは、思いついた空白と `/` だけを挙げた。
push の前の `/code-review --fix` が、引用符の直後に空白なしで続く属性（`width="1"onclick=...`）と、名前空間の接頭辞を付けた `<a:script>` を除けないと指摘した。
テストの期待値も 2 件、仕様（HTML と XML がその出力をどう読むか）から決めず、自分の理解で書いて外れた。うち 1 件は、後で出力をそのまま期待値にしたので、XML として読めない出力（`<rect"y"`）を固定していた。

同じ日、PR #922 の反復 1 の指摘を受けて、除去を、HTML の字句解析を手で再現して属性を 1 つずつ読む形に替えた。
反復 2 の `/code-review` が、XML にだけある文脈（ASCII 以外で始まるタグ名・コメントの中の閉じない引用符・実体の宣言）のハンドラが残る回帰を 3 件指摘した。
プレビューを `<img>` で読み込む形にしたときも、XML として正しくない SVG（xmlns が無いなど）が白い PNG になることを確かめていなかった。
文脈を見ない除去に戻し、プレビューは CSP で script を止める形にした。
反復 3 の `/code-review` が、CSP は `<meta http-equiv="refresh">` による移動を止めず、移動先では script が実行されることを指摘した。`<meta>` を除く形にしたが、反復 4 で閉じないタグ・`</meta>`・コメントの中の形が指摘され、移動に要る属性名 `http-equiv` を置き換える形にした。

## 根本原因

- なぜ抜けたか → 除く形を、HTML の属性とタグの文法から挙げず、元のコードと Issue の 2 例から挙げた
- なぜ文法から挙げなかったか → `.agents/rules/state-space-and-mutation-proof.md` は埋め込み先の文法から挙げると書くが、例は Markdown だけで、HTML の属性の区切りやタグ名の形が無い
- 2026-10-08 の学び（embed-into-markup-enumerate-grammar、applied）と同じ原因の再発である
- 反復 2 の回帰: SVG は HTML としても XML としても読まれるのに、形を HTML の文法だけから挙げた。反対側（XML の読み方）を当てなかった
- 指摘を受けて構文を読む処理を自作したので、読めなかった文脈が「ハンドラ無し」として通った。除去のような安全のための処理は、読めない文脈で取り除く作りかを先に確かめる

## 根拠

`/code-review` の指摘を手元で実行し、直す前のコードで 3 件とも残ることを確かめた。
反復 2 の指摘 3 件は、属性を読む形に替える前のコード（e6b02368）と替えた後のコード（a7219439）に同じ入力を渡して確かめた（替える前は除き、替えた後は残す）。同じ原因の再発なので、priority と confidence を high にした。

## 提案

`.agents/rules/state-space-and-mutation-proof.md` の「埋め込み先の仕様から、文字列が構文として読まれる形を挙げる」に、HTML の例を足す。

- 例: 属性の区切り（空白・`/`・引用符で閉じた値の直後）、終了タグの後の属性、名前空間の接頭辞、取り除いた後に現れる形（入れ子）
- テストの期待値は、出力を HTML と XML がどう読むか（script とハンドラが残らない、残る属性と文字が入力と同じ）という仕様から決める。実際の出力を、そのまま期待値にしない。
- 例に、XML にだけある形（コメント・CDATA・処理命令・実体の宣言・ASCII 以外の名前）を足す
- 安全のための除去は、構文を自作して読む前に、読めない文脈でも取り除く作りかを確かめる
- CSP のように攻撃の一部を止める仕組みを使うときは、その仕組みが止めない形（`<meta http-equiv="refresh">` による移動など）を仕様から挙げる
