# 外部の成果物を後で書き換えるかの判定に使う値を、run の間だけ残る manifest に置いた

## 事象

issue-batch の run の #905 で、PR の本文に追記した範囲を人が書き換えたかを判定する値を、run の manifest（`/tmp` の 1 つの欄）に置く手順を書いた。
ローカルレビューが、同じ根の指摘を 5 件出した。
前の run の PR を再開すると値が無い。1 つの run の複数の PR で値を取り違える。GitHub の画面で保存すると改行が CRLF になって一致しない。書き込みの途中で失敗すると値が残らない。
値を PR の本文の目印に置き、改行をそろえて計算する形に書き直した。

## 根本原因

判定の値を、判定する対象（PR の本文）と別の場所に置き、その場所が残る範囲（1 回の run・1 つの欄）を、対象が残る範囲（PR の寿命・PR ごと）と比べなかった。
入力の状態として、再開・複数の対象・別の書き手が保存したときの正規化・書き込みの途中の失敗を、書く前に挙げていなかった。

## 根拠

1 回の観測で、指摘の 5 件がすべて「値の置き場所の範囲が対象の範囲より狭い」ことから生じていたので、原因を 1 つに絞れる。
KEDB 照合では `manifest`・`再開`・`状態` を照合し、一致する学びは無かった。

## 提案

外部の成果物（PR・Issue の本文など）を後で書き換えるかの判定に使う値は、置く前にその値が残る範囲（実行・欄の単位）と対象が残る範囲を 1 行ずつ書き、狭ければ対象そのものに置く。

- 置き場所を決めたら、再開・複数の対象・別の書き手による保存（改行や空白の正規化）・書き込みの途中の失敗の 4 つを、判定の入力の状態として挙げる
- 反映先の候補は `.agents/rules/state-space-and-mutation-proof.md` の「記録を読むチェックは、書き手の不変条件を読み手ですべて検査する」の箇条
