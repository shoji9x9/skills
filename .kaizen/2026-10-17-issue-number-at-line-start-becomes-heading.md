# Markdown の行を Issue の番号（`#` と数字）で書き始めない

## 事象

同じセッションで 2 回、Markdown の段落の行を「#633 の…」「#632 で…」のように Issue の番号で書き始めた。
1 回目は PR の本文で、markdownlint の自動修正が見出し（`# 633`）に書き換えた。
2 回目は `.kaizen/` の学びで、pre-commit の markdownlint が MD022・MD025・MD026 で commit を止めた。

### 2026-10-18 の再発（Issue #625: kaizen の学びの本文）

kaizen の学びの「## 事象」の段落を「#625 で、…」で書き始め、整形のために `markdownlint-cli2 --fix` を当てた。
`--fix` は警告を出さずに行を見出し（`# 625 で、…`）に書き換え、その後の検査が MD022・MD025・MD026 で失敗した。
同じ学びが pending のまま注入されていたが、書くときに当てなかった。

### 2026-11-08 の再発（Issue #933: kaizen の学びの本文）

kaizen の学びの「## 事象」の段落を Issue の番号で書き始め、`markdownlint-cli2 --fix` を当てた。
`--fix` は警告なしに行を見出しに書き換え、その後の検査が MD022・MD025・MD026 で失敗した。
この学びは pending のまま、セッション開始時に注入されていた。

同じセッションで、別の学びの `## 根拠` に追記した行も Issue の番号で書き始めた（4 回目）。
python の文字列で本文を組み立てたので、書いた行を Markdown として読み直さなかった。lefthook の markdownlint が見出しに書き換えて止めた。

## 根本原因

- なぜ見出しになったか → 行頭の `#` の後に空白が無くても、markdownlint の `--fix` は空白を足して ATX 見出しにする（MD018）
- なぜ繰り返したか → 1 回目は言い換えて直しただけで、書き方の規約として残さなかった
- なぜ書く時点で気づかないか → 文として読むと自然で、Markdown の構文としての意味が見えない
- なぜ 3 回目が起きたか → 規約は pending の提案のままで、書く時点で機械が止めない。`--fix` は書き換えを報告しないので、検査が失敗するまで気づかない
- なぜ 4 回目が起きたか → 本文を python の文字列で組み立ててファイルに書いたので、書いた行を Markdown の行として目で読まなかった。書く手段が変わると、文として読み直す機会も無くなる

## 根拠

同じ原因（行頭の `#` と数字を `--fix` が見出しにする）での 3 回目と 4 回目の再発を、検査の失敗で確かめた（high）。
4 回目は、スクリプトの文字列で本文を組み立てたときにも起きることを示す。書く手段に関わらず止める機構が要る根拠になる。
KEDB 照合（見出し・`#`）で、このノートが一致した。

## 既存の規約

- 扱い: なし
- 場所: なし
- 照合した範囲: `AGENTS.md`・`docs/`・`.agents/rules/`・`skills/kaizen/` を、`` 行頭の `#` ``・`MD018` で検索した

## 提案

Markdown の行頭の `#` と数字（`#625`）を、整形の `--fix` より前に実行する検査で検出して止める。

- 書き方は「Issue #632 の作業で…」のように語を前に置く
- 適用先候補: lefthook の format 段で、`markdownlint-cli2 --fix` より前に実行するジョブ。`scripts/gates/prose/lint-prose.ts` は lint 段で `--fix` の後に実行されるので、行が見出しに書き換わった後では検出できない
- 横断: commit message と Issue のタイトルは Markdown として整形されないので対象外
- 機構の効果と費用: 効果は、同じ原因で 4 回再発した記録があり（手で書いたときもスクリプトで組み立てたときも起きた）、`--fix` が警告なしに書き換えるので、ほかに気付く手段が後の検査の失敗しかないこと。
  費用は、判定が「段落の行頭が `#` と数字（`#` の後に空白が無い）」の 1 つの形で済み、例外はコードブロックの中だけであること。
  format 段に新しいジョブを 1 つ足し、`--fix` より前に実行する順序を lefthook の設定で決める必要がある。
