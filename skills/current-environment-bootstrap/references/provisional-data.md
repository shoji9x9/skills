# 暫定起動データの構築（工程 6）

**ここで作るのは「現行アプリを起動し、ログインし、主要画面を探索できる」ための最小限のデータであり、比較の正解ではない。**
ゴールデンデータセットは `replace-strategy` の測定と機能インベントリが終わったあとに `golden-dataset` が確認済みの意味論を基に別途構築する（禁止事項 5）。

## 暫定起動データとゴールデンデータの分離

| | 暫定起動データ（本スキル） | ゴールデンデータセット（`golden-dataset`） |
|---|---|---|
| 目的 | 現行アプリを起動・探索できるようにする | 現・新の比較を成立させる |
| 前提 | 機能インベントリはまだ無い | 機能インベントリ・測定・戦略が確定済み |
| 網羅 | 起動に要る最小限 | エッジケースを意図的に含む代表データ |
| 根拠 | 確定済みの意味論のみ。確認待ちは含めない | 確定済みの意味論のみ |
| ツール | `<bootstrap_tool_dir>`（既定 `bootstrap/`） | `<dataset_tool_dir>`（既定 `seed/`） |

- **自動昇格させない。** 「暫定データが十分に見えるからゴールデンデータにする」を行わない。網羅の設計基準が違うため、流用は代表性の検討を飛ばすことになる
- **ツールも分ける。** 同じディレクトリ・同じエントリに相乗りさせない（`golden-dataset` フェーズ A の事前削除が暫定データを消すのは正常な動作であり、混在させると再構築の再実行が壊れる）
- **`golden-dataset` フェーズ A は暫定起動データを置き換える。** そのため**起動に要る前提**（認証ユーザー・マスタ・コード表等）は、フェーズ A のデータ設計に確定根拠に基づいて含める必要がある。
  この引き継ぎ事項は `metadata.json` の `handoff.boot_requirements` に列挙する（[`verification-handoff.md`](verification-handoff.md)）

## 作り方

- **決定論的・冪等**にする。ID・連番・UUID・基準時刻を固定し、削除（FK 依存の逆順）→ 投入（依存順）の構造で何度実行しても同じ状態になるようにする
- **確定済みの意味論だけを使う。** 確認待ちの値を「とりあえず」で埋めない
- ツールは対象プロジェクト側のコードなので、`references.coding_conventions` に従って書く（未整備でも停止しないが、推測で自分の流儀を持ち込まず既存コード・リント設定から読み取る）
- 生成・更新したら設定の `verification_commands` を通す（**設定に無くても停止せず**、その旨を `verification.md` に記録して進む）
- 投入した値は 1 件ずつ `semantics.md` に根拠付きで記録する（**どの値がどの根拠で入っているか**が後から辿れない環境は、引き渡しても比較基準にならない）

## 投入ゲート

**投入前に 2 枚のゲートを通す。どちらか一方でも通らなければ投入しない。**

1. **設定由来ゲート**: 投入先 target が `db.seedable: true` であること（`dataset_mode: static` なら書き込み先がすべて `dataset_static_paths` 配下に収まること）。
   許可が無ければ設定の修正を促して停止し、**自分で `seedable: true` を足さない**
2. **自己申告ゲート**: 接続先の環境変数**名**を提示し（値は表示しない）、テスト環境であることをユーザーに確認する

加えて、投入するデータ自体に**来歴・利用許可が不明なものが 1 件でも混ざっていたら投入しない**（禁止事項 3。判定は [`data-semantics.md`](data-semantics.md)「来歴と利用許可」）。

## 起動に必須の項目が確認できないとき

**捏造せず停止する。** 起動・ログインに必須（NOT NULL かつ既定値なし、または認証・権限の判定に使われる）な項目の意味を確認できない場合は、
その項目を質問票の**最優先**に立て、`status: blocked` として停止する。

- **起動に必須でない未確認項目は停止理由にしない。** 台帳に「確認待ち」として残し、影響（どの機能が検証できないか）を書いて進む。
  この区別が付かないと、確認待ちが 1 件でもあるだけで環境が永久に建たなくなる
- 「NULL にしておけば動く」で埋めない——それは値の選択であり、根拠の無い選択である。**NULL を選ぶこと自体に根拠が要る**
