# 設定ファイルの扱い

shoji9x9/skills の配布スキルは、設定を同じ置き場所・同じ形式・同じ順序で読み書きする。
この文書は、設定を読むスキルがすべて同じ内容で持つ。スキルごとのキーの意味と値は、各スキルの文書とスキーマ（`config-schemas/<名前>.schema.json`）にある。

## 層と置き場所

設定は、次の 3 つの層のファイルに書く。`<名前>` はスキル名か、複数のスキルが使うキーをまとめた `common` である。

| 層 | 置き場所 | 値を適用する範囲 | commit |
| --- | --- | --- | --- |
| リポジトリ | `.config/skills/shoji9x9/<名前>.jsonc` | このリポジトリの全員 | する |
| 人ごと・リポジトリ限定 | `.config/skills/shoji9x9/<名前>.local.jsonc` | このリポジトリの自分だけ | しない（gitignore） |
| 人ごと | `${XDG_CONFIG_HOME:-~/.config}/skills/shoji9x9/<名前>.jsonc` | このマシンの自分の、すべてのリポジトリ | しない |

`shoji9x9` は配布元の名前で、他の配布元のスキルと置き場所が重ならないようにするために入れている。
`.config/` はリポジトリのルート（`git rev-parse --show-toplevel`）の下に置く。`XDG_CONFIG_HOME` が空か相対パスなら、`~/.config` を使う。
`~` は `HOME` のディレクトリで、`HOME` が無いか空なら、ユーザーのデータベース（passwd）のホームを使う。
それでも人ごとの層の置き場所が絶対パスに決まらなければ、人ごとの層を読まず、`set --layer user` も止める。読まないことは、読み取りのたびに stderr の `note:` で示す。

## どの層に置くか

値の持ち主と、値を適用する範囲で決める。

- リポジトリ: そのリポジトリで全員が同じ値を使うもの。commit してレビューする（マージの方式、規約のドキュメント、共有フォルダの ID など）
- 人ごと・リポジトリ限定: このリポジトリでだけ、自分が違う値を使いたいもの（このリポジトリでだけ使うレビューツールなど）
- 人ごと: 自分がどのリポジトリでも同じ値を使うもの（人の ID、タイムゾーン、マシンで決まる値）

人ごとの層はマシンごとの場所（`XDG_CONFIG_HOME`）にあるので、マシンで決まる値（sandbox の可否、タイムアウト）もここに置く。
人が 1 回だけ値を変えたいときは、ファイルを書き換えず、スキルの CLI のオプション（`--review-tool none` など）で渡す。
値を残しておきたいなら、置き場所は必ず上の 3 つのファイルのどれかにする。

キーごとに、置ける層が決まっている（スキーマの `x-layers`）。
個人の設定がリポジトリの方針を上書きしないように、リポジトリで揃える値（`merge_method` など）はリポジトリの層だけに置ける。
置けない層に書いたキーは、読み取りがエラーにする。

### 環境変数にする値

環境変数は、次の 3 種類に当たる値だけに使う。それ以外の値を環境変数に置かない。

1. 秘密の情報（token・client secret など）。設定ファイルにも書かない
2. プログラムが子プロセスに渡す値（CI の workflow の inputs、テストの隔離）。スキーマの `x-env` に名前を宣言したキーだけが、環境変数から値を受け取る。
   eval のランナーのように、手元の人ごとの設定を読ませたくないプログラムは、`SHOJI9X9_SKILLS_IGNORE_USER_CONFIG=1` を渡す。
   読み取りは人ごとの層を無いものとして扱い、そのことを stderr に出す。値は `1` だけを受け付ける。利用者が設定を置くための変数ではない
3. 他のツールが名前を決めている変数（`XDG_CONFIG_HOME`・`CHROME_PATH` など）

`.env` や `.env.local` に置いていた秘密でない値は、上の層のどれかのファイルへ移す。

## 解決の順序

すべてのスキルで、キーごとに次の順に探し、最初に見つかった値を使う。

1. CLI のオプション
2. 環境変数（`x-env` を宣言したキーだけ）
3. 人ごと・リポジトリ限定（`<名前>.local.jsonc`）
4. 人ごと（`${XDG_CONFIG_HOME:-~/.config}/skills/shoji9x9/<名前>.jsonc`）
5. リポジトリ（`<名前>.jsonc`）
6. スキーマのデフォルト（`default`）

値はキーの単位で決まり、オブジェクトや配列を層の間で混ぜ合わせない（上の層にあるキーが、下の層の同じキーを丸ごと置き換える）。
値を使わなかった層のファイルも、すべて検証する。どの層の綴りの誤りも見逃さないためである。

## 形式

形式は JSONC（コメントと末尾のカンマを許す JSON）にする。`//` と `/* */` のコメントを書ける。
最上位はオブジェクトで、キーはスキーマに定義したものだけを置ける。エディタの補完に使う `$schema` のキーは、置いても無視する。
キーの重複はエラーにする。

## 読み方

スキルの中の `scripts/skill-config/skill-config.mjs` で読む（Node.js が要る）。JSONC のパーサ（jsonc-parser、MIT）を同じディレクトリの `vendor/` に同梱しているので、利用者のプロジェクトに依存を入れる必要は無い。

```bash
CFG="<このスキルのディレクトリ>/scripts/skill-config/skill-config.mjs"
node "$CFG" get <名前> <キーのパス>      # value=<JSON> と source=<層> を出力する
node "$CFG" get <名前> <キーのパス> --raw # 値だけを出力する（文字列はそのまま、それ以外は JSON）
node "$CFG" dump <名前>                  # すべてのキーの値と出所を JSON で出力する
node "$CFG" validate <名前>              # すべての層のファイルを検証する
node "$CFG" paths <名前>                 # 3 つの層のファイルのパスを出力する
```

`<キーのパス>` は、最上位のキーか、入れ子の値を指すパス（`current.origin`、配列の要素なら `targets.0`）である。数字だけの部分は配列の添字として読む。`.` を含むキーと数字だけのキーは、JSON の配列（`'["pricing","gpt-5.1"]'`）で書く。
層は最上位のキーごとに選び、パスはその層の値の中をたどる。パスの先に値が無ければ、値が無いとき（exit 3）と同じに扱う。

`source` は `cli`・`env`・`local`・`user`・`repo`・`default` のどれかで、ファイルの層なら `path=<ファイル>` も出力する。
終了コードは、0 が成功、1 が設定の誤り（知らないキー・型の誤り・置けない層・旧い場所の設定）、2 が引数の誤り、3 が値が無い（どの層にも無く、デフォルトも無い）である。
1 のときは、エラーの内容を利用者に示して止まる。デフォルトの値で続けない。3 は「設定が無い」という正常な結果なので、そのキーの扱いを各スキルの文書に従って決める。

設定ファイルがどの層にも 1 つも無いときに、Node.js なしでデフォルトの値を使えるスキルがある（kaizen・box などの bash のスクリプト）。
設定ファイルが 1 つでもあって Node.js が無いときは、デフォルトの値で動かずに止まる。書いた設定を警告なしに無視しないためである。

## 書き込みの決まり

設定ファイルは、`skill-config.mjs` の `set` と `append` で書く。手で書いてもよいが、書いた後に `validate` を実行する。

```bash
node "$CFG" set <名前> <キーのパス> '<JSON の値>' --layer repo        # キーを足す
node "$CFG" append <名前> <キーのパス> '<JSON の値>' --layer repo     # 配列の末尾に要素を足す
```

- キーのパスは `a.b.0.c` の形で書く。キーに `.` を含むときは、JSON の配列（`'["pricing","gpt-5.1"]'`）で書く。
- `set` は、欠けているキーだけを足す。既にあるキーは変えずに止める（同じ値なら何もしない）。
  既にある値を変えるのは、利用者が確かめた後だけにし、`--replace` を付ける。
- `append` に `--unique-by <欄>` を付けると、その欄が同じ要素が既にあれば足さない。
- どちらも、コメントと整形を残したまま書く。書いた後のファイルをスキーマで検証し、通らなければ書かない。
- ファイルが無ければ作る。リポジトリの層のファイルを作ったら、commit してレビューする。

### 人ごと・リポジトリ限定の層

`.local.jsonc` は commit しない。`.gitignore` に次の 1 行が無ければ、書き込みは止まる。

```gitignore
/.config/skills/shoji9x9/*.local.jsonc
```

gitignore されるファイルは、`git worktree` で作った作業ツリーには入らない。worktree で作業するなら、`.env.local` などと同じように worktree へコピーする。

## 移行

次の旧い置き場所の設定と、使わなくなった環境変数が残っていると、読み取りは移行の手順を示して止まる。
旧い設定を警告なしに無視すると、デフォルトの値で動いてしまうためである。旧い場所は読まない。

| 旧い置き場所 | 移す先 |
| --- | --- |
| `.config/skills/shoji9x9/skills.yml` | `skills.<スキル名>` の節を `<スキル名>.jsonc` に、`skills.common` の節を `common.jsonc` に。キーの名前と値は変わらない。YAML のアンカーは展開して書く |
| `.kaizen/config`（`KEY=VALUE`） | `kaizen.jsonc` の同じ名前のキー。`on` と `off` は `true` と `false` に、数は数のまま書く |
| `.agent-usage/config.json` | `agent-usage.jsonc` |
| `${XDG_CONFIG_HOME:-~/.config}/agent-usage/config.json` | `${XDG_CONFIG_HOME:-~/.config}/skills/shoji9x9/agent-usage.jsonc` |
| 環境変数（`SKILLS_REVIEW_TOOL` など） | エラーの内容に書いた層のファイルの、同じ意味のキー |

移したら、旧いファイルを消し、環境変数を `.env` などから消す。
