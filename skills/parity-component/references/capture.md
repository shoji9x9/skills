# 現行からの採取（要素単位の 4 点）

インスタンス × 状態ごとに 4 点を採る。**撮影条件・ノイズ基準値・保存先の規約は `parity-suite` の `references/baseline.md` が正本**で、ここへ転記しない。
本ファイルが定めるのは、採取の単位がページではなく**要素**になることで変わる部分だけである。
**`parity-suite` の `references/baseline.md` を読めない場合は、条件を推測して採取へ進まず停止する**（撮影条件が違うと採取物は比較に使えない）。

| 採るもの | 手段 | なぜ要るか |
|---|---|---|
| 要素のスクリーンショット | Playwright の `locator.screenshot()` | 名前の付かない内部要素の見た目差を画素経路が拾う |
| 計算後スタイル | `parity-suite` 同梱の trait-capture.mjs | 決定論的に比較できる値。状態ごとに採る |
| **当たっている CSS 規則** | 同梱の `scripts/css-rules-capture.mjs` | 計算値が見せない側（`:hover` の宣言・`!important` の競合・どの規則が効いているか） |
| **データ依存部品の実データ** | 現行の可視行から抽出 | 見本に同じ入力を与えないと、データ由来の差と実装の差を分けられない |

## ページ全体ではなく要素を撮る

- 撮る前に**対象要素が一意に引けること**を確かめる（複数一致のまま撮ると、どのインスタンスを撮ったか後から決められない）
- **要素スクショは要素の矩形で切られるので、外側の余白（`margin`）は写らない。** 余白は計算後スタイルと相対幾何が持つ
- `position` や親の `overflow` で要素が切れる場合は、切れた状態のまま撮って**切れていることを `gaps.md` に記録する**（親ごと撮って範囲を広げると、比較対象が部品でなくなる）

## 状態への遷移は呼び出し側が行う

trait-capture.mjs も css-rules-capture.mjs も「いまの状態」を採るだけで、状態遷移は行わない。
`hover` / `active` / `focus` / `disabled` / `checked` などへ遷移させてから採る。

- **遷移したことを、採る前にその状態固有の assertion で確かめる**（属性・クラス・可視要素の変化）。遷移できていないまま採ると、`default` の値が `hover` として記録される
- 遷移できない状態の扱いは [`instances.md`](instances.md)「状態集合はインスタンス間で揃える」に従う

## 当たっている CSS 規則

`scripts/css-rules-capture.mjs` を**コピーせずスキル配下からそのまま実行する**。出力は `baseline/<instance>/<state>/css-rules.json` に置く。

- **計算値の代わりではなく、計算値の裏側を採る。** どの宣言が勝つかは計算後スタイルが持っており、本ツールは**候補と条件**（状態・擬似要素・`@media` / `@supports` / `@layer`・`!important`）を出す。
  どちらか片方だけでは、実装時に「なぜこの値になっているのか」を再現できない
- **`inaccessible` が非ゼロなら、そのスタイルシートの規則は 1 件も見えていない。** クロスオリジン配信の CSS（CDN 配信の市販部品テーマ等）が典型で、
  **0 件を「そのシートには関係する規則が無い」と読まない**。`gaps.md` の「特性化できなかった箇所と理由」へ種別「採取値の射程外」として残す
- **`unresolved` が非ゼロなら、そのセレクタは当たるかどうかを判定していない。** 同じく `gaps.md` に残す。
  既知の発生源が 1 つある——**状態付きの親に入れ子になった規則**（`.btn:hover { & .icon { … } }`）は、`&` の解決で親の状態が
  `:is(.btn:hover)` の中へ入るため `state-inside-functional-pseudo` として `unresolved` に落ちる。
  当たる／当たらないを黙って決めずに残す設計なので、該当する規則は**現行の CSS を直接読んで実装の材料にする**
- 出力が大きくなりやすいので、**宣言が空の規則は実装の材料にならない**が、削らずそのまま残す（削ると再実行時に差が出た理由を追えない）

## データ依存部品

データグリッドのように**描画がデータに左右される部品**は、見本側のデータをいくらでも作れる一方、**現行側のデータを部品の都合で書き換えることはできない**。
そこで**現行に実際に写っている一部分を採り、それを見本の入力にする**。

1. 現行のインスタンスで、**1 画面に収まる範囲の行**（先頭 N 件など、撮影範囲に全体が写る件数）を決める。N は `metadata.json` の `instances[].data.rows` に記録する
2. その範囲が**画面に写った状態**でスクリーンショットと計算後スタイルを採る（写っていない行を後から足さない）
3. 同じ範囲の**実データを DOM から抽出**し、`baseline/<instance>/data.json` に保存する。列の論理名と値の対応を持たせる（表示文字列だけでなく、書式の前の値が DOM から取れるならそれも）
4. **来歴を確認する。** `.replace/dataset/metadata.json` の `version` を読み、**`golden-dataset` フェーズ A が投入したデータセットの上で採ったこと**を `metadata.json` の `dataset_version` に記録する。
   確認できない場合（データセット投入前の環境で採った、投入対象でない target で採った）は**抽出データを見本に使わない**——来歴・利用許可が不明なデータを新側へ持ち込まない規律に触れる（正本は `replace-strategy` の `references/scope.md`「スキルが行う作業の範囲」）
5. 抽出データに**個人情報・シークレットが含まれていないこと**を確認する。含まれるなら見本に使わず、`golden-dataset` へ戻して比較に使えるデータを用意してもらう

- データセットのバージョンが上がったら、**採取物と抽出データの両方が陳腐化する**。`metadata.json` の `dataset_version` と現在の版を突き合わせ、古ければ再採取を宣言する
- **抽出データを手で整形しない。** 見やすさのために値を丸める・並べ替えると、見本と現行で入力が変わり、差分の原因が実装なのか入力なのか分からなくなる

## ノイズ基準値

`parity-suite` と同じく**同一条件で 2 回採り**、画素差分と特性照合を 2 回分に対して回した差分量を `metadata.json.noise_baseline` に**インスタンス × 状態ごと**に記録する。

- 2 回目の書き出し先は `.replace/components/<slug>/noise-pass2/`。**基準値を記録したら削除する**（どの工程も読まない。正本は `parity-suite` の `references/baseline.md`）
- 部品単体は画面全体より描画要素が少ないぶんノイズも小さくなりやすいが、**小さいことを前提に測定を省かない**——省くと、照合で出た差が回帰なのか揺れなのかを決める根拠が無くなる

## 採取環境と利用者環境の乖離

**採取環境でだけ成立する一致は、差分器では捉えられない。** 総称ファミリー（`system-ui` / `sans-serif`）や OS 既定のフォームコントロール外観は、
現行・新側の両方に同じ解決を与えるため、採取環境では差分ゼロになり別環境でだけ崩れる。

- 扱い（環境非依存にする／利用者環境でも採る／`gaps.md` に残す）の正本は `parity-suite` の `references/baseline.md`「採取環境と利用者環境の乖離」
- **部品ではこの穴が広がる。** チェックボックス・ラジオ・`select` のように**現行が標準コントロールをそのまま使っている**部品は、
  見た目の大半が OS とブラウザの既定で決まる。採取値が現行アプリの CSS 由来なのか環境の既定由来なのかを、
  css-rules-capture.mjs の出力（当たっている規則があるか）で切り分け、**規則が無い値は環境由来として `metadata.json` の `instances[].ua_defaults` に記録する**。
  ここを混同すると、新側が自前描画で作り直しているのに採取環境でだけ一致する
