# ディレクトリの構成

1 つのディレクトリの直下のファイル数を 20 件以下に保つ規約と、超えたときの扱いを決める。

## 数え方

git 管理下のファイル（`git ls-files`）を、ディレクトリごとに直下だけで数える。
サブディレクトリとその中身は親の件数に入れず、シンボリックリンクはファイルとして数える。

## 超えたときの扱い

20 件を超えたら、まず分ける。分けられないディレクトリだけ、20 件を超えてよい。
分けられるかは、次の表で決める。

| 扱い | 当たる場合 | 例 |
| --- | --- | --- |
| 分ける | 下の 2 つに当たらない場合はすべて。import や参照の書き換えが多いことは、分けない理由にならない | `scripts/lib`、`scripts/skills/parity-suite`、`skills/agent-usage/scripts/lib` |
| 20 件を超えてよい（件数に限りがある） | ツールや外部の仕様がファイルの場所を決めていて、動かすと読まれなくなる。またはファイルの集まりが 1 つの単位として入力になり、名前で参照されていて、分けると入力が変わる。件数は増えても限りがある | リポジトリの直下（ツールの設定）、`evals/kaizen/fixtures/candidate-scan`（eval が一式を入力にし、prompt がファイル名で参照する） |
| 20 件を超えてよい（件数に上限が無い） | スキルやツールが仕様として 1 件 1 ファイルで溜めていき、件数に上限が無い。置き場所もその仕様で決まっている | `.kaizen`、`.kaizen/archive`、`.agent-usage/records`、`.claude/skills` |

件数に限りがあるとして超えてよいとしたディレクトリにファイルを足すときは、足すファイルも表の条件（ツールや外部の仕様が場所を決めている、1 つの単位として入力になる）に当たるかを確かめる。
当たらないファイルは、分けた先に置く。

`scripts/` と `scripts/gates/` の直下には、ファイルを置かない。

## 分け方

分けるときは、まずファイルを役割でグループにする。次に、グループと今のディレクトリの名前の関係で、置き方を選ぶ。

| 置き方 | 選ぶ場合 | 例 |
| --- | --- | --- |
| サブディレクトリを作る | 今のディレクトリの名前が、どのグループにも当てはまる（グループが、その名前の役割を細かく分けたものになっている） | `scripts/lib` の中に `testing/`・`text/` を作る。どちらも共有ライブラリなので、`lib` の名前のままでよい |
| 兄弟ディレクトリを作り、必要なら今のディレクトリの名前を変える | グループどうしが並ぶ役割で、今の名前が一部のグループにしか当てはまらない | `lib` の中身がテスト用の helper と手で起動するツールに分かれたら、`tools/` を兄弟に作って移し、`lib` を `testing/` に変える |

サブディレクトリは、親の名前がグループの役割を言い表しているときだけ作る。親の名前と中身が合わないまま 1 段深くすると、名前から中身を推測できなくなる。
兄弟ディレクトリにするときは、新しく作るディレクトリが、親のディレクトリの既存の分類と重ならないかを先に確かめる。重なるなら、既存の分類に移す。
名前を変えると参照の書き換えが増えるが、そのことは名前を変えない理由にならない。

どちらの置き方でも、次のことを守る。

- ディレクトリの名前は、中のファイルに共通する役割を表す名詞にする（`testing/`・`text/`・`checks/`・`sources/` など）。
  名前の順・作った順・件数で機械的に分けない。どこに何があるかを名前から推測できなくなる。
- ファイルと、それに付くテスト（`*.test.ts`）・ミューテーションテストの定義（`*.mutations.json`）・fixture は、同じディレクトリにまとめて移す。
  テストを対象の隣に置く規約（`AGENTS.md`「ディレクトリ構造」）を保つためである。
- 分けた後の各ディレクトリも 20 件以下にする。サブディレクトリを作ったなら、親の直下に残すのは、どのグループにも当たらない共通のファイルだけにする。
- `AGENTS.md`「ディレクトリ構造」の図に載っているディレクトリを足したり名前を変えたりしたら、図も直す。
- 配布スキル（`skills/<name>/`）の中を分けたら、`scripts/tools/reinstall-skill.sh <name>` でインストール済みのコピーも作り直す。
  コピーは `skills/` と同じ構成になるので、コピーの側だけを 20 件を超えてよいものとして扱わない。

移した後は、次の参照を新しいパスに直し、テストと横断のチェックで確かめる。

- 相対パスの import と `new URL("…", import.meta.url)`
- `join(dirname(fileURLToPath(import.meta.url)), "..", …)` のように、ファイルの位置からルートを求める処理。1 段深くなった分の `".."` を足す
- パスを文字列で持つもの（ミューテーションテストの定義の `file`・`test_file`・`find`、`scripts/mutation/mutation-durations.json` のキー、文書の参照、設定ファイル）
