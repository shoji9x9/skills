# スライドのデザインシステム

shoji9x9/skills のスキルを、導入する人に説明するスライドと、それを配信する GitHub Pages のページで使う。
ロゴは持たないので、名前は `display` の書体で文字として書く。

## 内容の書き方

- 日本語版は、リポジトリの文章の規約（行為者を主語にする、名詞を「の」で連ねない、否定と対比で演出しない）に従う。英語版は日本語版を訳し、スライドの数と並びを変えない。
- 1 枚のスライドで伝えることは 1 つにする。見出しは `title`、要点の 1 文は `lead`、残りは `body` の箇条で書く。
- 根拠にした文書（`SKILL.md` の節など）は、スライドには出さず、ストーリーラインに書く。
- スピーカーノート（`<aside>`）は、話す内容を書く場所なので、根拠や作り方の覚え書きを書かない。
- スライドの単位を読み手に示すときは「第 N 章」と書く。
- コマンドとパスは、スライドでも `code` の書体で書く（`gh skill install shoji9x9/skills <名前>`）。
- 絵文字は使わない。

## 色

- 地は `paper`、文字は `ink` にする。コードブロック・表・図の箱は `surface` に置く。
- 色に意味を持たせる。どのスライドでも同じ意味で使う。
  - `flow`: 流れと呼び出し方（図の矢印、スキル名の強調、リンク）
  - `human` と `human-ink`: 人が判断する点（承認・停止の条件）。印の塗りは `human`、文字は `human-ink`
  - `output`: 成果物（Issue・PR・SVG・HTML など）
- `flow` と `human` は青と橙の組なので、色覚の違いがあっても見分けられる。色だけで区別せず、ラベルの文字も添える。
- `line` は装飾の細線だけに使う。意味を持つ枠や矢印には使わない。
- 表紙と章の扉だけ、`ink` の帯を地にし、文字を `paper` にしてよい。

## 文字

- 和文と欧文は `IBM Plex Sans JP`（Google Fonts）、コードは `IBM Plex Mono`（Google Fonts）で書く。GitHub Pages のページでも同じ書体を読み込む。
- スライドの大きさは 1920 × 1080 を基準にし、`display`・`title`・`lead`・`body`・`label`・`caption` の 6 段だけを使う。
- 見出しは折り返しをそろえる（`text-wrap: balance`）。本文の 1 行は 40 字程度までにする。

## 余白と形

- スライドの外周は `space-4`、見出しと本文の間は `space-3`、箱の内側は `space-2` を取る。
- 角丸は 3 段だけを使う。コードと図の節点は `radius-md`、大きな囲みは `radius-lg`。
- 影とグラデーションは使わない。面は色の差と `line` の細線で分ける。

## 図

- 流れの図は左から右へ並べ、矢印は `flow` にする。人が判断する点は `human` の印を節点に付ける。
- 図の節点の名前は `label`、補足は `caption` にする。
- Slides の独自の要素（`x-shape`・`x-icon`・`x-connector` など）は、GitHub Pages のページで表示できることを確かめてから使う。
