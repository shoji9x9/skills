Two flows, chosen by the style policy

The style_policy value in replace-strategy decides which skills check features with screens.

style_policyMatches the current app inSkills that check features with screens
reproduce (default)UI behavior and appearance (color, size, spacing, fonts)parity-suite (Playwright) builds the criteria, and parity-diff compares the screens of both apps
freeUI behavior only (actions, states, roles, text, API). The appearance only needs to look right to peoplespec-parity (e2e) builds the suite and checks only the new app. It does not compare screens

You choose the value when setup decides the strategy, and keep it once work on features starts. If you must change it, the agent first asks you, for each started feature, whether to rebuild its outputs. Cross-cutting APIs and batches use parity-suite and parity-diff with either value.
