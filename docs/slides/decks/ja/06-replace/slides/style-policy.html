スタイルの方針で分かれる 2 つの流れ

画面のある機能を確かめるスキルは、replace-strategy の設定にある style_policy で決まる。

style_policy現行に合わせるもの画面のある機能を確かめるスキル
reproduce（デフォルト）UI の仕様と、見た目（色・寸法・余白・書体）parity-suite（Playwright）が基準を作り、parity-diff が新旧の画面を比べる
freeUI の仕様（操作・状態・role・テキスト・API）だけ。見た目は、人が見て違和感の無いものにするspec-parity（e2e）がスイートを作り、新側だけを確かめる。新旧の画面は比べない

値は、setup で戦略を決めるときに利用者が選び、機能に着手した後は変えない。どうしても変えるなら、着手済みの機能で作った成果物を作り直すかを、機能ごとに利用者に確かめてから変える。横断 API とバッチは、どちらの値でも parity-suite と parity-diff で確かめる。
