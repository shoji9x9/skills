# 単価表と料金ページの差の点検

`agent-usage` は、同梱の単価表（`skills/agent-usage/assets/pricing.json`）に無いモデルの費用を空欄にする。
新しいモデルが出ても単価表に足すまで費用が空のまま記録されるので、月次のワークフローが単価表と公式の料金ページを比べ、差を追跡 Issue に載せる。
この文書は、点検が報告するものと、報告を受けて単価表を直す手順を書く。

## 点検が報告するもの

`.github/workflows/check-pricing-drift.yml` が毎月 1 日に `scripts/monthly/check-pricing-drift.ts` を実行し、結果を追跡 Issue に載せる。
追跡 Issue のタイトルは `Check pricing drift to review (<確認した日>)` である。
手で実行するときは、`gh workflow run check-pricing-drift.yml` を使う。

スクリプトは、次の 2 つの料金ページを Markdown で取得する。どちらも、ページの URL の末尾に `.md` を付けると Markdown を返す。

| 料金ページ | 読む表 |
| --- | --- |
| <https://platform.claude.com/docs/en/about-claude/pricing.md> | 見出し「Model pricing」の下の、列が `Model`・`Base input tokens`・`5m cache writes`・`1h cache writes`・`Cache hits and refreshes`・`Output tokens` の表 |
| <https://developers.openai.com/api/docs/pricing.md> | 見出し「Standard pricing data」の下のすべての表。短いコンテキストの入力・出力・キャッシュ済みの入力の列だけを読む |

料金ページのモデル名は、ログのモデル名の形に直してから単価表と比べる。
Anthropic は `Claude Opus 4.1` を `claude-opus-4-1` にし、OpenAI は `gpt-5.5 (<272K context length)` の括弧の注記を外す。

追跡 Issue の表には、次の 5 種類が載る。

| 種類 | 意味 |
| --- | --- |
| 単価表に無い | 料金ページにあり、単価表に無いモデル |
| 料金ページに無い | 単価表にあり、どの料金ページにも無いモデル。どちらかの料金ページを読めなかったときは挙げない |
| 単価が違う | 両方にあり、単価が違うモデル。違う項目を `項目: 単価表 → 料金ページ` の形で書く |
| 記録の費用が空 | `.agent-usage/records` に費用が空（`cost_source` が `unknown`）の `usage` の行を持ち、今も単価表に無いモデル。ログに出るモデル名が料金ページに無いもの（`codex-auto-review` など）は、料金ページとの比較では見つからないので、ここで見つける |
| 料金ページを読めなかった | 取得に失敗した、または見出し・列・単価の形が変わって表を読めなかった。理由を内容の列に書く |

長いコンテキスト・Batch・Flex の単価と、OpenAI のキャッシュの書き込みの単価は、単価表が持たないので比べない。

「単価表に無い」と「記録の費用が空」は、一度報告したモデルを次の実行から挙げない。
単価表に足さないと決めたモデルが毎月残ると、追跡 Issue をクローズできないからである。
報告したモデルの一覧は、追跡 Issue の本文の目印（`check-pricing-drift-seen`）に残る。
open の追跡 Issue が無いときは、クローズ済みの最後の追跡 Issue の本文から一覧を読む。
タイトルで検索した新しい順の 100 件に追跡 Issue が無いときは、ワークフローが失敗し、追跡 Issue を変えない。それより古い Issue の一覧を読まずに報告すると、報告済みのモデルをもう一度挙げるからである。
見つけた最新の追跡 Issue が open のときも、ワークフローが失敗する。open の追跡 Issue の照会で見つからなかったので、そのまま進むと新しい追跡 Issue を重ねて作るからである。
そのため、報告を受けた月のうちに直すかを決める。次の月に新しいモデルが無ければ、Issue はクローズされる。
「料金ページに無い」「単価が違う」「料金ページを読めなかった」は、直すまで毎回挙げる。

各行の「前回から」の列は、前回の本文と比べて新規か継続かを示す。追加したコメントには、新規と解消の一覧が載る。
報告済みなので挙げなくなったモデルは、解消に入れず、本文の「挙げなかった」の件数に数える。
料金ページを読めなかった実行では、「単価表に無い」「料金ページに無い」「単価が違う」を解消に入れない。読めなかったページと比べていないからである。

差が 0 件になると、ワークフローは追跡 Issue の本文を更新してからクローズする。クローズするのは、両方の料金ページを読めたときだけである。
料金ページを読めなかったときは、その行が 1 件として数えられるので、Issue は open のまま残る。
単価表や記録を読めないとき（このリポジトリの中の誤り）は、ワークフローが失敗し、追跡 Issue を変えない。

## 報告を受けて単価表を直す手順

単価表を直すかは人が決め、Issue を立てて PR で直す。ワークフローは単価表を書き換えない。

1. 追跡 Issue の行と、料金ページの該当する行を読み、直すかを決める。
   単価表に足さないと決めたモデル（使わないモデルなど）は、何もしなくてよい。次の実行から挙がらない。
   報告済みのモデルをもう一度挙げさせたいときは、最後の追跡 Issue の本文の目印の一覧から、そのモデルの識別子を消す。
2. 直す行ごとに、`skills/agent-usage/assets/pricing.json` を次のように直す。
   - 単価表に無い: `models` にモデルを足す。単価は USD / 100 万トークンで書く。Anthropic は `input`・`cacheWrite5m`・`cacheWrite1h`・`cacheRead`・`output` を、OpenAI は `input`・`cacheRead`・`output` を持つ
   - 料金ページに無い: モデル名を変えただけでないかを料金ページで確かめてから、`models` から消す
   - 単価が違う: 今の単価を書き換えずに、料金ページの単価を新しい期間として足す。
     単価のオブジェクトを配列にし、新しい要素に `since`（料金ページで単価が変わった日）を書く。
     書き換えると、変わる前の応答の費用も新しい単価で計算され直す。期間の書き方は `skills/agent-usage/references/records.md`「費用」にある。
     料金ページの単価が変わったのではなく、単価表の書き間違いだったときは、期間を足さずにその単価を書き換える
   - 記録の費用が空: ログのモデル名と料金ページのモデル名の対応を確かめる。対応があればその単価を足し、無ければ（`codex-auto-review` など）費用を空のまま残すかを Issue に書く
3. `retrieved` を、料金ページを確かめた日にする。単価表の先頭の `$comment` が、新しいモデルの扱い（長いコンテキストの単価を持たないことなど）と合うかも確かめる。
4. `skills/agent-usage/` を直したので、`scripts/tools/reinstall-skill.sh agent-usage` でインストール済みのコピーを同期する。
5. 単価表を直した後に `agent-usage report` を実行すると、記録で費用が空だった行にも費用が入る。

料金ページを読めなかった行は、次のように扱う。

1. 内容の列の理由と、ワークフローのログを読む。取得の失敗（HTTP のエラーや時間切れ）なら、`gh workflow run check-pricing-drift.yml` でもう一度実行する。
2. 形が変わって読めないなら、料金ページの Markdown を取得して、見出しと列の名前を確かめる。
   `scripts/monthly/check-pricing-drift.ts` の見出し・列・単価の読み方を直し、テストにその形を足す。
