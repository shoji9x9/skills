## 前回より下がったものと、その原因

- eval 1: 前回は 3 run のどれかが満たし、今回は満たさなかった assertion がある。
  - 受領資産を「受領済み／導出可能／不足」の 3 区分で個別に分類し、DDL・公式 seed・データ辞書を受領済みとして記録している
  - orders.status の値と正常系遷移をデータ辞書の記載を根拠に「確定済み」として扱い、推測扱いにも確認待ちにもしていない
- eval 2: 前回は満たし、今回は満たさなかった assertion がある。
  - DDL そのものが受領されていないことを停止理由にせず、マイグレーションから決定論的に完全復元できるかを検証する方針を示し、空の DB へ実際に全マイグレーションを適用して最終スキーマを得る手順を示している（机上判定で済ませていない）
  - 初期ユーザーのパスワードのように受領資産が値を持たない項目（データ辞書は「構築担当が設定する」とだけ記す）を推測で埋めず確認待ちまたは不足として扱い、接続文字列からは環境変数名だけを控えている
- 原因: どれもタイムゾーンとは別の項目である。
  eval 1 は公式 seed を「出所不明」として不足にし、`semantics.md` を作らなかった。
  eval 2 は空の DB への適用の手順を示さず、接続文字列の環境変数名を成果物に残さなかった。
  今回の run は 1 run なので、変更による回帰か run のばらつきかを区別できない。
  eval 1・2 を 3 run で実行して確かめることを、残りの作業に挙げる。
