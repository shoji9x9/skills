## アナリストパス（所見）

- **5/5。** 「3 つ並べるだけでは足りない」と結論し、pre-commit に載っているものをそのまま `full` へ
  移すのが禁止された埋め方であること、判別にはスクリプト側の引数の扱いまで読む必要があること、
  規約の仕分け基準が「ルール設定があるか」ではなく「破った入力が `full` で落ちるか」であることを、
  いずれもプロンプトの問いに答える形で述べた。
- **契約に無い有用な指摘が出たので、走行後に skill へ取り込んだ**: `full` に置くフォーマッタを
  非破壊のチェック形（`--check` 相当）にしないと、対象を黙って書き換えたうえで必ず通り
  **ゲートとして機能しない**。`diff` 列はさらに害が二重で、手順 7 のレビュー対象である
  未コミット差分そのものを動かす。「走る範囲」節・`setup` 対話・`parity-replace` の
  `adversarial-review.md`・`review-template.md` に反映した。
- **その規定に対応する assertion（6 本目）は本 run の走行後に追加したため、この採点には含まれない。**
  上の 5/5 は 5 本時点のもの。`--check` の有無で判断せず**通した後に作業ツリーの差分が増えないことを
  実測する**という述語は skill 固有だが、本 run はこの規定が skill に無い状態で一般論として
  指摘したのみで実測判別には言及していない。**iteration-16 で再走し 6/6 を確認した**（同 benchmark 参照）。
- 対象リポジトリを持たない使い捨てプロジェクトのため、`lefthook.yml` と各スクリプトを実際に読んでの
  判別は行われていない（一般論としての回答）。判別**手順**を述べられるかは測れたが、
  判別そのものの精度はこの eval では測れない。
